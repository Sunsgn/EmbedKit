# MCU 与 RTOS 开发

## 1. 板级 Bring-up 顺序

按依赖从底向上验证：

1. 电源、复位、启动脚和基础时钟；
2. 调试接口、异常向量和最小日志；
3. GPIO 与管脚复用；
4. 系统 Tick、定时器和看门狗；
5. UART/I²C/SPI/CAN/ADC/PWM/DMA；
6. RTOS 调度、堆、栈和同步原语；
7. 设备服务、协议和产品业务；
8. 低功耗、升级、故障注入和长稳。

每层保存寄存器、波形、日志或仪器证据。下层未证明时，不用上层重试掩盖故障。

## 2. 驱动检查清单

- 原理图网络名、芯片引脚、复用功能和板型是否一致；
- 电平、方向、上下拉、开漏、驱动能力和有效极性；
- 外设时钟、电源域、复位和初始化顺序；
- 中断号、优先级、标志清除和临界区；
- DMA 通道、缓冲生命周期、对齐和 Cache 一致性；
- 超时、总线忙、NACK、仲裁丢失、溢出和恢复；
- 多实例和板型差异是否通过配置/适配器表达；
- 驱动是否保持通用，不嵌入产品策略。

寄存器访问异常要向上追查时钟门控、基地址、供电、条件编译和初始化前置条件。

## 3. ISR、任务与回调边界

ISR 应只完成必要的硬件确认、时间戳、数据采集和通知：

- 禁止阻塞、长延时、动态内存、大日志和复杂协议；
- 使用 RTOS 的 FromISR API，并满足中断优先级约束；
- ISR 与任务共享数据要定义原子性、可见性和缓冲所有权；
- DMA 完成不等于业务完成，应继续校验长度、帧和状态。

任务应有单一主要职责，明确启动、就绪、运行、停止和故障状态。依赖就绪用事件表达，不用固定延时冒充；确需延时时记录硬件/协议依据和超时兜底。

## 4. 并发与事务

每个跨任务操作建议包含：

```text
事务 ID、来源、目标、参数、创建时间、截止时间、
当前状态、重试计数、最终结果和原始证据引用
```

区分“成功入队、已发送、收到链路 ACK、业务执行成功”。锁范围要小且锁顺序固定；禁止无限等待。队列满必须选择拒绝、覆盖、合并、降级或背压，并可观测。

## 5. RTOS 资源和健康

持续记录：

- 每个任务优先级、周期、最坏执行时间和栈高水位；
- 堆总量、最低余量、最大连续块和分配失败；
- 队列深度、峰值、丢弃和超时；
- CPU 空闲率、中断负载和看门狗复位原因；
- 软件定时器回调耗时；
- 动态对象的创建/销毁和泄漏。

喂狗点必须代表关键任务健康，不能用一个仍运行的低优先级任务掩盖其他任务死锁。

## 6. 采样与安全控制

采样链应保留：原始码、校准版本、换算公式、单位、有效范围和故障状态。档位、阈值和去抖使用表驱动测试覆盖边界、迟滞、抖动、开路、短路和左右/通道映射。

安全功能遵循：

- 本地保护优先于联网、升级和日志；
- 阈值、延时和映射来源必须是硬件版本、标准或批准的试验记录；
- 安全状态机需要传感器故障、执行器故障和通信失效路径；
- 修改后需要 HIL/实机故障注入，构建或主机测试不能放行；
- 安全参数和普通产品配置分离，变更有审计和批准。

## 7. 低功耗

低功耗是跨模块状态机，而不是单一开关。定义：

- 运行、空闲、浅睡、深睡和关机模式；
- 进入条件、禁止条件和引用计数锁；
- 唤醒源、恢复顺序、时钟稳定和唤醒延迟；
- 通信、Flash、升级、安全动作和调试的锁行为；
- 锁泄漏、异常复位和时间基准补偿。

实测平均/峰值电流、唤醒可靠性、计时误差、联网保持和关键外设恢复。状态变量只能证明软件意图，不能证明真实功耗。

## 8. MCU 测试重点

- 外设：超时、忙、断线、错误标志、DMA 边界和恢复；
- RTOS：队列满、栈不足、堆不足、优先级反转和死锁；
- 协议：半包、粘包、CRC、重复、乱序和重放；
- 存储：写入中断电、损坏、磨损和旧版本迁移；
- 安全：传感器/执行器故障、看门狗和失效安全输出；
- 系统：反复上电、弱网、低电压、温度和 24/72 小时长稳。
