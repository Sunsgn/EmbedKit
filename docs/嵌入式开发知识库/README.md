# 嵌入式产品开发知识库

- 版本：V1.0
- 整理日期：2026-11-12
- 适用范围：裸机、事件驱动、RTOS MCU、嵌入式 Linux、无线与 IoT 产品
- 目标读者：嵌入式开发、测试、系统、硬件和使用 AI 协作的工程人员

## 1. 定位

本知识库把多个真实项目中的工程经验整理为平台无关的方法。它不提供某一芯片、操作系统或产品的固定答案，而是帮助开发者回答：

1. 当前事实和未知项是什么；
2. 问题属于硬件、驱动、系统、服务还是业务哪一层；
3. 谁拥有外设、状态、缓冲和进程生命周期；
4. 正常、边界和失败路径如何闭环；
5. 结论由什么证据证明，达到哪一级；
6. 如何回退、复现、发布和维护。

知识库中的数字、端口、节点、超时和分区仅在明确标为案例时有效，不得直接复制到其他项目。

## 3. 推荐使用路径

### 新项目

先建立项目事实表和唯一构建入口，再完成资源、分层和验证设计。不要在工具链、硬件版本和协议版本未知时直接生成产品代码。

### 接手陌生项目

按“规则 → 项目入口 → 构建配置 → 需求/协议/原理图 → 实现和调用链 → 历史证据 → Git 状态”的顺序阅读。输出事实、证据、未知项和风险，不把文件名或常见模式当成确定事实。

### 故障诊断

先冻结版本、配置、时间线和原始证据，再定位故障层级。每次实验只改变一个主要变量，记录预期、实际和反证；已经被充分排除的路径进入“禁止重复实验”清单。

### AI 协作

把 [AI 嵌入式产品开发规范](../AI嵌入式开发规范/README.md) 设为目标工程的 AI 规则入口，按任务类型强制加载对应分册，并用项目变量模板补充具体硬件、工具链、构建和安全边界。通用约束不能替代项目数据手册、原理图、协议和真实验证。

## 4. 核心判断框架

任何功能完成前都应回答：

- 输入来自哪里，格式、频率、上限和可信边界是什么；
- 数据经过哪些任务、线程、进程、队列、总线和存储；
- 输出如何被用户、设备或上层系统验证和带走；
- 超时、断线、损坏、资源不足、取消和重启时如何恢复；
- Flash、RAM、栈、CPU、带宽、存储、功耗和温度上限是什么；
- 达到的证据等级是什么，哪些仍待实机或现场验证；
- 如何关联源码、固件、设备、配置、测试和报告；
- 如何安全回退到已验证基线。
