# 通信、存储、升级与安全

## 1. 通信接收路径

推荐分层：

```text
ISR/DMA/socket 收取
  → 有界缓冲
  → 帧边界/长度/静默时间
  → magic、版本、长度、CRC/认证校验
  → 字段解析和语义校验
  → 业务事务队列
  → 异步结果与状态上报
```

覆盖 0 字节、半包、粘包、超长、非法编码、CRC 错、重复、乱序、重放、超时、断线和重连。多字节字段显式处理字节序、符号、缩放和单位，不直接把外部字节强转为结构体。

## 2. 链路所有权和状态机

UART、SPI、CAN、TCP、无线模组或云连接只能有一个明确所有者。业务层提交有界事务，不直接插入同步命令。状态机必须表达：

- 未初始化、准备、连接、就绪、忙、退避和故障；
- 命令发送、响应匹配、链路 ACK 和业务结果；
- 超时、有限重试、退避、取消和最终失败；
- 断线期间数据保留/丢弃/合并策略；
- 重连后的状态同步和幂等性。

## 3. 存储和配置

持久化格式至少包含 magic、schema 版本、长度、校验和提交状态。设计时覆盖：

- 写入掉电和部分写；
- 双副本、日志式或平台原子替换；
- 容量、条数、轮转和写寿命；
- 损坏检测、默认值和人工恢复；
- 旧版本迁移、新版本回退和未知字段；
- 唯一标识、校准、密钥和生产 NV 的独立保护。

关键写入应先写数据与校验，最后提交有效状态。缓存的 ACK 清理要关联具体记录/事务，不能因新旧消息交叉误删。

## 4. OTA/FOTA

通用状态机：

```text
IDLE → PREPARE → RECEIVE → VERIFY → PENDING
          ↘          ↘         ↘
              FAILED / CLEANUP
PENDING → REBOOT → FIRST_BOOT_CHECK → COMMIT / ROLLBACK
```

校验产品、硬件、基线版本、目标版本、包类型、长度、分区、哈希和签名。数据块校验会话、序号、偏移、长度，使用安全的溢出检查。覆盖重复、漏块、乱序、空间不足、低内存、断网、断电、首次启动失败和配置迁移。

平台无自动回滚时，必须提供明确的有线恢复或双镜像替代方案。流式/分块算法可以降低 RAM 峰值，但不能降低完整性校验语义。

## 5. 日志与诊断

日志应回答状态和失败原因，包含模块、时间、状态、事务号、错误码、关键长度、耗时和重试。避免高频重复；原始帧限长并脱敏；生产日志控制级别、存储、时序影响和远程导出权限。

敏感字段不得进入日志、崩溃转储、测试快照或 AI 对话。必要时输出不可逆标识或末尾少量字符用于关联。

## 6. 安全边界

- 密钥、密码、Token、证书私钥和生产唯一值不写入源码；
- 使用模板与受控部署注入实际凭据；
- 外部长度、路径、URL、命令参数、文件和协议字段先校验；
- 进程执行参数化，避免 shell 拼接；
- 调试口、测试命令、校准和连续发射入口与量产隔离；
- 远程控制不能绕过本地联锁和安全状态；
- 更新包、发布包和配置有签名/哈希、版本策略和审计；
- 最小权限运行，设备节点、FIFO、socket 和配置文件设置恰当权限。

AI 不应接触或回显明文生产秘密，也不能自行批准量产、认证或 OTA 发布。
