# 案例经验与复用边界

## 1. 通用指南案例

### 可迁移经验

- 统一构建入口和工具链恢复优先于快速堆功能；
- 多链路控制使用单一所有者、有界事务和异步结果；
- 半包、外设时钟和低内存问题需要保留原始证据；
- 分块处理可以降低峰值内存，但不得削弱校验；
- 构建、模拟、实机、现场和生产证据严格分级。

### 不可照搬

具体 Modbus/AT 命令、端口、缓冲、超时、分区和任务边界属于原项目配置。

## 2. FreeRTOS A22 燃气灶案例

### 可迁移经验

- 通信任务拥有模组链路，业务任务通过队列交接；
- 烟机联动从“连接即发送”演进为序列号、ACK、有限重试和重连恢复事务；
- RTOS 启动阶段、任务创建、分配失败、栈溢出和高水位应可观测；
- 安全阈值、通道映射和延时必须关联硬件版本与试验记录；
- 在拆分大状态机文件前先建立协议回放与表驱动测试；
- 已运行研发工程应先冻结、补入口、治理生成物，再模块化。

### 不可照搬

CW32L083、FreeRTOS 版本、任务优先级/栈、14 KiB 堆、MS5193、F20/MC661、AT24C04、B003、炉头映射和安全参数只对该案例有效。家电安全结论不能推广到其他产品。

## 3. RV1106 Linux 案例

### 可迁移经验

- 明确远端 SDK、本地应用 overlay 和板端运行文件的三方权威关系；
- Kernel/DTS/驱动、媒体核心、控制应用和 shell 编排分层维护；
- 应用使用稳定设备链接/状态接口，不固定易变 `/dev/videoN`；
- FIFO 帧协议处理长度上限、短读、EOF、超时、取消与重连；
- 预编译媒体程序缺少对应源码时，应停止把它当作可维护量产组件；
- 主机依赖不能整体复制到 ARM，必须检查 ELF 架构、ABI 和白名单；
- “模块加载、STREAMON、DMA 数据、有效图像、性能和长稳”分级验收；
- 位映射与物理连接不匹配时，上层格式转换不能恢复缺失位；
- 保存失败实验和禁重复清单能避免反复试错。

### 不可照搬

RV1106、Luckfox SDK 路径、SC3336、OV3660、D8:D15/M1 D2:D9、具体 video 节点、FIFO 路径、GPIO 和 10 MiB 帧上限属于该案例。其他 SoC 必须重新核对手册、原理图和驱动。

## 4. 跨案例共同规律

| 规律 | MCU/RTOS 表现 | Linux 表现 |
| --- | --- | --- |
| 单一所有者 | UART/总线任务 | 设备采集进程/服务 |
| 稳定接口 | 队列、事件、事务 | socket/FIFO/状态文件/稳定链接 |
| 资源有界 | 栈、堆、队列、重试 | RSS、FD、磁盘、帧、重连 |
| 分层定位 | 时钟→驱动→任务→业务 | 硬件→DTS/驱动→系统→应用 |
| 保护基线 | 可运行固件与安全链路 | Kernel/Boot/设备主链路 |
| 证据分级 | 构建≠实机 | 节点/数据≠有效业务 |
| 可追溯发布 | hex/map/配置/测试 | image/DTB/KO/app/model/manifest |

## 5. 经验转规则的方法

从案例提炼规则时依次询问：

1. 这是平台规律、子系统规律还是单项目配置？
2. 依据是代码推断、主机测试、实机还是现场证据？
3. 对其他芯片/OS 成立需要什么前提？
4. 有哪些反例和未知项？
5. 应写成强制约束、推荐实践还是案例提示？

只有跨平台成立且涉及安全、数据完整性或可恢复性的内容，才适合写成无条件强制规则。
