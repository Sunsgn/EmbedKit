# EmbedKit Web 工具平台合理化开发方案

## 1. 文档目的

本文档是 EmbedKit 后续开发的执行基线。目标是在不回退现有通信调试、集成测试、工程分析、资料和学习能力的前提下，将 EmbedKit 演进为打开网页即可使用、需要本机权限时由本地助手增强的通用嵌入式开发工具平台。

本方案坚持小步增量、自动验证和独立 Git 检查点，不以一次性重构替代持续交付。

## 2. 产品定位与边界

EmbedKit 面向嵌入式开发、调试、测试、分析和学习场景，重点提供：

1. 纯网页运行的计算、协议、固件和诊断工具。
2. 工程源码、MAP、ELF、日志和运行轨迹分析。
3. 串口、TCP、UDP、WebSocket 和后续 CAN 设备联调。
4. 可复现的集成测试、证据和报告。
5. 可追溯的资料导航与实践学习路径。

EmbedKit 不替代 Keil、IAR、CMake、编译器、链接器、烧录器、J-Link、OpenOCD 或厂商 IDE；优先消费这些工具已有的工程配置、构建产物和日志。

## 3. 用户体验目标

### 3.1 纯网页工具

用户应通过“选择工具 → 输入、粘贴或选择文件 → 查看结果”完成操作，无需创建项目、登录账号、启动本地服务或使用命令行。

### 3.2 本机能力

串口、CAN、ELF/DWARF 深度解析、大型工程目录和大型日志等浏览器受限能力由 EmbedKit 本地助手提供。首次使用允许一次安装和系统授权；后续用户只需选择文件、目录或设备。

用户界面统一使用“本地助手”名称，协议版本、端口和内部接口默认收纳在诊断详情中。

### 3.3 渐进式界面

默认只显示高频参数，高级配置放入“更多设置”。工具结果先显示结论和可执行建议，再显示证据、详细字段和原始数据。错误必须说明原因、恢复方法并提供直接操作。

## 4. 顶层信息架构

保留当前工作台、设备项目、工程分析、通信调试、集成测试、嵌入式工具箱、AI 助手、资料中心和学习中心导航。具体工具不增加顶级入口，统一位于工具箱中并使用独立地址：

```text
/#/toolbox
/#/toolbox/:toolId
```

工具箱首页负责搜索、分类、收藏和最近使用；工具工作区一次只展示当前工具。项目关联是可选增强，不是任何工具的使用前置条件。

## 5. 系统边界

```text
GitHub Pages Web
├─ 页面、路由和工具目录
├─ 纯浏览器领域算法
├─ IndexedDB/localStorage
├─ 文件选择、导出和报告
└─ 本地助手能力检测
              │
              ▼
EmbedKit Local Agent
├─ 串口、TCP/UDP 与 CAN
├─ 本地目录和大型文件
├─ ELF/DWARF 与地址解析
└─ 受控调用已有本机工具
```

`frontend` 是正式网页应用，`proxy` 是 Local Agent。当前不发展第二套重复后端；Agent 新能力明显增多后再按串口、网络、CAN、文件、ELF 和安全边界增量拆分。

## 6. 程序框架

### 6.1 当前阶段最小结构

```text
frontend/src/
├─ App.tsx
├─ pages/
│  ├─ ToolboxPage.tsx
│  └─ ToolWorkspacePage.tsx
├─ features/toolbox/
│  ├─ ToolCatalog.tsx
│  └─ ToolErrorBoundary.tsx
├─ tools/
│  ├─ registry.ts
│  ├─ types.ts
│  └─ <tool-id>/
├─ utils/
└─ services/
   ├─ toolPreferences.ts
   └─ agentClient.ts
```

不一次性建立大量空层级。新增工具采用独立目录，现有工具只在被修改时逐个迁移；已经测试通过的领域算法优先复用。

### 6.2 稳定工具内核

工具平台公共内核只负责：

1. 工具注册和唯一 ID 校验。
2. `/toolbox/:toolId` 路由和懒加载。
3. 收藏、最近使用和本地偏好。
4. 单工具错误隔离。
5. 本地助手能力检测。
6. 后续长任务的取消、超时与 Worker 调度。

具体协议、固件和计算逻辑不得进入注册表、路由或公共工作区。

### 6.3 工具模块规范

简单工具至少包含界面、纯算法和自动测试；复杂工具再增加类型、示例和帮助文件：

```text
tools/modbus/
├─ ModbusTool.tsx
├─ modbus.ts
├─ modbus.test.ts
├─ examples.ts
└─ help.zh-CN.md
```

工具页面不能成为算法本体，模块之间不能直接调用其他页面组件。跨模块联动通过明确的数据输入输出完成。

## 7. 工具注册契约

每个工具声明稳定 ID、版本、名称、分类、关键词、能力需求、文件类型和懒加载入口。注册表采用编译时静态注册，不在当前阶段执行第三方远程脚本或建设动态插件市场。

系统启动和自动测试必须检查：

- 工具 ID 唯一。
- 接口版本兼容。
- 分类与能力声明有效。
- 工具入口可以加载。
- 需要本地助手的能力有安全降级说明。

## 8. 稳定性与可靠性

### 8.1 错误隔离

应用和单个工具分别设置错误边界。工具异常只能关闭或重新加载当前工具，不能破坏导航、其他页面或其他工具。

### 8.2 长任务

小型计算在浏览器主线程执行；大型 MAP、ELF、SVD、固件和日志解析使用 Web Worker 或 Local Agent。长任务必须支持进度、取消、超时、大小限制和页面卸载清理。

### 8.3 数据可靠性

收藏、最近使用、参数偏好、项目、测试和学习进度采用版本化数据。升级必须迁移或兼容读取，损坏条目应隔离并允许导出诊断，禁止直接清空全部用户数据。

源码、固件、ELF、大日志和密钥默认不自动持久化；保存前必须由用户明确选择。

### 8.4 Agent 兼容

网页通过集中 Agent Client 获取状态、协议版本和能力列表。缺少 CAN、ELF 等单项能力时只禁用对应功能，不能影响串口、网页工具或其他模块。

## 9. 串口稳定维护边界

当前串口页面进入稳定维护状态。本轮工具框架开发不调整串口总体布局、分屏、快捷指令、定时发送、在线波特率切换、更多串口设置、DTR/RTS、时间戳和 CR/LF 展示。

仅允许明确缺陷修复、兼容性处理和回归测试。后续协议联动优先通过用户明确选择的数据导出或“用协议工具打开”完成，不直接重构串口内部状态。

## 10. 安全要求

Local Agent 只监听回环地址，验证网页来源和协议版本；文件与目录必须由用户选择，进程调用必须参数化并限制可执行程序和工作范围。网页和 Agent 不得默认上传源码、固件、日志或密钥，也不得提供任意命令执行接口。

## 11. 分阶段实施

### 阶段 1：最小工具平台

- 建立工具类型和注册表。
- 增加 `/toolbox/:toolId` 独立路由。
- 建立统一工具工作区和未知工具降级。
- 增加单工具错误边界。
- 复用现有 10 个工具，不改写算法。
- 保留原工具箱单页选择方式的兼容跳转。

验收：具体工具地址可直接进入和刷新；一次只展示一个工具；未知 ID 可恢复；现有工具和串口回归通过。

### 阶段 2：易用性基础

- 工具搜索、分类、收藏和最近使用。
- 工具示例、帮助和浏览器/Agent 能力标识。
- 统一空状态、错误提示和恢复入口。
- 建立工具注册表自动校验。

### 阶段 3：现有工具模块化

按 CRC、进制、CAN、PWM、ADC、HEX、BIN、MAP 顺序迁移。每次只迁移一个工具，保持输入、输出和测试结果一致。

### 阶段 4：高价值网页工具

依次增加 Modbus RTU/TCP、自定义协议帧、Cortex-M HardFault、SREC、固件合并与比较、SVD 和 CAN DBC。

### 阶段 5：本地助手增强

增加普通用户安装包、自动检测、系统文件/目录选择、ELF/DWARF、地址到源码、CAN 适配器和大型日志能力。串口接口保持兼容。

### 阶段 6：跨模块闭环

实现通信数据进入协议工具、Fault 地址进入 ELF 定位、工具结果进入测试报告、固件分析关联设备和分析结论跳转资料。

### 阶段 7：长期使用保障

完成 Web Worker、数据备份恢复、迁移测试、PWA 离线、依赖安全治理、安装包发布和真实设备验收。

## 12. 开发与 Git 流程

每个增量遵循：

1. 检查 `AGENTS.md`、本文档、工作区和最近检查点。
2. 只选择当前阶段一个可回退增量。
3. 先建立失败或验收用例，再实现最小通用能力。
4. 运行受影响测试；里程碑运行前端测试、lint、构建、Pages 校验和 Agent 测试。
5. 检查差异，不提交运行日志、缓存、临时下载和无关构建产物。
6. 创建目标单一的 Git 检查点，并在执行记录中登记结果和剩余风险。

## 13. 完成判定

完整平台必须满足：

- 普通工具打开网页即可使用。
- 真实设备能力首次安装后只需选择路径、文件或设备。
- 项目关联保持可选。
- 新增工具不需要修改主导航和多个大型页面。
- 单个工具异常、Agent 离线和损坏输入不影响其他模块。
- 大任务不会阻塞网页且能够取消。
- 数据和 Agent 协议可迁移、可降级。
- 所有结论可回到文件、地址、日志、测试步骤或计算依据。
- 串口和其他已完成功能不因平台演进而回退。
- GitHub Pages、纯浏览器模式和 Local Agent 模式均通过对应验收。
