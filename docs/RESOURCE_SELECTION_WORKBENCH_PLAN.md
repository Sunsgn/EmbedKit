# 资料与选型中心开发方案

状态：已确认方向，待分阶段实施  
适用范围：资料中心、器件目录、在线资料来源、选型记录与导出  
产品定位：从产品功能和系统约束出发，形成可核验、可恢复、可导出的器件组合方案；同时保留独立的型号与资料查询能力。

## 1. 本轮需要解决的问题

当前实现已经具备版本化器件记录、MCU 与通信收发器筛选、在线精确型号发现、证据导出和选型记录，但仍属于过渡形态：

- 把 MCU、通信收发器当作一级“功能”，没有表达一个产品功能需要多个器件角色共同完成；
- MCU 与通信筛选页面各自硬编码参数，新增器件类别必须复制页面和筛选逻辑；
- 用户不能增加项目特有条件，也不能区分必须、优先、参考和暂未确定；
- 保存的是单类器件筛选记录，不是包含全局约束、多个角色和兼容性结论的完整方案；
- 资料查询、知识来源、选型面板和搜索结果依次全部展开，首屏信息密度高且操作主线不清晰。

本轮不以扩充大量型号和静态模板为完成目标。优先建立通用方案模型、动态条件能力、清晰布局和旧数据迁移，为后续器件类别与在线参数标准化提供稳定底座。

## 2. 用户实际工作流

### 2.1 按功能设计方案

用户输入：

- 产品功能描述，例如“24 V 工业现场的四路温度采集节点，通过隔离 CAN FD 上传”；
- 系统级约束，例如供电、工作温度、尺寸、成本、生命周期、认证和环境等级；
- 一个功能模板，或完全空白的自定义方案；
- 每个器件角色的参数条件、优先级和已知候选型号。

确定性处理流程：

```text
描述功能
→ 确认全局约束
→ 拆分器件角色
→ 编辑动态条件
→ 查询或导入候选器件
→ 单角色确定性筛选
→ 检查角色间兼容性
→ 核验官方资料与未知项
→ 保存、导出和后续恢复
```

用户得到：

- 每个角色的候选、排除原因、未知参数和证据位置；
- 角色间电压、接口、速率、温度等兼容性结论；
- 资料覆盖率、冲突来源和必须人工确认的项目；
- 带版本、时间、约束、候选、判断依据和来源的方案报告。

### 2.2 按型号查询资料

用户可不创建方案，直接输入完整或部分型号，查询本地器件、官方数据手册、参考手册、勘误、应用文档、CAD 与采购入口。在线搜索摘要只用于发现候选来源，不自动成为已验证参数。

### 2.3 恢复历史工作

用户可独立打开历史方案或旧版单器件选型记录。旧记录迁移成只有一个器件角色的功能方案，不丢失原条件、候选和结果；迁移前的原始版本号保留在元数据中。

## 3. 页面信息架构

资料中心调整为三个互斥的主模式，同一时间只加载一个重型工作区：

```text
资料与选型中心
├─ 按功能设计方案
├─ 按型号查询器件
└─ 我的资料与选型记录
```

页面标题下只保留模式切换、当前目标和关键状态。不再默认同时展示功能选型、知识来源、型号搜索、器件卡片和在线链接。

### 3.1 桌面端功能方案工作台

```text
┌──────────────────────────────────────────────────────────────┐
│ 资料与选型中心  [功能方案] [型号查询] [记录]   保存/导出     │
├──────────────────────────────────────────────────────────────┤
│ 方案摘要：名称 · 功能描述 · 全局约束 · 覆盖率 · 未知/冲突    │
├──────────────┬───────────────────────────────┬───────────────┤
│ 方案与角色    │ 当前角色工作区                 │ 方案检查      │
│              │                               │               │
│ MCU          │ [条件] [候选] [资料核验]       │ 兼容性        │
│ ADC          │ 动态条件编辑器                 │ 未知项        │
│ CAN FD       │ 候选列表与排除原因             │ 来源冲突      │
│ 电源         │                               │ 证据覆盖率    │
│ + 添加角色   │                               │               │
├──────────────┴───────────────────────────────┴───────────────┤
│ 当前对象、保存状态、来源更新时间和失败恢复提示               │
└──────────────────────────────────────────────────────────────┘
```

布局规则：

- 左栏宽度约 220–260 px，可折叠，负责方案步骤和器件角色，不放参数表单；
- 中栏是唯一主操作区，内部通过“条件、候选、资料核验”页签互斥展示；
- 右栏宽度约 280–340 px，显示摘要与问题，可折叠，不重复显示候选详情；
- 候选详情使用抽屉或中栏替换视图，关闭后恢复原滚动位置和筛选状态；
- 保存、导出、重新计算等主操作固定在工作台标题区，始终显示当前方案和当前角色；
- 长候选列表分页或虚拟化，筛选条件按组折叠，高级条件默认收起。

### 3.2 窄屏与低分辨率

- 小于 `1280 px` 时右侧检查栏折叠为带问题数量的抽屉；
- 小于 `900 px` 时左栏改为顶部角色选择器，主区保持单列；
- 小于 `640 px` 时使用“方案 → 角色 → 条件 → 候选 → 检查”的分步导航；
- 不允许三栏被压缩成不可操作的窄列，也不允许表单控件无控制换行；
- 页面刷新后恢复主模式、当前方案、当前角色和工作区页签，但不恢复已失效的网络请求。

### 3.3 型号查询与记录页

- “按型号查询”保留现有搜索、类别、厂商、本地型号详情和在线来源能力；搜索栏固定在内容顶部，只有发生查询后才展示结果和对应来源；
- “知识来源”改为型号查询中的可折叠来源说明或独立抽屉，不占用默认首屏；
- “我的记录”按功能方案、单型号收藏、旧版选型记录分组，提供搜索、恢复、复制、导出和删除；
- 删除前说明作用范围，重要记录优先导出；损坏记录隔离显示，不能导致全部历史记录无法读取。

## 4. 通用领域模型

新增版本化模型，并复用现有 `PartRecord`、来源、文档和证据结构：

```ts
interface FunctionSolution {
  schemaVersion: number;
  id: string;
  name: string;
  description: string;
  templateId?: string;
  globalConstraints: GlobalConstraint[];
  roles: PartRole[];
  compatibilityResults: CompatibilityResult[];
  evidenceSummary: SolutionEvidence;
  createdAt: string;
  updatedAt: string;
}

interface PartRole {
  id: string;
  categoryId: string;
  name: string;
  purpose: string;
  constraints: SelectionConstraint[];
  candidatePartIds: string[];
  selectedPartId?: string;
}

interface ParameterDefinition {
  schemaVersion: number;
  id: string;
  categoryId: string;
  label: string;
  valueType: "number" | "range" | "enum" | "boolean" | "text";
  canonicalUnit?: string;
  allowedUnits?: string[];
  supportedOperators: ConstraintOperator[];
  description: string;
}

interface SelectionConstraint {
  id: string;
  parameterId?: string;
  customName?: string;
  valueType: "number" | "range" | "enum" | "boolean" | "text";
  operator: ConstraintOperator;
  value?: unknown;
  unit?: string;
  priority: "required" | "preferred" | "reference" | "undetermined";
  source: "template" | "user" | "import";
}
```

相关模型还包括 `GlobalConstraint`、`FunctionTemplate`、`CompatibilityRule`、`CompatibilityResult` 和 `SolutionEvidence`。所有稳定关联使用 ID，不依赖可变显示名称。

## 5. 动态参数与筛选规则

### 5.1 参数注册表

- 参数定义、单位定义和器件类别采用注册表，不写入页面组件；
- MCU、通信收发器先迁移为角色适配器，后续传感器、ADC、隔离、电源、存储、电机驱动等沿相同接口扩展；
- 用户可以添加未注册的自定义参数，并选择值类型、运算关系、单位和优先级；
- 自定义参数若无法映射候选数据，结果为“资料不足/需要人工核验”，禁止默认满足。

### 5.2 运算关系

首版至少支持：

- 等于、不等于；
- 大于等于、小于等于、大于、小于；
- 候选范围包含目标范围、候选范围位于目标范围；
- 包含任意值、包含全部值；
- 支持、不支持；
- 人工核验。

单位换算只允许注册表声明的同量纲单位。未知单位、量纲不符、非有限数值、上下限倒置必须显示结构化错误，不进入排序。

### 5.3 四级优先级

- `required`：不满足则排除，缺少可靠数据则标记待核验；
- `preferred`：参与评分和排序，但不排除候选；
- `reference`：只展示对比，不影响资格与排序；
- `undetermined`：保留问题，提醒用户补充，不执行判断。

评分不能掩盖硬条件失败。界面必须先展示资格状态，再展示偏好匹配，不生成虚假的综合精确分数。

## 6. 功能模板与角色

首批只提供少量可编辑模板，避免把模板误当完整器件库：

1. 工业通信节点：控制器、通信收发器、隔离、电源与保护等可选角色；
2. 传感器采集节点：传感器/输入接口、信号调理、ADC、控制器、电源等可选角色；
3. 自定义空白方案：用户自己添加任意角色和条件。

模板仅用于生成初始角色和约束。用户可增删角色、修改用途、修改全部约束或将方案另存为本地模板。模板不内置“唯一正确器件组合”。

## 7. 兼容性与证据边界

角色间检查通过版本化规则注册表扩展，首批实现：

- 供电与 IO 电压范围是否相容；
- 数字接口类型是否对应；
- 数据速率或采样吞吐是否覆盖；
- 工作温度范围是否覆盖全局约束。

检查结果必须区分：通过、不兼容、资料不足、规则不适用和人工核验。每项结论记录参与器件、参数、换算过程、规则版本和证据 ID。

在线来源边界：

- 官方厂商文档可在人工确认版本后成为已验证证据；
- 授权分销商参数可作为待核验导入值；
- 聚合站、搜索摘要和自由文本只能帮助发现候选，不能直接通过硬条件；
- 来源冲突保留全部原值，显示冲突，不静默选择其中一个。

## 8. 失败路径、资源上限与恢复

- Local Agent 离线：本地目录、已有记录、条件编辑和离线筛选继续可用，在线发现单独降级；
- 查询超时或取消：保留已返回候选并允许重试，不复制半成品记录；
- 未知器件类别：使用通用自定义角色和手工参数，不猜测为 MCU 或收发器；
- 损坏记录：隔离单条记录并提供原始 JSON 导出，不影响其他记录加载；
- 存储超限：阻止新增保存，提示导出或删除，已有数据不被覆盖；
- 规则或注册表升级：保留规则版本，旧结果显示“需重新计算”，用户确认后生成新结果；
- 单方案建议上限：32 个角色、每角色 64 个约束、100 个候选；历史方案默认 100 条，本地存储继续设置总字节上限；超限时通过导入拆分或导出归档处理。

## 9. 旧能力迁移

- 保留现有 `PartRecord` v1、型号查询、在线精确型号发现、资料链接和 JSON 证据导出；
- `PartSelectionPanel` 与 `McuSelectionPanel` 的条件和候选能力迁入通用角色工作区，不直接删除；
- 旧 `PartSelectionRecord` v1 兼容读取，迁移成一个角色的 `FunctionSolution`，保留原 `scope`、时间、条件、候选和评估结果；
- 在迁移和回归验证完成前保留旧解析器，不通过清空 localStorage 解决结构升级；
- 原入口 `/resources` 保持有效，新增内部模式不得破坏 GitHub Pages 哈希路由和 `/EmbedKit/` 子路径。

## 10. 分阶段开发顺序

### 增量一：动态选型基础与布局骨架

1. 建立功能方案、器件角色、参数定义、动态约束和单位注册表；
2. 扩展确定性筛选引擎，支持动态运算符、单位校验和四级优先级；
3. 实现通用动态条件编辑器和用户自定义条件；
4. 将 MCU、通信筛选包装成角色适配器；
5. 建立三模式资料中心和三栏/折叠/窄屏分步布局；
6. 兼容读取旧记录并迁移为单角色方案；
7. 保证型号查询和旧数据不回退。

### 增量二：功能模板和完整方案持久化

1. 实现工业通信节点、传感器采集节点和空白方案；
2. 支持角色增删改、方案复制、自动保存、恢复和删除；
3. 导出带约束、候选、未知项和证据的完整方案 JSON；
4. 实现损坏记录隔离、超限提示和迁移状态展示。

### 增量三：角色扩展与兼容性检查

1. 增加传感器、ADC、隔离、电源、存储等角色适配器；
2. 实现首批电压、接口、速率和温度兼容性规则；
3. 支持从角色检查问题跳转到条件、候选参数和原始资料；
4. 规则未知时安全降级为人工核验。

### 增量四：在线标准化与报告

1. 将在线候选参数映射到参数注册表，并保留原始值和来源；
2. 支持官方资料核验状态、来源冲突和版本更新时间；
3. 导出可阅读报告并支持历史方案比较；
4. 形成从功能需求到可审计器件组合的端到端验收样本。

## 11. 测试与验收

每个增量必须先执行相关单元与界面测试，里程碑再执行 lint、生产构建和 Local Agent 回归。至少覆盖：

- 数值、范围、枚举、布尔和文本条件的正常与失败判断；
- 单位换算、非法单位、未知参数、冲突来源、非有限数值和边界上限；
- 必须条件排除、必须条件缺失、偏好排序、参考条件和未确定条件；
- 旧版记录正常迁移、部分损坏隔离、存储超限和恢复；
- Local Agent 在线、离线、超时、取消和结果部分返回；
- 桌面三栏、低分辨率折叠、移动分步模式和刷新恢复；
- 型号查询独立使用、功能选型独立使用、记录恢复，以及三者切换后状态不串扰；
- 生产构建资源保持 `/EmbedKit/` 前缀，哈希路由能直接进入资料中心。

首个可验收闭环：用户从空白方案创建“工业温度采集节点”，添加 MCU、ADC、CAN FD 收发器和电源角色，为任一角色增加自定义条件；系统能解释候选为何满足、排除或资料不足，保存后刷新可恢复，Local Agent 离线不丢失本地工作，并能导出包含来源与未知项的方案 JSON。

## 12. 完成判定

只有同时满足以下条件，功能方案工作台才可认定完成：

- 用户不受固定模板和固定参数限制，可以创建真实的自定义方案与约束；
- MCU、通信收发器是方案角色而不是伪装成产品功能；
- 结果具有确定性排除原因、未知项、证据和兼容性边界；
- 页面在常见桌面与窄屏下始终只有一个明确主工作区；
- 型号查询、资料导航和旧选型记录没有丢失或弱化；
- 保存、恢复、导出、失败恢复、资源上限和旧数据迁移均有测试；
- 每个开发增量测试通过后只提交相关文件并创建独立 Git 检查点。
