# EmbedKit 离线与更新策略

GitHub Pages 版本在生产构建中注册 Service Worker。用户至少成功在线打开一次后，应用壳和已经访问过的同源静态资源可在断网时继续使用。

## 离线可用

- 已加载过的工作台页面和嵌入式网页工具。
- 内置资料索引、课程内容和学习进度。
- 浏览器本地保存的设备项目、测试套件、测试历史与分析摘要。
- 工作区备份文件的导出和导入。

首次从未打开的懒加载页面可能尚未进入缓存，因此不能承诺离线可用。用户在离线使用前应在线进入需要的页面一次。

## 离线不可用

- Local Agent 未运行时的真实串口、TCP/UDP、本地文件、ELF 深度解析和可选构建。
- 外部芯片资料、数据手册、云端 AI 和其他联网来源。
- 尚未缓存的页面代码和静态资源。

Service Worker 不缓存 `/EmbedKit/api/` 请求，不会把设备会话、AI 请求或本地文件接口响应当作离线数据。

## 更新行为

新 Service Worker 安装完成后，页面显示“发现新版本”。用户点击“更新并重载”才切换到新缓存；不会在正在调试或编辑时强制刷新。激活后删除旧的 `embedkit-shell-*` 缓存。

开发服务器不注册 Service Worker，避免旧缓存干扰本地调试。生产验收使用：

```powershell
cd frontend
npm run build
npm run verify:pages
npm run preview
```

在线打开页面并依次访问需要离线使用的模块，然后在浏览器开发者工具中切换 Offline 并刷新。应显示离线提示，Hash 路由仍可恢复；真实设备和联网入口应显示各自的离线或 Agent 状态，不得伪装可用。
