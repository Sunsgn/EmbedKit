# EmbedKit v1 产品完成方案

## 1. 完成目标

EmbedKit v1 定义为面向通用嵌入式开发的本地优先工作台。它不替代 Keil、IAR、CMake 或芯片厂商 IDE，而是把设备项目、工程理解、通信调试、自动化测试、运行证据和报告串成可追溯闭环，同时保证每个主要模块可以独立使用。

“完成”不表示无限增加页面，而表示以下核心流程都有真实输入、明确失败路径、持久化、自动测试和可交付文档：

1. 不创建设备项目即可直接完成串口、TCP、UDP、WebSocket 调试。
2. 可选地把通信会话关联到设备、固件和测试运行，但关联不是前置条件。
3. 导入通用 C/C++ 工程及已有 MAP、ELF、日志和运行轨迹后，能给出带文件、行号、证据和置信度的结构与执行流程。
4. 流程测试支持串口、网络、延时、发送、等待、断言、变量和失败停止，并能生成可导出的真实报告。
5. GitHub Pages 上纯浏览器功能独立可用；需要本机权限的功能由版本化 Local Agent 提供并明确降级。

## 2. 系统边界

| 层级 | 职责 | 不承担的职责 |
| --- | --- | --- |
| GitHub Pages 前端 | 工作区、浏览器工具、数据展示、本地持久化、能力检测 | 直接访问任意文件、串口或原始套接字 |
| Local Agent | 串口、TCP/UDP、工程文件、受控进程、工具链检测 | 云端保存用户源码或替代厂商 IDE |
| 领域服务 | 工程模型、MAP/轨迹解析、测试执行、报告生成 | 页面布局和平台专用命令 |
| 适配器 | 工具链、工程、OS、协议和测试设备差异 | 改变公共数据模型 |

## 3. 完成矩阵

### P0：独立通信与测试底座

- 前端 Vitest/Testing Library 基础设施。
- 通信页无需设备项目即可进入并切换全部传输方式。
- Agent 离线、协议不兼容、端口占用、权限拒绝的明确提示。
- TCP/UDP 客户端和服务端真实回环测试。
- WebSocket 本地回环测试，覆盖文本、二进制、断线和重连。
- 串口传输适配器可注入；自动测试使用内存虚拟串口，真实设备使用系统串口适配器。
- 测试日志带统一毫秒时间戳、方向、字节数、文本和 HEX 证据。

验收：无设备项目时通信页面测试通过；Agent 测试、前端测试、lint 和生产构建全部通过。

### P1：集成测试闭环

- 用例和流程步骤支持新增、复制、排序、删除、撤销和版本迁移。
- 一个流程首次选择串口后，后续串口步骤默认继承；允许显式覆盖并清楚显示来源。
- 支持串口/TCP/UDP/WebSocket 的连接、发送、等待、断言和关闭步骤。
- 变量、超时、重试、取消、清理和失败停止语义统一。
- 运行环境、设备、固件、Agent 版本、输入、输出和失败证据进入报告。

验收：AT 联网流程通过虚拟模组运行；任一步失败时资源被关闭且报告能定位失败步骤。

### P2：工程理解与证据链

- 自动识别 Keil、IAR、CMake、Make、Ninja 和未知裸机工程，不自动重复编译。
- 优先消费已有 MAP、ELF、构建配置和日志；构建只作为用户显式选择的可选能力。
- 执行模型覆盖裸机循环、事件驱动、回调、中断和可插拔 RTOS 适配器。
- 程序框架展示启动链、任务/线程、状态机、回调、中断和模块依赖。
- 所有结论可跳转文件与行号，并显示来源、覆盖率、未知项和置信度。
- MAP 优化建议包括 Flash/RAM 热点、重复与大符号、栈风险和可执行控制建议。

验收：至少使用裸机、主流 RTOS、非 FreeRTOS 和未知格式四组固定样本回归。

### P3：设备项目与真实设备闭环

- 设备、固件、连接配置、会话、测试运行和分析报告使用稳定 ID 关联。
- 通信页已有独立会话可选择性归档到设备项目。
- 真实设备验收清单覆盖串口收发、波特率切换、DTR/RTS、拔插恢复和长时间接收。
- 提供虚拟设备脚本与人工硬件测试说明，自动测试不伪装成真实设备结果。

验收：同一设备的一次通信会话、一次测试运行和一份报告可互相追溯，独立模式仍正常。

### P4：发布、可靠性与安全

- GitHub Actions 依次运行前端测试、lint、生产构建和 Local Agent 测试后才能部署。
- `/EmbedKit/` 子路径、哈希路由和静态资源自动验证。
- Local Agent 实施来源校验、结构化错误、能力协商、路径约束、参数化进程和日志脱敏。
- 长日志采用条数/大小上限和增量读取；所有轮询可取消并在卸载后停止。
- IndexedDB 数据带版本、迁移、导入导出和损坏降级。

验收：全量质量门禁通过，线上地址可访问，Agent 离线不会阻断纯浏览器功能。

### P5：嵌入式工具箱

- 所有计算、编码、校验和转换工具不依赖设备项目、Local Agent 或网络即可独立使用。
- 统一输入格式、进制标识、范围校验、错误定位、复制、清空和导出行为。
- 补齐常用嵌入式能力：CRC/校验和、进制与字节序、位域、串口时间、定时器、波特率、分压/ADC、色环电阻、存储容量、时间戳和常见协议帧辅助。
- 算法与页面分离，每个工具覆盖标准向量、空输入、非法输入、上下界和大输入测试。
- 计算结果显示公式、单位、舍入方式和适用边界，不把估算结果伪装成芯片手册结论。

验收：工具核心算法单元测试通过，页面在无 Agent、无网络和无设备项目时仍可完成输入到导出的完整操作。

### P6：资料中心

- 本地基础器件目录可离线搜索、分类、筛选和查看，不因外部数据源失败而清空页面。
- 外部资料通过可注册数据源适配器接入，记录来源 URL、厂商、抓取时间、字段置信度和失败原因。
- 数据手册、封装、参数和采购信息分别建模，禁止把搜索摘要当作已验证器件参数。
- 支持用户收藏、标签、项目可选关联、最近查看、数据导入导出和失效链接标记。
- 外部请求实施域名白名单、超时、取消、缓存、速率限制和结构化错误；不上传用户工程或敏感数据。
- 建立多厂商、多品类、无结果、网络失败、字段冲突和离线模式测试矩阵。

验收：断开网络后本地目录和收藏仍可用；外部来源失败时显示具体来源状态；数据手册链接与结构化参数均能追溯证据。

## 4. 自动执行顺序

每个夜间批次只处理一个可回退增量：

1. 读取 `AGENTS.md`、本文件、Git 状态和最近检查点。
2. 跳过用户未提交文件，不清理、不覆盖、不批量暂存。
3. 选择完成矩阵中最高优先级且未完成的一项。
4. 先增加失败用例，再做最小通用实现。
5. 运行受影响测试；里程碑再运行前端测试、lint、build 和 Agent 测试。
6. 复核功能没有回退，只提交本项相关文件。
7. 在本文件“执行记录”中写入结果、测试、提交号和剩余风险。
8. 遇到真实设备、密钥、外部发布或产品决策时停止该项并转做不依赖该阻塞的任务。

## 5. 夜间质量门禁

```text
frontend: npm test && npm run lint && npm run build
proxy:    npm test
git:      git diff --check
```

禁止无人值守执行：真实设备固件下载、删除用户数据、上传源码或日志、强制修复依赖、修改密钥、推送远程分支和发布生产版本。
