# EmbedKit 真实设备通信验收

虚拟串口和回环网络测试用于自动回归，不能代替真实 USB 转串口、目标板和固件验收。本流程只收集通信证据，不下载固件、不自动选择端口，也不修改工程。

## 1. 准备

1. 关闭占用目标串口的 Keil、IAR、串口助手和烧录工具。
2. 确认设备供电、电平和地线；TTL、RS-232、RS-485 不得直接混接。
3. 在 `proxy` 目录安装锁定依赖：`npm ci`。
4. 使用 `npm run serial:list` 获取系统实际端口和 USB 标识。

## 2. 自动证据采集

文本请求示例：

```powershell
node scripts/serial-device-acceptance.mjs --port COM11 --baud 115200 --send "AT" --expect "OK" --timeout 3000
```

HEX 请求示例：

```powershell
node scripts/serial-device-acceptance.mjs --port COM11 --baud 115200 --hex "01 03 00 00 00 02 C4 0B" --timeout 3000
```

联网或鉴权指令必须增加 `--redact-request`，避免密码进入报告：

```powershell
node scripts/serial-device-acceptance.mjs --port COM11 --send "AT+CWJAP=..." --expect "OK" --redact-request
```

只有设备确实要求时才附加 `--dtr` 或 `--rts`。命令输出版本化 JSON，包含串口参数、发送字节数、接收文本/HEX 预览、接收总字节数、期望和耗时；有期望但不匹配、或完全没有接收数据时退出码为非零。接收证据默认最多保留 64 KiB，可用 `--max-capture 256..1048576` 调整；达到上限后继续统计总字节数，并以 `truncated: true` 明确标记，不会无限占用内存。

## 3. 人工验收矩阵

- 正确波特率下连续收发并核对 RX/TX 字节数。
- 错误波特率应显示乱码或期望失败，不得误报通过。
- 在线切换波特率后再次收发，不要求关闭页面或重建设备项目。
- 分别验证不追加、CR、LF、CRLF 行尾。
- 根据目标硬件说明验证 DTR/RTS；默认保持 OFF。
- 连续接收逐字节输出、无换行输出和高速突发数据。
- 拔出设备后显示断开或错误；重新插入后可由用户明确恢复。
- 两个串口会话同时运行并验证分屏、日志过滤、快捷指令和定时发送。
- 导出日志并确认时间戳、方向、文本/HEX 和字节统计可追溯。

真实设备结果必须记录设备型号、固件版本、USB 转串口型号、端口、参数和测试时间。没有连接真实硬件时只能报告“自动回归通过、真实设备待验收”。

## 4. 集成测试证据闭环

1. 启动 Local Agent，在集成测试的“通道配置”中按需展开串口 A/B 的“新建或复用连接”，选择端口和波特率；非常用的数据位、停止位、校验和流控在“高级串口参数”中设置。用例可设置默认发送行尾，文本“发送数据”和“发送并断言”步骤可独立继承或覆盖为无行尾、CRLF、CR、LF；HEX 步骤始终按显式字节发送。步骤基础属性、流程变量、流程默认值、重试策略及高级断言默认折叠，折叠标题必须保留当前配置摘要。也可以在通信调试的已连接会话中点击“用于集成测试”，跳转后明确绑定到串口 A 或 B；绑定成功只显示会话摘要，需要时再点“更换连接”。交接记录只在当前浏览器会话保存 10 分钟，跳转不会自动运行测试。
2. 页面直接创建的串口会话应在测试结束、手工解除或页面退出时关闭；复用的外部会话只解除绑定，不得由集成测试关闭。拔出或占用端口时应显示可恢复的连接或读取错误。
3. 如需证明固件版本，先对构建产物计算 SHA-256，再在集成测试页选择该指纹。文件名相同不能代替指纹；不关联固件仍可运行。
4. 运行流程后导出 JSON 或 HTML。报告应包含当前模型版本、可选固件指纹、通信端点、会话 ID、RX/TX 字节和逐步证据。
5. 超时用例应保存期望值、有限长度的实际接收数据、超时值和重试次数；没有接收数据时必须明确为空，不得伪造响应。
6. 人工确认在报告中必须标记为 `manual-confirmation`，不能当作自动设备响应。
7. 检查 JSON 中没有密码、令牌、绝对源码路径、固件内容或 Local Agent 授权令牌，再归档报告。

串口、TCP/UDP、WebSocket、集成测试和设备项目始终保持可选关联；任何一个模块缺失都不能阻止其他模块独立使用。

## 5. WebSocket 独立链路自测

在 `proxy` 目录运行 `npm run websocket:loopback`，然后在“通信调试 → WebSocket”中连接 `ws://127.0.0.1:18080`。依次发送文本和 HEX 数据，应原样回显；主动断开后可再次连接。

`npm test` 还会在真实本地 socket 上自动验证文本、二进制、关闭和重连。该回环只证明 EmbedKit WebSocket 链路正常，不代表目标设备或远程服务已验收。
