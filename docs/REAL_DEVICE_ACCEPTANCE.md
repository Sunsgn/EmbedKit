# EmbedKit 真实设备通信验收

虚拟串口和回环网络测试用于自动回归，不能代替真实 USB 转串口、目标板和固件验收。本流程只收集通信证据，不下载固件、不自动选择端口，也不修改工程。

## 1. 准备

1. 关闭占用目标串口的 Keil、IAR、串口助手和烧录工具。
2. 确认设备供电、电平和地线；TTL、RS-232、RS-485 不得直接混接。
3. 在 `proxy` 目录安装锁定依赖：`npm ci`。
4. 使用 `npm run serial:list` 获取系统实际端口和 USB 标识。

## 2. 自动证据采集

文本请求示例：

```powershell
node scripts/serial-device-acceptance.mjs --port COM11 --baud 115200 --send "AT" --expect "OK" --timeout 3000
```

HEX 请求示例：

```powershell
node scripts/serial-device-acceptance.mjs --port COM11 --baud 115200 --hex "01 03 00 00 00 02 C4 0B" --timeout 3000
```

只有设备确实要求时才附加 `--dtr` 或 `--rts`。命令输出版本化 JSON，包含串口参数、发送内容、接收文本/HEX、字节数、期望和耗时；有期望但不匹配、或完全没有接收数据时退出码为非零。

## 3. 人工验收矩阵

- 正确波特率下连续收发并核对 RX/TX 字节数。
- 错误波特率应显示乱码或期望失败，不得误报通过。
- 在线切换波特率后再次收发，不要求关闭页面或重建设备项目。
- 分别验证不追加、CR、LF、CRLF 行尾。
- 根据目标硬件说明验证 DTR/RTS；默认保持 OFF。
- 连续接收逐字节输出、无换行输出和高速突发数据。
- 拔出设备后显示断开或错误；重新插入后可由用户明确恢复。
- 两个串口会话同时运行并验证分屏、日志过滤、快捷指令和定时发送。
- 导出日志并确认时间戳、方向、文本/HEX 和字节统计可追溯。

真实设备结果必须记录设备型号、固件版本、USB 转串口型号、端口、参数和测试时间。没有连接真实硬件时只能报告“自动回归通过、真实设备待验收”。
