# AIES V6：AI 开发约束入口（L0）

本包用于约束具备文件、终端和测试能力的 AI 开发工程，不替代 AI，也不要求每次全文读取所有规则。

## 强制加载顺序

1. 每个新任务只先读取本文件；禁止递归读取整个 `rules/`、`docs/`、历史资料或所有专业约束。
2. 确认项目根、用户要求、允许写入范围和已有修改后，运行：

   `python -m aies route --project-root <项目根> --task <用户原始需求> --json`

3. AI 只读取路由结果中的 `ai_read_files`。`machine_rule_files` 供程序校验，禁止为理解任务而全文载入模型上下文。
4. 任务影响扩大时重新路由并增量读取新文件；已读取且 SHA-256 未变化的文件本会话不重复读取。
5. 项目自己的 `AGENTS.md`、`CLAUDE.md`、`CONSTRAINTS.md`、`.ai/PROJECT_PROFILE.md` 只按目标路径作用域加载；不得把一个项目事实推广为全局默认值。

## 不可省略的全局底线

- 先发现真实工程、约束、Git/文件状态、构建/EDA/测试入口，再修改。未知事实标记 `UNKNOWN/CONFLICT`，禁止猜测芯片、RTOS、引脚、SDK、协议、板厂或阈值。
- 写入仅限用户授权根目录，保护已有脏文件；不得回退、覆盖或混入用户无关改动。
- 删除、覆盖、移动、clean、烧录、设备控制、Git 变更、制板、生产和正式发布分别需要精确目标、影响、恢复方案及独立授权。
- 外部命令使用参数数组、固定工作目录、超时和允许列表；不得把用户文本拼成 Shell 命令。
- 实现后必须实际运行可用的构建和测试，保存当前输入、工具版本、退出码、原始日志、产物及 SHA-256。
- 缺工具、设备、许可证、原生工程或批准时标记 `UNAVAILABLE/BLOCKED/NOT_RUN`；Mock、旧产物、退出码 0、图片或 AI 自填批准不能成为真实 PASS。
- `COMPLETED` 仅在完成合同的全部必需检查都有有效证据时成立。中断恢复先重验输入锁和工作区；不确定的非幂等动作进入 `NEEDS_REVIEW`，不得盲目重放。
- 详细日志落盘，对话只给结论、关键错误、证据路径和下一动作。Token 优化不得跳过安全、兼容、失败路径和回归验证。
- 宿主未强制所有写路径经过执行器时，隔离能力标记 `POLICY_ONLY`，不得宣称强制沙箱。

## 使用定位

AI 负责理解需求和实际开发；本包负责按需提供专业约束、路由、证据门禁和恢复规则。路由只是确定应读内容，不等于完成设计、编码或验证。
