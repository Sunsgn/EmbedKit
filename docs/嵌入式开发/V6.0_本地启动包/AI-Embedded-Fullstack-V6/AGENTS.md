# AIES V6.0 统一 AI 工程约束入口

本文件是 AI 在本包内工作的唯一统一文字入口。`rules/*/rules.json` 是其可执行注册表；项目内约束只在自身目录作用域提供事实和更严格规则。

## 目标与边界

按任务和真实资料完成：发现 → 提取事实 → 路由影响 → 完成合同 → 受控执行 → 验证 → 整改回归 → 证据交付 → 可恢复交接。

- 平台无关：不得默认 STM32、FreeRTOS、Keil、GCC、KiCad、Windows 或任何单一项目。
- 本地优先：工程资料默认留在本地；外部服务必须说明发送范围并获授权。
- 不替代工具链：识别并调用已有 IDE、编译器、EDA 和测试入口；没有真实工具、许可证、工程或设备时标记 `UNAVAILABLE`、`BLOCKED` 或 `NOT_RUN`。
- BS20、A22 和示例工程只用于其自身作用域或验证，不得成为全局芯片、串口、SDK、路径和构建默认值。
- 不允许用 Mock、图片、旧产物、退出码 0、空日志或 AI 自填批准冒充真实构建、ERC/DRC、实机或生产验证。

## 每次任务的强制顺序

1. 确认目标根目录真实存在、允许写入范围、Git/文件现状和用户已有修改；路径不符时拒绝写入，不猜测替代路径。
2. 只读发现根目录到目标路径作用域内的 AI/项目约束、Profile、构建入口、源码、EDA、测试和版本信息。
3. 记录事实来源、路径、SHA-256、作用域、版本、状态与可信度。不同来源冲突时输出 `CONFLICT`，禁止猜一个值继续改写。
4. 使用 `python -m aies route` 按“工程事实 + 任务目的 + 影响”选择专业规则；未知任务保持只读，不能以空 `GENERAL` 规则编辑。
5. 在执行前生成任务、输入锁、计划和完成合同；合同必须列出每个必需检查、证据和失败动作。
6. 仅通过类型化适配器执行允许的动作，固定参数、工作目录、超时、工具版本、输入与输出；禁止把用户字符串拼成 Shell 命令。
7. 执行“实现 → 测试 → 原始证据 → 判断 → 修复 → 回归”；失败测试不得删除或放宽。
8. 更新状态、日志、证据、`HANDOFF` 和验收结果；仍受外部条件阻塞的任务保持真实状态。

## 路由、风险与专业加载

- 项目模式：`PROJECT_NEW`、`PROJECT_EXISTING`、`PROJECT_UNKNOWN`。
- 深度：`LIGHT` 只读/局部，`STANDARD` 模块及受影响回归，`FULL` 跨系统或发布门禁。
- 风险：`T0` 只读，`T1` 局部修改，`T2` 接口/模块变化，`T3` 系统/高影响设计，`T4` 实物、生产或正式发布。
- 普通软件任务加载 core/software 及实际受影响规则；原理图审核不自动加载 PCB 布线；PCB 制造输出追加制造追溯；Pinmux/ADC/标定追加软硬件接口与验证；安全功能追加安全、集成和失效验证。
- 纯目录任务只加载目录规则；已有工程的普通开发不得自动迁移目录。新项目只创建 V1.20 最小入口和当前真实需要的分支。

## 授权与工程保护

只读操作可执行；隔离新建和授权构建限于指定范围。覆盖、移动、删除、清理、烧录、设备控制、Git 变更、制板、生产发布和正式批准分别需要精确目标、影响、恢复方案和独立授权。

- 写入前保护已有脏文件；与用户改动重叠时停止，不回退、不覆盖。
- 删除或移动必须校验解析后的绝对路径；不得对工作区根、主目录、盘符根或未解析变量做递归操作。
- 同一权威文件只有一个写入拥有者；并发冲突必须阻断。
- 当前 Python 执行器不能阻止宿主上的其他 Shell/文件路径，因此隔离等级必须报告 `POLICY_ONLY`，不得宣传为操作系统强制隔离。

## 证据、完成与恢复

验证层级必须分开：`SCHEMA_VALID`、`ARTIFACT_VERIFIED`、`TOOL_VERIFIED`、`INTEGRATION_VERIFIED`、`APPROVAL_VERIFIED`。后一级不能由前一级或 AI 声明自动升级。

- `PASS` 必须绑定具体验收项、当前输入、工具版本、退出码、原始日志、预期产物及 SHA-256；必需产物缺失时即使退出码 0 也不能 PASS。
- `COMPLETED` 仅在完成合同的所有必需检查均有有效证据时成立；数据不足必须区分 `UNKNOWN/NOT_RUN`，不能写“未发现问题”。
- 恢复时重新验证包版本、输入锁、源码/EDA 哈希、工具版本和脏工作区。已完成操作不重复；结果不确定的烧录、删除、覆盖、提交、生产动作进入 `NEEDS_REVIEW`。
- 日志采用追加式事件记录；长任务有超时、停止、有限重试和资源释放。日志、轨迹和大文件必须有大小或条数上限。

## 专业最低要求

- 软件：核对调用链、并发/中断、超时恢复和资源边界；实际构建并回归。缺目标数据则资源结论为 UNKNOWN。
- 原理图/PCB：使用原生可编辑工程，核对器件/网表/封装/叠层/板厂条件，真实运行 ERC/DRC 并重新打开核查；没有 EDA 或布线引擎就报告能力缺口。
- 协同：维护需求→引脚/电气/时序→驱动/任务/状态→测试的双向映射；修改任一端检查另一端。
- 测试/制造：记录版本、设备/仪器、刺激、阈值、原始结果；硬件、固件、BOM、标定和产测配置不兼容或未知时禁止放行。
- 安全：明确故障默认状态、时序限制、故障注入和责任批准；网络可用不能替代本地安全行为。

## 输出、效率与复核命令

对话只给摘要、关键错误、证据路径和下一动作，完整日志落盘。先定位再局部读取；同会话缓存未变规则，跨会话重验哈希。Token 节省不得降低规则覆盖。命令用法见 `QUICKSTART.md`，复核运行 `python -m unittest discover -s tests -v`。

任何规则冲突按顺序处理：平台安全和本次有效授权 > 当前目标工程权威事实与更严格约束 > 本文件及可执行规则 > 历史参考。无法决定时停止受影响写操作，继续不依赖该冲突的安全只读工作。
