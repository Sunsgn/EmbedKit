# 项目目录、资料与归档详细约束

## 适用范围与首要原则

适用于新项目初始化、现有目录盘点、资料整理、迁移、归档和交付映射。普通开发不得借“统一目录”迁移既有工程；现有布局默认保留，只建立映射和最小增量。目录整齐不能优先于构建、IDE、脚本、链接和用户历史兼容。

## 模式识别与开始前清单

- `PROJECT_NEW` 仅在解析后的目标根为空或只含允许的初始化元数据时成立；发现源码、工程、Git 或用户文件立即转为现有项目模式并停止创建。
- `PROJECT_EXISTING` 先生成只读清单：路径、类型、大小、mtime、哈希（适用时）、Git 状态、入口、构建/工程引用和敏感性；不立即移动。
- `DIRECTORY_ONLY` 任务不得顺带改代码、工程配置或产品行为；需要修复引用时形成独立变更和测试。
- 所有目标路径先解析绝对路径并验证在项目根；禁止跟随链接写到根外、用通配符跨层移动或覆盖同名文件。

## 新项目最小初始化

- 只创建项目入口、`.ai/PROJECT_PROFILE.md`、必要业务目录和最小说明；未知芯片、IDE、RTOS、构建系统和目录保持 `UNKNOWN`，不得生成虚假平台骨架。
- 根 `AGENTS.md` 只说明按需加载和授权边界，详细专业规则保存在约束包；禁止复制所有领域全文到每个项目。
- Profile 记录项目身份、平台、构建、板级映射、实时参数、协议、验证和授权；事实必须标来源，示例值不得保留成配置。
- 初始化在非空目录必须失败而非合并；重复初始化应幂等且不覆盖用户已填写 Profile。

## 现有工程盘点与分类

- 识别 IDE 工程、构建脚本、源码、链接脚本、配置、原理图/PCB、制造包、测试、工具、文档、固件、日志和生成物。
- 使用构建引用、包含路径、Git 跟踪和文档链接判定角色；仅凭扩展名不能断定文件可删除或属于输出。
- 重复文件以哈希、版本、引用和权威来源判断，禁止按名称/mtime自动删重。冲突版本都保留并标 `CONFLICT`。
- 大文件、二进制、日志和第三方包记录来源、许可证、保留策略和是否应进入 Git；不得无审查地加入宽泛 ignore。

## 移动、重命名与引用修复

- 移动前建立逐文件源→目标映射、冲突策略、引用清单、回退方法和预期 Git rename；未经明确目录任务授权不得执行。
- 目标存在时禁止覆盖；区分大小写冲突、Unicode 规范化、Windows 保留名、路径长度和跨平台分隔符。
- 修复构建文件、IDE 工程、include、脚本、CI、文档、EDA 库、测试夹具和发布配置中的引用；禁止只修文本中最明显路径。
- 移动后运行旧入口兼容检查和正式构建/测试；需要兼容链接或过渡脚本时说明期限，不能永久形成双权威副本。

## 文档、记录与权威源

- 每类资料指定权威源、所有者、版本和生成关系；生成 PDF/Gerber/报告不得反向覆盖原生可编辑文件。
- 开发记录包含目标、输入版本、变更、验证、证据和剩余项；临时日志/单次调试不堆入长期约束。
- 协议、数据手册和外部资料保存来源 URL/路径、版本、适用范围和验证日期；搜索摘要不得成为唯一权威依据。
- 文档链接使用可移植相对路径（适用时），敏感本地绝对路径和凭据不得进入公共交付。

## 生成物、日志与容量管理

- 构建输出、缓存、下载、运行日志、测试证据和正式交付分别管理；不得把正式固件和临时 output 混在无版本目录。
- 日志/抓包/波形设置单文件、总量、保留和轮转；清理前确认目标及证据保留要求，优先归档而非不可恢复删除。
- `.gitignore` 每条规则有对象和理由，先检查是否误排源码、配置、测试数据或正式交付；禁止用 `*` 掩盖未知文件。
- 归档包含清单、哈希、格式/版本、依赖、恢复说明和兼容读取；仅压缩成功不能证明可恢复。

## 交付、迁移与恢复验证

- 交付清单区分源码、原生设计、构建工具、依赖锁、固件、制造、测试、证据和使用说明；缺项明确 `NOT_INCLUDED` 及原因。
- 在干净临时目录解压，验证路径安全、清单哈希、CLI/构建/测试入口和文档链接；原工作区成功不能替代净室验证。
- 迁移到另一计算机时重建工具版本、项目配置和关联记录；机器专有密钥/许可证不应打包，提供合法恢复方法。
- 回滚使用 Git/备份或映射逆操作，先验证目标无新用户修改；禁止整体 reset 覆盖迁移后的有效工作。

## 验收、证据与失败门禁

证据包括模式判定、前后清单/哈希、移动映射、引用影响、冲突、构建/测试、净室恢复和回退说明。非空目录被当新项目、越界路径、覆盖同名文件、权威源丢失、引用未修复或归档无法恢复时判 FAIL 并停止；目录“看起来整齐”不得作为 PASS。
