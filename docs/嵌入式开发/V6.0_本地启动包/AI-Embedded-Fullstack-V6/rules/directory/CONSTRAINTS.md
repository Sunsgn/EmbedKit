# 项目目录、资料与迁移具体约束

## 适用范围与模式

只在目录初始化、整理、迁移、扩展或审核时加载。模式为 `NEW/ORGANIZE/EXTEND/AUDIT`；普通代码、构建和调试任务不得触发目录迁移。先读取项目 Profile 和目录框架版本/SHA；状态缺失或变化时完整读取 V1.20。

## NEW 与 EXTEND

NEW 仅在真实空项目创建根入口、`.ai/` 和四个核心入口：`program/`、`开发文档/`、`硬件原理图PCB/`、`测试/`。只创建当前真实需要的子分支，不批量生成空目录或 `.gitkeep`，未知事实写 UNKNOWN。

EXTEND 只创建指定新领域及入口，不能补齐整棵生命周期树。已有项目使用自己的唯一源码容器和例外名，禁止形成 `project/project` 或同义重复目录。

## ORGANIZE 六阶段

1. 只读盘点所有根级项目、隐藏文件、链接/联接、嵌套仓库、LFS/子模块及 Git 状态；记录路径、类型、数量、大小、时间和 SHA-256。
2. 将每项标记为迁移、保持、工程内部保持、外部隔离或待确认；确认源码顶层边界，工程内部 docs/tests/tools/build 不拆分。
3. 列出完整源→目标映射、冲突、精确破坏性动作、恢复保障、验证和最终根目录，范围不变时只请求一次批次确认。
4. 优先复制保留源或对已跟踪文件使用可恢复的 `git mv`；目标同名先比较哈希，禁止猜测覆盖。
5. 构建前核对文件数、总字节、逐文件哈希、额外/零字节、链接/LFS/子模块；再检查路径引用并从工程容器运行原入口测试。
6. 只有完整性和功能验证通过且清理路径已单独批准时才能删除源；最终逐项复查根目录残留并输出报告。

## 文件、存储与权威性

每个可编辑受控资料只有一个主文件；release、manufacturing、生产备份可保存有清单的只读快照。二进制达到 10 MiB 评估 LFS/外存，达到 50 MiB 不进入普通 Git 历史；外存记录位置、版本、大小和哈希。

`.gitignore` 精确匹配已确认输出，不能广泛忽略 Makefile、链接脚本、库、CMake 或正式产物。凭据、私钥、真实设备密钥和敏感 `.env` 不进入目录或日志。

## 验收、证据与失败处理

必需证据：完整盘点、迁移映射、授权、数量/字节/哈希对比、引用检查、原入口结果、Git 差异、源保留/清理状态和恢复方法。主体工程迁入不代表整批完成。

源不可读、哈希失败、同名冲突、边界不明、引用/构建失败或授权变化时停止受影响迁移并保留源。AUDIT 始终只读；目录任务不得自动获得删除、Git 或生产操作权限。
