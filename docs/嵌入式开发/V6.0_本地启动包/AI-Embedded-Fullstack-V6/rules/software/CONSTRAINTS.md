# 嵌入式软件开发具体约束

## 适用范围与输入

适用于裸机、事件驱动、不同 RTOS、嵌入式 Linux、BSP/驱动、协议、存储、Bootloader/OTA 和构建诊断。输入必须来自目标工程：源码版本、构建入口、编译器/SDK、板级映射、接口协议、资源限制和既有测试。不得用 BS20、A22、STM32、FreeRTOS、GCC 等样例值替代未知事实。

## 工程识别与设计动作

1. 定位启动入口、初始化顺序、任务/事件、ISR、调用链、共享状态和构建目标；结论标注文件与行号。
2. 优先复用既有 HAL、错误码、日志、队列、状态机和协议工具；新增接口定义参数、返回值、所有权、调用上下文、超时、线程安全及释放路径。
3. 修改范围保持最小；公共模型和适配器承载平台差异，业务层不得散落芯片、IDE、RTOS 或绝对路径特例。
4. 外部输入先校验长度、范围、版本、编码、大小端和校验值；所有缓冲区说明最大长度及溢出策略。

## 中断、DMA、并发与实时性

- ISR 仅处理必要状态、清标志和投递事件；禁止阻塞、动态分配、日志格式化、协议解析、Flash 操作和无界循环。
- DMA 缓冲明确所有者、生命周期、cache/对齐要求、半满/满事件、并发边界和溢出恢复；接收处理覆盖分包、粘包、空闲超时及高吞吐。
- 共享 UART/I²C/SPI/CAN/ADC/Flash 有单一驱动入口和互斥/队列策略；禁止多个模块绕过所有权直接访问。
- 任务明确职责、优先级、栈、周期/截止期、阻塞点和失败降级。重试有最大次数、退避和最终状态；禁止忙等和无限等待。
- 看门狗只能在关键周期真实完成后喂狗；长任务评估启动、报警、通信及低功耗影响。

## 外设、协议与数据

- GPIO/时钟/复位/Pinmux、DMA 通道和中断优先级来自板级权威配置，并与硬件契约双向核对。
- ADC 明确参考、分辨率、采样时间、量程、单位、校准、滤波、舍入、溢出和异常值；高频路径优先确定性整数/定点实现。
- 协议解析依次校验帧头、版本、长度、命令、校验和与剩余字段；未知版本/字段有兼容策略。结构体不得直接强转线格式。
- 队列有限长并定义满策略和安全消息优先级；通信失效不得阻塞本地安全功能。
- NVM 数据包含版本、长度、校验、默认恢复、迁移和回退；限制写频率并处理掉电。OTA 要求镜像身份/签名、兼容矩阵、原子切换、失败回退和防降级策略。

## 构建、资源与测试

使用工程原有入口和真实工具链，记录工具版本、目标、参数、退出码、完整日志和新产物哈希；旧 output 或旧日志不得作为本次证据。先运行受影响测试，再执行必要回归。

资源报告至少覆盖 Flash/ROM、RAM、堆、任务栈高水位、静态缓冲、协议缓存和关键时序。没有 MAP/ELF、栈测量或目标数据时写 `UNKNOWN/NOT_RUN`，禁止估算成 PASS。测试覆盖正常、边界、非法输入、超时、竞争、队列满、复位/掉线、掉电恢复和兼容旧数据。

## 验收、证据与失败处理

必需证据：源码定位、最小 diff、构建日志、产物哈希、测试日志、资源报告和未验证项。编译成功不能替代设备/时序验证；合成工程只能证明适配器路径。构建或必需回归失败时保留失败证据并停止相应放行，不得关闭功能、大范围重构或删除失败测试来变绿。
