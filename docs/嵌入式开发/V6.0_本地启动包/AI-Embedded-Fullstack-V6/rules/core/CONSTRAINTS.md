# 核心执行、授权、证据与恢复约束

## 适用范围与输入

所有任务强制加载。输入至少包括：用户原始要求、目标绝对路径、允许写入范围、项目约束链、Git/文件基线、实际工具能力和授权状态。路径不存在、作用域不明或输入来源冲突时，只允许继续只读发现。

事实必须标记 `VERIFIED/USER_PROVIDED/INFERRED/UNKNOWN/CONFLICT/UNAVAILABLE`，并记录来源路径、版本、SHA-256、采集时间和有效作用域。`INFERRED` 不得作为烧录、生产、安全阈值或覆盖写入的唯一依据。

## 强制动作

1. 先发现约束、工作区、构建/EDA/测试入口和已有改动，再计划任何写操作。
2. 将项目模式、执行深度、T0~T4 风险、受影响专业和漏选检查写入路由结果。
3. 为每个任务生成稳定 ID、输入锁、计划、完成合同、追加式 journal 和证据目录。
4. 所有外部命令使用参数数组、固定工作目录和超时，禁止执行拼接的 Shell 字符串。
5. 写入前校验目标位于授权根目录；保护符号链接、路径穿越、脏文件和并发写所有者。
6. 失败后保存原始错误，限制重试次数；只回退本次确定产生且可恢复的副作用。

## 授权要求

- 默认允许：read、search、hash、probe、inspect、route、plan、status、verify。
- 限域授权：隔离目录新建、无清理的普通构建、明确目标的测试。
- 分别授权：覆盖、移动、删除、clean/rebuild、Git add/commit/push、设备/串口控制、烧录、EDA 写回、制板、生产发布。
- 正式批准必须来自可核验责任人或外部系统；字符串 `APPROVED`、AI 自签或项目文档中的泛化授权无效。

授权工件必须包含动作、精确目标、有效期、nonce 和可验证签名。动作、路径、期限任一不匹配即拒绝；拒绝某动作不应阻止无关只读工作。

## 证据与验收

证据按 `SCHEMA_VALID → ARTIFACT_VERIFIED → TOOL_VERIFIED → INTEGRATION_VERIFIED → APPROVAL_VERIFIED` 升级。每级只能由匹配证据获得：文件存在且哈希一致；工具真实执行且目标正确；集成环境和版本符合合同；批准来源可复核。

`PASS` 必须包含用例 ID、输入版本、工具版本、命令参数、退出码、原始日志、预期产物及哈希。退出码 0 但产物缺失、旧日志、错误目标、篡改哈希和空证据均失败。`COMPLETED` 要求全部 required_checks 通过；否则保持 `PARTIAL/BLOCKED/FAILED/NOT_RUN`。

## 恢复、资源与失败处理

恢复时重验包版本、输入锁、HEAD、脏文件、工具版本和约束哈希。已完成操作跳过；可幂等失败项才允许重试；状态不确定的烧录、删除、覆盖、提交和生产动作进入 `NEEDS_REVIEW`。同一文件只允许一个写拥有者。

扫描、文件、日志、并发和超时必须有上限；超过上限应给出已覆盖范围和安全停止原因，不得静默截断后给出完整性结论。宿主未强制所有写路径经过执行器时，隔离能力必须写为 `POLICY_ONLY`。

## 必需输出

路由追踪、任务/输入锁/计划、journal、证据校验结果、状态和 HANDOFF。失败输出必须说明类别、最小复现、已执行检查、可继续事项、恢复条件和下一禁止动作。
