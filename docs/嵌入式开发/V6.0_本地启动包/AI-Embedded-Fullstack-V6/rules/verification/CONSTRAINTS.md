# 测试、验证与缺陷闭环具体约束

## 适用范围与测试合同

每个用例必须包含稳定 ID、需求/风险关联、对象版本、前置条件、环境、工具/仪器及校准状态、刺激、步骤、测量点、阈值/单位/容差、期望结果、超时、清理/恢复和原始证据位置。阈值未知的用例只能形成待执行合同，不能 PASS。

## 测试分层与动作

- 静态/单元：解析器、规则、算法、边界和错误码；使用确定性输入并验证实际输出，不只检查文件存在。
- 集成：驱动、RTOS、协议、存储、网络和模块间状态；覆盖分包粘包、竞争、队列满、超时、掉线、复位和恢复。
- 仿真/HIL：明确模拟了什么、未模拟什么、模型版本和偏差；模拟 PASS 不升级为实机 PASS。
- 实机：记录设备标识、硬件/固件/Bootloader/配置、端口、仪器、连接图、环境和原始采样。
- 可靠性/EMC/安全：依据适用产品标准和批准计划执行；通用规则不伪造限值或认证结论。

测试集至少覆盖正常、边界、空/损坏输入、最大规模、超时、取消、重复执行、并发、断电/重启、旧数据迁移和失败恢复。安全关键功能必须有故障注入及安全状态/时序证据。

## 自动化、数据与资源限制

测试运行固定命令参数、工作目录、工具版本、超时和目标身份；可停止并释放端口/进程/设备。日志和样本设置单文件大小、总量、保存周期和脱敏策略；长日志保留原始文件，对话只给摘要。

随机或时间相关测试记录种子和时钟来源；重试不得掩盖不稳定。Flaky 用例单独标记并调查，不能通过增加无限重试获得 PASS。

## 缺陷与回归闭环

缺陷记录最小复现、输入/版本、预期/实际、原始日志、影响范围和根因证据。修复必须增加能重现原问题的回归用例，先证明失败再证明修复，随后执行受影响回归；不得删除失败用例或降低阈值。

## 验收、证据与失败处理

结果只用 `PASS/FAIL/BLOCKED/NOT_RUN/NOT_APPLICABLE`，且逐用例绑定证据。`NOT_APPLICABLE` 需要适用性理由和责任确认；缺设备/工具/测量为 BLOCKED 或 NOT_RUN。汇总报告保留所有非 PASS，不以通过率掩盖关键失败。

必需证据：原始日志/测量、输入和产物哈希、工具/设备版本、退出码、时间、复现命令及报告。证据缺失、版本不匹配、日志过旧或目标身份错误时拒绝结果。
