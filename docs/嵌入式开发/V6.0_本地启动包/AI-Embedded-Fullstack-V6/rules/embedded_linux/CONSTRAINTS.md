# 嵌入式 Linux、驱动与系统服务具体约束

## 适用范围与输入

适用于 Bootloader/Kernel/rootfs 启动链、设备树、内核驱动、用户态服务、进程/线程、IPC、网络、存储、升级和现场诊断。输入包括板级硬件、SoC/BSP、内核/发行版、工具链、设备树、rootfs 构建、服务管理器、权限模型和目标运行日志。

## 启动链与设备树

记录 ROM→Bootloader→Kernel→init/rootfs→服务的版本、配置、命令行、分区和失败恢复。设备树节点必须与原理图、时钟、GPIO、中断、DMA、regulator、地址和驱动 binding 对应；禁止通过反复延时或屏蔽错误让设备“看起来启动”。

启动故障按电源/Boot ROM、介质/分区、Bootloader、Kernel early log、驱动 probe、rootfs 挂载和服务分层定位。日志绑定当前镜像、DTB 和板卡版本。

## 驱动、并发与用户接口

- 内核驱动遵守内核 API/locking/runtime PM/错误路径；probe/remove、open/close、suspend/resume 和并发访问资源对称释放。
- 中断顶半部保持有界，耗时工作放到底半部/线程；DMA 映射、cache、IOMMU 和生命周期使用目标内核 API。
- sysfs/debugfs/ioctl/netlink 等 ABI 明确单位、范围、权限、兼容版本和输入校验；debugfs 不作为生产稳定 ABI。
- 用户服务处理超时、重启、依赖、资源上限、日志轮转和优雅停止；不得以 root 权限作为默认修复。

## 文件系统、网络与升级

只读/可写分区、持久数据、日志、临时文件和掉电一致性有明确策略。写放大、空间耗尽、文件损坏和只读回退必须测试。网络服务使用最小监听面、权限和凭据；目标/接口/端口来自项目配置。

系统升级绑定 Bootloader、Kernel、DTB、rootfs、应用和配置兼容；支持原子更新、健康确认和回退。容器/包管理依赖锁定版本和来源，不将在线下载作为不可追溯构建步骤。

## 验收、证据与失败处理

必需证据：构建配置、镜像/DTB/rootfs 哈希、启动日志、驱动 probe/错误路径、服务状态、资源/压力/掉电测试和升级回退。主机模拟测试不能替代目标内核/板卡验证。

内核 oops、锁死、泄漏、不可恢复文件系统、权限扩大、升级无回退或版本组合不明时阻止发布。缺目标板时可完成静态配置和主机测试，但目标状态保持 NOT_RUN。
