# 适配器、规则与扩展生态具体约束

## 适用范围与输入

适用于新增芯片、RTOS、IDE、工具链、MAP/固件格式、EDA、通信协议、设备/HIL、分析规则和第三方插件。扩展不得把项目特例写入公共模型，也不得因单个扩展失败破坏核心或其他扩展。

## 扩展清单与契约

扩展清单至少声明稳定 ID、版本、提供者、能力、适用工具/格式/平台版本、权限、输入/输出 schema、资源限制、依赖、测试样本和安全降级。能力状态使用 `AVAILABLE_VERIFIED/AVAILABLE_UNVERIFIED/READ_ONLY/UNAVAILABLE/BLOCKED_BY_AUTH/UNSUPPORTED`。

适配器实现 `probe/supports/plan/execute/collect_evidence/verify_outputs/rollback_plan`。`probe` 必须无副作用；`plan` 不执行动作；`execute` 只接受结构化动作和授权；输出包含工具版本、命令参数、工作目录、超时、退出码和产物。

## 隔离、兼容和故障

扩展输入严格校验，文件和进程作用域限制在用户选择范围。插件不得获得默认网络、设备、凭据或高权限；宿主无法强制隔离时如实标记 POLICY_ONLY。

扩展 API/schema 版本化，升级提供兼容读取或显式迁移；未知新字段安全忽略或拒绝，不能误解析。单个扩展异常、超时、崩溃或无许可证时必须可停止、释放资源并返回结构化错误，不影响核心状态。

解析器保留原始输入、覆盖率、未知项和置信度。检测规则区分确定性、启发式和 AI 建议；扩展不得把启发式结果升级为工具验证事实。

## 测试与发布

每个扩展提供正常、损坏、未知格式、边界大小、超时、取消、重复、并发、兼容旧版本和缺能力样本。至少覆盖一个目标样本和一个非目标/未知样本，防止过拟合单一工程。

发布固定接口/schema、依赖、许可证、样本和兼容矩阵；生成清单与哈希。第三方代码和二进制记录来源，不自动联网下载执行。

## 验收、证据与失败处理

必需证据：清单/schema、能力探针、兼容矩阵、测试样本/结果、权限/资源/取消验证和降级行为。仅有类/入口/说明或 Mock 成功不能认定扩展可用。

扩展输出缺证据、越权、泄漏资源、误识别未知格式或破坏其他扩展时禁止发布；回退到核心通用分析并保留原始数据和明确能力缺口。
