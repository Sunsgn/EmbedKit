# 原理图与电子硬件具体约束

## 适用范围与输入

适用于器件选型、BOM、电源、时钟、复位、保护、数字/模拟/RF 接口和原理图审查。输入包括原生可编辑工程、器件数据手册及版本、BOM/封装库、供电和功耗、接口/电压域、环境与法规目标、结构限制和板级约束。缺关键额定值或封装映射时不得给出可制造结论。

## 强制设计与审查动作

1. 解析所有页、层次连接、网络、电源标志、未连接引脚和全局标签；输出可追溯的器件/Pin/网络表。
2. 逐器件核对型号、生命周期、额定值、容差/降额、封装、引脚编号、极性、替代料和数据手册修订。
3. 电源计算输入范围、稳态/峰值电流、效率、压降、纹波、热耗散、启动/关断时序、反接/浪涌/ESD/过流保护及故障状态。
4. 时钟和复位核对频率/负载、启动裕量、复位阈值与宽度、调试/量产入口和上电默认状态。
5. 数字接口核对逻辑电平、上拉/下拉、驱动能力、终端、隔离和未上电反灌；模拟链路核对量程、源阻抗、参考、噪声、带宽、保护和误差预算。
6. RF/高压/安全相关设计必须加载专属约束和适用标准，未知净距、材料或认证条件时列为阻塞项，不编造限值。

## 原理图与库要求

- 符号、封装和 3D/机械信息具有稳定库来源和版本；禁止仅凭名称假定 Pin 映射正确。
- 关键电源、地、模拟参考、差分对和安全网络使用明确网络名；跨页连接可追踪。
- 测试点、编程/调试、产测和故障隔离需求进入原理图，不在 PCB 阶段临时猜测。
- 硬件接口变更必须输出对软件 Pinmux、驱动、电压、时序、生产和现场兼容的影响。

## 工具执行与验证

先探测 EDA 版本、许可证、脚本/API 和原生格式支持。真实运行 ERC，并区分错误、警告、已审查例外；修改后重新打开原生工程、复跑 ERC 并审查差异。AD19 或 KiCad 能力必须以当前安装版本实测，不能从新版文档外推。

静态审查不能替代仿真、样机、示波器/电源测量、EMC 或可靠性验证。缺工具时可交付带证据的审查报告，但 ERC 状态为 `NOT_RUN/UNAVAILABLE`。

## 验收、证据与失败处理

必需证据：原生工程/库/BOM 哈希、数据手册来源、计算依据、ERC 原始报告、差异和未关闭问题。网络冲突、封装/Pin 不确定、电压域冲突或安全阈值未知时停止设计放行；允许继续不依赖该缺口的只读核对。任何人工 waiver 必须记录责任人、理由、范围和版本，AI 不得自行关闭。
