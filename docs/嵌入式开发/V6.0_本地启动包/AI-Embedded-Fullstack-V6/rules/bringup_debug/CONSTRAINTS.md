# 板级 Bring-up、底层调试与故障定位具体约束

## 适用范围与输入

适用于首次上电、板卡启动、时钟/复位/GPIO/中断/DMA、I²C/SPI/UART/CAN 外设验证、下载调试、崩溃和现场日志定位。输入包括原理图/PCB 版本、BOM、供电限制、板级配置、固件/Bootloader、调试器/仪器能力、连接方式和安全边界。

## 上电与基础验证顺序

1. 上电前目检极性、焊接、短路和连接器方向，断电测量关键电源对地阻抗；不明短路不得直接加电。
2. 使用限流电源，从项目批准的电压/限流开始；记录静态/启动电流和各电源轨，不得在通用规则中猜数值。
3. 依次验证主电源、时钟、复位、调试接口、Boot/下载、最小固件，再启用外设和高功率负载。异常时回到最近验证层，禁止同时改多个变量。
4. 每次测试绑定板卡序列号、硬件/BOM、固件哈希、探针/仪器、连接图和原始波形/日志。

## 底层外设与实时调试

- GPIO：核对 Pinmux、方向、上下拉、有效电平、复位默认状态、驱动能力及外部冲突；输出切换先保证负载安全。
- 时钟/复位：测量实际频率、幅度和启动时间；核对 PLL/分频、复位源、棕断和看门狗原因。
- 中断/DMA：检查向量、优先级、清标志、事件计数、缓冲所有权、溢出和缓存一致性；使用计数/时间戳而非大量 ISR 日志。
- I²C/SPI/UART/CAN：先验证电气电平/上拉/终端/模式/速率，再验证帧、时序、错误和恢复；逻辑分析/示波器证据与软件日志对齐。

## 故障定位方法

先冻结可复现输入和版本，再按电源→时钟/复位→CPU/启动→内存→外设→协议→应用层缩小。使用二分、最小固件、故障寄存器、堆栈、地址到符号和前后版本差异。不得通过关闭安全功能、无限延时或大范围重构掩盖根因。

调试命令、端口和设备动作需要明确目标授权。崩溃保留复位原因、寄存器、栈、任务、日志窗口和 ELF/MAP 身份；旧符号文件不能用于当前地址解释。

## 验收、证据与失败处理

Bring-up 结论按层级记录：未上电、供电验证、时钟复位验证、调试连接、最小启动、外设验证、系统运行。高层通过不能反推低层未测项。

缺仪器、板卡、授权或安全条件时标记 BLOCKED。出现过流、过热、异常气味、错误电压或安全执行器未知状态时立即停止受影响硬件动作并断开安全电源；保存现场状态后再分析。
