# 板级 Bring-up、底层调试与故障定位详细约束

## 适用范围与安全准备

适用于新板首次上电、电源/时钟/复位、调试口、GPIO/中断/DMA、总线、启动失败和崩溃定位。开始前锁定原理图/PCB/BOM/返修状态、板号、供电要求、限流值来源、测试点、仪器接地和已知风险。高压、射频功放、电机、加热或燃气执行器必须隔离/禁用并取得授权。

## 首次上电顺序

- 断电检查短路、极性、关键阻值、焊接/错件和电源到地阻抗；阻抗读数需考虑电容充电，禁止单次蜂鸣判断。
- 使用限流电源，从项目批准电压/限流开始；记录输入电压、电流、波形和异常温升。通用规则不提供默认限流值。
- 按电源树顺序测每路稳态、纹波、启动/掉电、Power Good 和时序；仪器带宽、探头接法和测点影响要记录。
- 任一路过流、反向、振荡、异常热或电压超额立即断电并隔离，不得反复上电“观察是否恢复”。

## 时钟、复位、Boot 与调试口

- 测量主/低速时钟频率、幅度、启动时间和稳定性；使用适合的低负载探头，避免探头使晶振停振或误判。
- 同时观察电源、复位和时钟，确认阈值/脉宽/顺序；复位脚高并不证明内核已运行。
- 核对 Boot Strap 的上电采样电平及外部器件影响；调试连接前确认接口电压、地、方向、频率和安全访问状态。
- 从读取器件 ID/核状态、停止位置、向量表、SP/PC、复位原因逐步定位；不得一开始全片擦除或改保护位。

## 最小固件与逐级启用

- 使用与目标芯片/板卡匹配的最小可审查固件，只启用时钟、一个安全 GPIO 或调试输出；记录源码、链接地址和固件哈希。
- 建立已知好检查点后依次启用内存、定时器、中断、单个外设、DMA、总线和应用；一次只加入一个可观察变量。
- GPIO 翻转验证同时检查寄存器配置和引脚波形；禁止仅凭软件读回判断物理 Pin 正确。
- 每步定义成功、停止条件和回退；失败回到最近已知好状态，不通过大范围初始化/延时试错。

## GPIO、中断、DMA 与总线调试

- Pinmux 对照原理图、封装 Pin 和配置；先确认电压/外部驱动，防止两个输出争用。
- 中断验证源状态、使能、优先级、向量、触发、清除顺序、ISR 计数和时延；中断风暴时先禁用源并保存状态。
- DMA 验证请求映射、地址、长度、对齐、Cache、完成/错误标志和缓冲所有权；数据不一致时比较 CPU 与总线视角。
- I²C/SPI/UART/CAN 用示波器/逻辑分析仪核对物理幅度、速率、时序/模式和帧；软件日志只能作为关联证据。
- 总线卡死、bus-off、NACK、溢出和噪声恢复需实际触发；不得用正常收发替代异常恢复验证。

## 启动失败、HardFault 与异常定位

- 保留复位原因、故障寄存器、SP/PC/LR、异常栈、关键内存和启动阶段标记；任何复位前先尽可能保存最小证据。
- 地址解析必须使用该设备实际固件同哈希的 ELF/MAP，记录加载基址和优化；不同构建的符号不能用于确定结论。
- 区分取指/数据总线、对齐、权限、栈溢出、看门狗、棕断和显式复位；不要把所有复位归为“程序跑飞”。
- 对间歇问题增加有限计数器、阶段 GPIO/trace 或保留 RAM，而非用大量日志改变时序。

## 故障隔离方法

- 建立假设表：现象、可能层级、支持/反对证据、下一最小区分实验。每次只改变板卡、固件、配置、供电、线缆或工装之一。
- 交叉替换必须记录板号/版本，防止“好板/坏板”标签代替数据；返修板明确改动和复测范围。
- 禁止在无原理图依据时改电阻、电容、引脚、时钟、启动延时或保护；临时飞线/拆件必须有照片/记录和恢复状态。
- 环境/仪器问题与产品问题分开，探头接地、带宽、采样率和触发条件纳入证据。

## 自动化、长期监控与资源恢复

- 自动脚本探测端口/设备身份，超时可停止并释放串口、调试器和仪器；禁止默认选择“第一个设备”。
- 下载/复位是有副作用操作，需授权并记录镜像、地址、工具、设备及结果；读回/版本握手确认实际运行镜像。
- 监控设置日志轮转、心跳、异常触发和原始数据保留；无输出区分设备停机、链路断开和采集程序失败。

## 验收、证据与失败门禁

证据包括板卡/BOM/返修身份、供电限值来源、仪器设置、上电和时序波形、最小固件哈希、逐级检查点、总线捕获、异常寄存器和同哈希符号解析。无真实板/仪器时只能 `PLAN_ONLY/NOT_RUN`；过流、错误电压域、复位/时钟不稳定或固件身份不明时禁止继续高层功能验证。
