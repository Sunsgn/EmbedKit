# 安全、功能安全与发布详细约束

## 适用范围、资产与权威边界

适用于信息安全、危险控制、密钥、调试口、升级、数据保护、发布和现场处置。先识别资产、人员/设备危害、攻击面、信任边界、法规/安全等级、责任人和可接受风险；通用规则不得编造安全阈值或代替认证判断。

## 威胁、危害与安全需求

- 对物理端口、无线/网络、协议、固件、供应链、制造、维护、云端和数据导出建立威胁模型，记录攻击者能力、入口、影响和缓解。
- 对传感、执行器、电源、通信、软件和人员操作进行危害/故障分析；安全状态、最大响应时间和独立保护来自批准需求。
- 安全需求有稳定 ID、实现和验证追踪；“使用加密”“有看门狗”不是完整需求，必须明确算法/密钥/身份/失败行为或监测覆盖。
- 安全与可维护性冲突必须形成决策和受控恢复路径，禁止永久后门或通用主密钥。

## 身份、权限与命令授权

- 默认拒绝和最小权限；设备、用户、服务、工装和固件身份分别认证，不能只凭可伪造名称/MAC/端口。
- 每个敏感命令检查认证、授权范围、目标状态、防重放、速率限制和审计；解析成功不等于允许执行。
- 会话有建立、过期、撤销和重连语义；权限变化立即生效。失败响应避免泄漏密钥、内部路径或可利用状态。
- 本地调试/产测能力在发布配置禁用或受强认证；开发命令、测试密钥和临时账户不得进入正式镜像。

## 密钥、凭据与加密

- 定义密钥类型、生成、注入、存储、使用、轮换、撤销、备份和销毁；私钥不得出现在源码、普通日志、测试报告或公共包。
- 算法、长度、模式、随机数和证书验证遵循项目批准策略及目标平台能力；禁止自制密码算法或固定 IV/nonce。
- 随机源需有平台依据和失败处理；设备唯一密钥不能由公开序列号直接推导。
- 安全比较、认证后解密、错误处理和敏感缓冲清理按库接口执行；CRC/哈希不能替代消息认证或签名。

## 输入、协议与内存安全

- 所有外部长度、索引、计数、地址、版本和状态在使用前验证；整数溢出检查先于分配/拷贝。
- 解析器有帧/文件/嵌套/对象/时间上限，处理截断、重复、未知字段和资源耗尽；坏输入不得导致越界、永久阻塞或日志洪泛。
- 禁止将网络/文件参数直接用于 Shell、路径或任意内存/寄存器访问；路径规范化后限制在授权根。
- 错误信息最小化但保留审计关联；敏感数据在 UI、导出、崩溃转储和遥测中脱敏。

## 安全启动、升级与回退

- 从不可变/受保护根信任验证 Bootloader、应用和配置，明确每级验证对象、密钥和失败安全状态。
- 镜像验证产品/硬件、版本、长度、哈希和签名；在认证完成前不得执行。防回滚策略及授权恢复必须可测试。
- 更新抗断电且保留最后可启动版本；确认新版本健康前不能永久提交。错误签名、目标、截断和确认前复位均需拒绝/回退。
- 密钥撤销和签名算法迁移考虑已部署设备；测试密钥通过不能证明生产密钥流程。

## 功能安全与危险输出

- 危险执行器采用明确安全状态、互锁、命令超时、故障检测和独立保护；通信丢失或软件卡死不得保持无限危险输出。
- 安全相关输入执行合理性、范围、变化率和交叉检查；传感器短路/开路/冻结与真实危险条件区分。
- 看门狗、诊断和冗余必须证明覆盖目标故障；同源数据、同一电源或同一软件缺陷不能被误称独立冗余。
- 真实燃气、高压、运动、加热等设备操作需专门授权、物理隔离、急停和人员责任，缺条件只能做安全模拟并标明边界。

## 漏洞、依赖与发布门禁

- 维护依赖/工具链/组件清单及版本来源，扫描已知漏洞、许可证和供应链完整性；发现项按适用性、可利用性和缓解记录，不得仅按扫描数量判断。
- 发布从干净、受控基线可复现构建，产物签名/哈希、SBOM、配置、迁移、回退和发布说明绑定同一版本。
- 发布前关闭必需测试、威胁/风险缓解和高严重缺陷；例外必须有责任人、范围、到期和补救。AI 不得自行批准风险或正式发布。
- 泄露响应包括撤销、轮换、通知、受影响版本识别和现场升级；不得删除审计证据掩盖事件。

## 验收、证据与失败门禁

证据包括资产/威胁/危害模型、安全需求追踪、权限矩阵、密钥流程、安全启动/升级测试、模糊/负向测试、SBOM/漏洞评估、发布产物哈希和批准。硬编码秘密、未认证危险命令、无界解析、错误镜像可启动、独立保护未验证或高风险无批准时禁止发布。
