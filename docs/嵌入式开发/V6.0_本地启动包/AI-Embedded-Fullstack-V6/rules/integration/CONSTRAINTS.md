# 软硬件协同与系统接口具体约束

## 适用范围与接口模型

适用于 Pinmux、GPIO、总线、ADC/PWM、时钟/复位、功耗、传感/执行器、协议、硬件/固件版本和跨专业状态机。每个接口记录稳定 ID、信号/网络、硬件 Pin、软件驱动、方向、电压、有效电平、上电默认值、时序、单位/精度、所有者、版本、来源和测试用例。

## 强制动作

1. 建立“需求 → 系统接口 → 硬件网络/器件 → MCU Pin/外设 → BSP/驱动 → 任务/状态机 → 测试”的双向追踪。
2. Pinmux 或硬件版本变化时同时检查原理图、PCB 网络、板级配置、驱动初始化、中断/DMA、测试夹具和生产配置。
3. 通信接口核对电平、速率、帧格式、端接、超时、复位/掉线和版本兼容；模拟接口核对量程、参考、误差、校准、滤波和单位转换。
4. 建立启动/关断/复位/休眠/唤醒时序，列明硬件稳定条件与软件等待依据；不得用任意 sleep 掩盖竞态。
5. 功耗、热、精度和时序预算列出每个贡献项、最坏值、单位、计算方法、裕量和缺失数据。缺数据输出 `UNKNOWN`，不能只给通用建议。

## 状态、故障与版本

- 用显式状态/事件描述正常、降级、恢复和安全状态；网络或云端失效不得破坏本地安全行为。
- 故障包括断线、短路/开路、越界输入、总线卡死、模块复位、看门狗、掉电和版本不兼容；明确检测、超时、隔离、恢复和可观测证据。
- 硬件、BOM、固件、Bootloader、协议、NVM/标定和产测配置建立兼容矩阵。矩阵缺失或状态非 `VERIFIED_COMPATIBLE` 时禁止混版放行。

## 验收、证据与失败处理

必需证据：接口契约、双向映射、变化 diff、预算表、兼容矩阵、跨域测试和未决冲突。只有字段齐全且无重复 Pin/资源冲突才可通过静态映射；实际电气、时序和故障行为仍需工具/设备证据。

来源冲突、单位不一致、接口一端缺失、安全默认值未知或版本组合未验证时，阻止相应集成/发布，继续可独立完成的专业分析。任何跨域变更必须在硬件和软件两侧都有明确责任与回归项。
