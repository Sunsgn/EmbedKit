# 目录框架适用与裁剪规则

`项目目录框架_V1.20.md`是完整权威目录基线，不是要求所有任务创建全部目录。

该基线原文保持不改，SHA-256为`096280d215cd0b07ba5e8c03ee27f62a69d59e07106235fc95b9c7a00749e371`。原文中的旧约束包路径按本版结构映射：`.ai/PROJECT_PROFILE.md`对应`project/PROJECT_PROFILE.md`，`.ai/工程规则/`对应`rules/`与`disciplines/`，`.ai/项目目录框架.md`对应本目录中的完整V1.20文件。此映射只解决规范包版本差异，不改变项目自身已有`.ai/`目录。

## 新项目

根据已启用专业创建最小目录集合；未启用专业可暂不创建。启用完整研发交付时再补齐系统、软件、硬件、测试、生产、发布和归档目录。空目录不得伪装成已完成能力。

## 已有项目

不得为了形式一致强制重排现有工程。先建立`现有目录 → V1.20职责`映射；只在职责缺失、名称冲突、证据不可追溯或用户明确要求时迁移。迁移必须有备份、映射、引用更新、验证和回退。

## 裁剪原则

- 同一资料只设一个权威位置，其他位置用索引或链接。
- 构建产物、缓存、依赖下载、日志和大文件按V1.20边界管理，不得进入普通源码历史。
- 专业独立使用时仍保留版本、证据、任务和交付的最小可追溯目录。
- 项目另有成熟目录规范时保留原结构，并用映射证明职责覆盖。
