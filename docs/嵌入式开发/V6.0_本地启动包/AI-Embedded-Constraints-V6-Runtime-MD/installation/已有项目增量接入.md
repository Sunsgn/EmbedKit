# 已有项目增量接入

## 禁止直接覆盖

已有`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、Copilot说明、`.ai/`、项目规范或同名Profile时，必须先读取、备份并逐项合并。不得以本包版本更新为由删除项目已有约束。

## 接入步骤

1. 只读盘点现有AI入口、目录、局部规则、Git状态和用户改动。
2. 对照`MANIFEST.md`生成冲突清单，记录每个同名文件的所有者和处理决定。
3. 保存待修改入口的可恢复副本或Git检查点。
4. 将`rules/`、`disciplines/`、`workflows/`、`templates/`、`installation/`放入不冲突位置；若更改位置，同步入口链接。
5. 合并根入口：保留原项目规则，增加对本规范`AGENTS.md`加载逻辑；冲突按效力规则显式解决。
6. 建立V1.20职责到现有目录的映射，不强制搬迁成熟工程。
7. 选择专业并填写当前任务最低事实；原有项目事实优先保留来源和版本。
8. 用只读试运行验证AI能找到源码、构建、EDA、测试和局部约束。
9. 检查差异，确认没有覆盖业务文件或改变构建行为，再创建接入检查点。

## 合并门禁

存在无法判断的入口冲突、安全规则弱化、同名文件所有权不明或不可恢复覆盖时停止接入并请求用户决定。
