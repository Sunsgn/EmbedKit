# 软硬件协同分析规范

本规范定义软件、原理图、PCB、固件配置和真实设备之间的接口契约及联合定位方法。它可以独立用于接口审核；只有任务实际涉及跨专业影响时才启用。

## 1. 统一接口契约

每个接口至少记录：稳定接口ID、功能、原理图网络、连接器与Pin、处理器引脚、复用功能、电压域、方向、驱动类型、上电/复位/低功耗状态、有效电平、时钟或速率、时序、单位与比例、软件符号、异常状态、硬件保护、验证方法及适用软硬件版本。

接口契约必须双向核对：从原理图网络找到软件配置，也能从软件Pin、外设实例和通道反查原理图与PCB位置。显示名称不同不能代替稳定ID映射。

## 2. 强制协同检查

- 时钟源、频率、容差和软件时钟树一致；PLL、分频和外设频率有计算证据。
- GPIO复用、方向、上下拉、驱动能力、默认电平和外部电路一致，不产生上电毛刺或争用。
- 中断有效电平、触发边沿、保持时间、去抖和清除顺序与器件行为一致。
- DMA通道、外设请求、缓冲区、Cache一致性和数据宽度与硬件数据流匹配。
- ADC参考、分压、保护、源阻抗、采样时间、分辨率、比例和单位一致。
- PWM频率、极性、死区、安全关断和功率级能力一致。
- I²C/SPI/UART/CAN/USB/Ethernet的电气拓扑、速率、端接、地址、模式、帧和超时一致。
- Boot模式、调试口、Bootloader、分区、升级和回滚与硬件启动配置一致。
- 上电、掉电、复位、Brown-out、看门狗和低功耗状态下软硬件均进入已定义安全状态。

## 3. 联合故障定位

1. 固定源码、固件、硬件、设备和配置版本。
2. 用可重复步骤复现，保存日志、总线帧、寄存器、波形和电源数据。
3. 建立从需求到软件调用、寄存器、引脚、网络、器件和测量点的因果链。
4. 通过单变量实验区分软件逻辑、配置、时序、电气、布局、器件、装配和环境问题。
5. 假设必须给出支持证据、反证条件和下一项最低成本验证；不得把时间相关性直接当因果。
6. 整改同时检查另一专业是否需要变更，并执行接口级和系统级回归。

## 4. 变更传播

任何引脚、网络、电压、时钟、极性、地址、比例、数据格式、时序、功耗状态、分区或安全状态变更，必须更新接口契约、相关源码/原理图/PCB、测试用例和兼容矩阵。只改单侧不得关闭问题。

## 5. 输出与完成条件

协同报告必须指向软件文件及符号、原理图页及网络、PCB位置或层、设备和原始证据。只有接口矩阵无未解决冲突、关键假设经真实证据验证、整改完成且受影响回归通过时才能`PASS`。无法上板时最多给出静态一致性结论，并保留`NOT_RUN`设备验证项。
