# 安全、合规与发布规范

本专业可独立用于产品安全分析、法规适用判断和发布审查。AI可以整理证据和发现缺口，但不得自行作法律结论、认证结论或风险接受决定。

- 建立资产、信任边界、攻击面、威胁、滥用场景、危害、缓解、残余风险和验证的追溯链。
- 身份、密钥、调试口、安全启动、固件签名、防回滚、更新、通信认证、权限和日志按产品生命周期设计；CRC不能证明来源可信。
- 密钥和凭据不得进入源码、普通日志、测试截图或交付包；生成、注入、轮换、吊销、备份和销毁均需授权与审计。
- 外部输入、文件、网络目标、进程参数和更新包执行严格校验；失败进入可恢复安全状态，不泄漏敏感信息。
- 适用标准和法规记录地区、产品类别、版本、范围、证据负责人和实验室/认证状态；预扫通过不等于正式认证。
- 发布前核对SBOM或依赖清单、已知漏洞、许可证、签名、兼容矩阵、回滚、支持期限和安全公告流程。
- 安全或合规豁免必须有批准人、期限、适用版本、补偿措施和关闭计划；AI不得自签。
