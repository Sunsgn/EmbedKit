# 测试与问题整改工作流

1. 将需求转换为可测量验收条件，锁定DUT、固件、配置、测试程序、仪器和环境。
2. 设计正常、异常、边界、恢复、压力和兼容用例；注明前置条件、步骤、预期、停止及清理。
3. 执行前检查接线、安全、仪器量程和校准；为每次运行分配唯一ID。
4. 保存未经筛选的原始日志、帧、波形和测量值，记录时间及版本。
5. 失败时先固化复现条件，不得通过删测试、放宽阈值或无限加超时使结果变绿。
6. 建立缺陷，区分软件、硬件、协同、装配、环境和测试系统根因。
7. 整改后先执行原失败用例，再执行受影响回归；记录修改提交与复测运行ID。
8. 所有结论按统一状态输出，未执行真实设备验证不得写PASS。
