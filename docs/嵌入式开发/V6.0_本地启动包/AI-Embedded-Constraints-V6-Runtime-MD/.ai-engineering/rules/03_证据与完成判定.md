# 证据与完成判定

## 1. 证据身份

证据必须能关联当前源码提交或文件哈希、固件版本、硬件版本、设备标识、配置、工具及版本、输入、执行时间和执行者。身份不匹配的旧结果只能作为参考。

## 2. 有效证据

按任务可包括：源码位置、编译与链接输出、静态分析、ELF/MAP、EDA源文件、ERC/DRC、网表、Gerber独立回读、设备日志、串口或总线原始帧、仪器原始数据、照片及测试报告。截图只能辅助定位，不能替代可解析原始数据和版本信息。

## 3. 结论分级

- `PASS`：验收条件全部满足，证据与当前对象匹配。
- `FAIL`：已执行且至少一项不满足。
- `BLOCKED`：缺少决定性输入、依赖或外部状态。
- `BLOCKED_BY_AUTH`：需要额外授权。
- `NOT_RUN`：具备条件但未执行。
- `UNAVAILABLE`：当前环境无相应工具、硬件或接口。
- `NOT_APPLICABLE`：有理由和证据证明不适用。

## 4. 禁止伪证据

文件存在、命令退出零、AI自述、Mock、预期结果、旧日志或单一样例不得单独证明真实通过。静态推测、仿真、台架和真实设备结果必须分开标记。

## 5. 完成门禁

功能实现、正常与失败路径、状态或数据兼容、定向测试、受影响回归、证据、使用边界和回退方法缺一不可。无真实条件时可以完成分析或实现，但交付状态必须保留未执行验证项，不能升级为最终验收通过。
