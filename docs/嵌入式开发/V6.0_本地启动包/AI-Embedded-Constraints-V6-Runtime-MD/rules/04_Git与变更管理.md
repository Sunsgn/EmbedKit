# Git与变更管理

1. 修改前检查工作区、分支、已有改动和忽略文件；用户改动默认保留。
2. 禁止使用整体回退命令覆盖工作区，禁止夹带无关文件、日志、缓存、下载和构建产物。
3. 每个检查点目标单一，提交前检查差异、暂存清单和敏感信息。
4. 受影响测试通过后方可创建检查点；不能安全拆分时报告原因，不擅自提交。
5. 提交信息应说明专业、对象和目的，例如`fix(software): handle uart receive timeout`。
6. Git提交不等于备份外部设备、EDA库、生产数据或未纳入版本控制的资料；这些内容按项目备份规则处理。
7. 推送、合并、打标签和正式发布需要用户授权或既有明确流程。
