# 软件任务工作流

1. 明确需求、目标平台、验收条件和禁止变更范围。
2. 检查工作区、局部约束和现有入口，填写当前任务最低软件事实。
3. 定位启动、调用、任务/事件/中断、数据流、硬件依赖和构建配置。
4. 分析接口、时序、并发、内存、功耗、持久化及兼容影响。
5. 在`work/<task-id>/TASK_PLAN.md`记录步骤、风险和验证方法。
6. 实施最小修改，不删除已有能力或掩盖失败。
7. 执行格式/编译/静态检查和受影响单元测试。
8. 按风险执行仿真、集成或目标板验证；不能执行时保留`NOT_RUN`。
9. 对失败定位根因后整改，增加回归用例并重新验证。
10. 复核差异、资源变化、证据和回退方法，创建可回退检查点或说明未提交原因。

退出条件：当前范围验收满足；失败路径经过验证；证据与当前源码/固件匹配；未验证项和硬件边界已明确。
