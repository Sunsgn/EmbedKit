# 构建系统、工具链与固件产物详细约束

## BUILD-001：适用范围与原工程优先

适用于 Keil/IAR/厂商 IDE、GCC/Clang、CMake/Make/Ninja、链接、ELF/MAP/BIN/HEX、签名和产物诊断。先识别原工程入口、目标、配置和工具版本；不得为方便分析而擅自替换正式编译器、链接脚本或构建系统。

## BUILD-002：构建入口与依赖识别

- 枚举工程/工作区、目标、Debug/Release、芯片/板卡变体、预处理宏、包含目录、库、链接脚本、后处理和输出。
- 记录编译器/汇编器/链接器/转换器版本、许可证和环境脚本；仅命令名相同不能证明工具链一致。
- 分析生成代码、子模块、包管理、SDK 和预编译库的来源/哈希；缺失依赖保持 `BLOCKED`，不得用不兼容版本顶替。
- IDE 工程优先解析自身配置；CMake/Make/Ninja 只在工程已有或明确作为适配层时使用，不能宣称等价正式构建。

## BUILD-003：可复现与隔离构建

- 构建前记录提交/工作区 diff、目标、环境和时间；输出进入独立目录，禁止混用旧目标或旧配置产物。
- 命令参数化执行并捕获完整日志、退出码和耗时；构建超时须终止子进程树并标基础设施/产品状态。
- 时间戳、绝对路径、随机构建 ID 和未固定归档顺序等非确定输入需识别；可复现比较先规范允许差异，再比较哈希/段内容。
- 增量构建通过不能替代必要的干净构建；清理命令只针对已验证的输出目录，禁止删除源码或用户文件。

## BUILD-004：编译、链接与警告

- 编译错误保留首个根因和后续摘要；禁止通过全局关警告、降级语言规则或删除模块变绿。
- 警告按工具版本和类别管理；新增抑制必须局部且有理由/测试。Release 与 Debug 的优化、断言、日志和安全配置分别检查。
- 链接核对入口、向量表、内存区、对齐、堆/栈、未解析/弱符号、重复节、垃圾回收和库顺序。
- 地址/尺寸必须与目标存储器和 Bootloader 分区比较；链接成功但越过真实分区仍 FAIL。

## BUILD-005：ELF 与 MAP 分析

- 解析 ELF 头的架构、端序、ABI、入口、段/节、符号和调试信息；工具必须支持该格式，解析失败不得静默降级为零大小。
- MAP 解析器按工具链/版本适配，保留未知行；禁止用 GCC 格式规则解释 Keil/IAR 后给出确定结论。
- 统计 Flash/ROM、RAM、data/bss/noinit、堆、栈、填充和按模块/符号增量；明确 VMA/LMA、加载与运行大小，防止重复计数。
- 比较必须使用相同目标/配置/链接规则；输出最大增长符号、来源对象和段变化，不只给总大小。

## BUILD-006：BIN、HEX 与镜像边界

- Intel HEX/S-record 校验记录类型、地址扩展、长度、校验和、重叠、空洞和 EOF；坏记录立即 FAIL，不得尽力拼接成“可烧录”。
- BIN 必须结合基址/分区/长度来源解释；裸文件无地址时不得猜测加载地址。
- 转换 ELF→BIN/HEX 记录工具/参数，核对段选择、填充、基址、大小和哈希；转换成功不证明目标兼容。
- 合并 Bootloader/应用/配置前验证区间无重叠、空洞填充值和各组件身份；禁止用文件拼接代替地址感知合并。

## BUILD-007：固件身份、签名与发布

- 产物元数据关联产品、硬件、目标、版本、提交、工具链、配置和构建 ID；元数据不能修改后不重新计算签名/哈希。
- 签名私钥不进入源码/日志/交付包；签名步骤验证输入哈希和目标，测试签名与生产签名明确区分。
- 发布清单包含所有产物大小/哈希、加载地址、用途和兼容矩阵；文件名不是身份依据。

## BUILD-008：诊断与崩溃地址映射

- PC/LR/地址必须使用运行固件同哈希的 ELF/MAP、正确加载基址和架构模式解析；内联/优化导致的不确定性需标注。
- 反汇编、符号、源码行和调用上下文交叉验证；单一最近符号不能证明根因。
- 固件差异支持段、符号、元数据和字节比较，区分预期版本/签名差异和非预期代码/配置变化。

## BUILD-009：验收、证据与失败门禁

证据包括原工程配置、工具版本、命令/环境、日志/退出码、当前产物清单和哈希、ELF/MAP 资源报告、转换/合并校验及可复现比较。旧 output、仅退出零、模拟编译或另一工具链不能证明正式目标 PASS；缺许可证/工具/依赖标 `UNAVAILABLE/BLOCKED`。
