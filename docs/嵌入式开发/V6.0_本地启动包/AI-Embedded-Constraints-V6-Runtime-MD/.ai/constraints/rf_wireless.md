# RF、无线连接与射频认证详细约束

## RF-001：适用范围与射频基线

适用于 BLE、Wi-Fi、蜂窝、Sub-GHz、GNSS、UWB、专有无线、天线和射频前端。开始前取得频段/区域、协议版本、射频芯片/模组、天线、匹配、层叠、外壳、供电、发射功率、法规和共存目标；禁止把开发板或参考设计性能直接外推成品。

- 区分认证模组与离散射频设计，明确可继承认证的条件和产品仍需执行的测试。
- 频率、信道、带宽、调制、功率和占空限制按目标销售区域和适用标准配置。
- 软件、硬件、天线、外壳和认证版本必须绑定，任一变化执行影响分析。

## RF-002：原理图、匹配与参考设计

- RF 供电、去耦、时钟、晶体、PA/LNA、开关、滤波、巴伦和匹配网络按当前器件资料审查。
- 元件值、封装、自谐振、Q、额定功率和容差匹配工作频段；DNP/调试位保留工程依据。
- 50 欧姆端口只是系统边界，芯片差分/复数阻抗不得未经网络转换直接连接。
- ESD 保护的寄生和钳位能力同时满足 RF 与抗扰要求，不能只选低电容或高防护单一指标。

## RF-003：PCB、天线与结构协同

- 受控阻抗、参考层、回流过孔、走线长度/转角、连接器和测试点按层叠与板厂能力实现。
- 天线净空、地开窗、边缘距离、馈点、匹配器件和禁布来自天线/模组要求；禁止在净空放铜、线束、电池或金属结构。
- 外壳材料、涂层、屏蔽、显示、电池、线束和人体使用姿态纳入天线调试；裸板结果不能证明整机性能。
- 多天线的隔离、极化、间距、MIMO/diversity 和切换策略通过测量验证。

## RF-004：协议栈、连接与资源

- 无线栈、控制器、主机、固件和认证配置版本明确；使用厂商 API 时核对线程/回调上下文、缓冲和事件生命周期。
- 配对、鉴权、重连、漫游、掉线、地址变化和密钥删除有集中状态机与超时，禁止无限扫描/重连耗尽电量。
- 广播/扫描/连接间隔、发射功率和数据率来自产品需求及法规，不用“最大功率”作为默认可靠性方案。
- 缓冲、吞吐、共存和电源模式相互影响时，建立可测预算和降级策略。

## RF-005：共存、干扰与抗扰

- 识别同机无线、开关电源、数字时钟、显示、USB、线束和外部发射源的频谱/时序冲突。
- Wi-Fi/BLE/蜂窝等共享天线或频段时，明确硬件仲裁、软件共存、优先级和最坏业务场景。
- 测试阻塞、去敏、互调、谐波、杂散和接收灵敏度，不能只测试近距离能连接。
- 干扰下验证重连、吞吐、时延、功耗和本地安全功能，禁止通过无限重试掩盖射频问题。

## RF-006：射频测量与性能验证

- 记录暗室/屏蔽箱、线缆、衰减、校准、端口、固件、信道、功率和环境；传导、辐射和 OTA 结果明确区分。
- 发送测试覆盖功率、频偏、EVM/调制、占用带宽、谐波和杂散；接收覆盖灵敏度、PER/BER、阻塞和选择性中的适用项。
- 天线测试覆盖回波损耗/驻波、效率、增益、方向图和典型使用姿态；单点 S11 好不代表 OTA 良好。
- 所有结果保留原始仪器文件和限值来源，截图只能作为辅助。

## RF-007：法规、区域配置与生产

- 认证计划明确目标区域、标准、产品类别、模组继承、天线限制、标签和软件锁定要求。
- 区域、信道、功率和 DFS/LBT 等配置必须受控，用户/远程命令不得绕过法规限制。
- 量产执行必要的晶振/功率/频偏校准和抽检，校准设备、系数、温度和固件可追溯。
- RF 参数、认证固件和测试模式受到权限保护，发布镜像不得暴露无认证连续发射入口。
- 国家/地区切换不能只依赖用户可编辑字符串；区域来源、首次配置、漫游、恢复出厂和离线行为必须有受控策略与审计。
- 模组固件、无线协议栈、天线供应商或外壳材料变化后，必须依据认证条件和最差性能重新确定传导、辐射与 OTA 的复测范围。

## RF-008：证据、验收与失败门禁

证据包括射频/区域需求、原理图和 PCB 核对、层叠/阻抗、天线/结构版本、协议栈配置、传导/辐射/OTA 原始数据、共存测试和认证报告。开发板通信、RSSI 截图或模组证书不能单独证明整机合规；频段/功率来源未知、天线条件超认证范围或关键杂散/灵敏度失败时禁止发布。
