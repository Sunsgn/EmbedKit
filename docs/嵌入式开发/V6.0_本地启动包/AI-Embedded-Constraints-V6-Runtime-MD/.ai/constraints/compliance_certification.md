# 法规、安规、行业标准与认证详细约束

## CERT-001：适用范围与法规识别

适用于安规、EMC、无线、环保、网络安全、功能安全和行业准入。开始前明确销售国家/地区、产品类别、使用环境、供电/安装、用户群、无线频段和安全影响，由合格责任人确认适用标准及版本；AI 不得自行作法律结论或签署符合性。

- 建立法规/标准清单，记录标准号、版本、适用条款、产品范围、责任人和证据。
- 区分强制认证、自我声明、客户/行业要求和内部目标，不得混为同一放行等级。
- 标准冲突或地区差异必须形成产品变体/受控配置，不能默认采用最熟悉地区规则。

## CERT-002：符合性矩阵与需求分解

- 将适用条款转为稳定 ID 的设计、文档、测试、标签、生产和现场要求，并追踪到实现和证据。
- 对不适用条款记录产品事实和判断责任人，禁止仅填 `N/A`。
- 标准中的测试等级、距离、材料、温度、样本和判据保留单位、条件和版本，不转写成脱离上下文的通用数值。
- 设计变化必须通过符合性矩阵评估是否需要局部/完整重测或认证机构沟通。

## CERT-003：安规与电气安全

- 识别危险电压/能量、可触及部件、绝缘等级、爬电/间隙、接地、温升、阻燃、机械危险和异常条件。
- 间距和绝缘数值基于工作电压、过压类别、污染等级、材料组、海拔和标准版本；缺输入时阻塞。
- 保护器件、熔断、温控和联锁的额定、失效模式及独立性有证据，软件控制不能替代必须的硬件保护。
- 异常测试和故障模拟需要批准的设备、样品和人员，不得在普通开发环境擅自执行。

## CERT-004：EMC、无线和网络安全协同

- EMC 发射/抗扰计划锁定端口、线缆、模式、负载、布置、等级和性能判据，预扫与正式认证分开。
- 无线认证核对模组继承条件、天线、功率、区域、软件配置和整机测试，模组证书不能自动覆盖最终产品。
- 网络安全要求追踪身份、更新、漏洞、数据和事件响应；扫描报告不能替代设计与过程证据。
- EMC/RF/安全整改需重新评估安规、热、结构、软件和生产副作用。

## CERT-005：环保、材料与供应链声明

- 材料合规、受限物质、回收/电池、包装和化学要求基于目标地区及产品类别。
- 供应商声明关联完整料号、制造商、版本/日期和证书范围，系列通用声明不能无依据覆盖具体料号。
- 替代料、表面处理、线缆、胶粘剂和塑料变化触发环保与安规影响分析。
- 证书过期、来源不明或适用范围不匹配时不能标为已符合。

## CERT-006：样机、配置与正式试验

- 认证样机的硬件/BOM、固件、配置、外壳、线缆、附件和工作模式与计划绑定并可追溯。
- 正式试验使用批准配置，临时调试功能、特殊降功率或非发布固件必须声明且评估代表性。
- 失败保留实验室原始报告、现象和配置，整改后确定重测范围；禁止只摘取通过页。
- Golden sample 和认证配置受控，量产偏差与认证版本比较。

## CERT-007：技术文档、标签与持续符合性

- 技术文件包括产品描述、图纸/BOM、风险、测试、关键件、软件/无线配置、标签、说明和符合性声明。
- 标签、警告、安装限制、无线/法规标识和用户说明与目标市场一致，翻译和版本受控。
- 量产维护关键件、工艺、测试和变更记录；供应商或认证关键参数变化触发持续符合性评估。
- 市场投诉、监管更新和漏洞进入变更与现场处置流程。
- 正式报告、证书、CB/DoC 等文件的产品名称、型号、地址、申请人和版本必须与销售产品一致；模板或相近型号文件不得移用。
- 认证到期、标准换版或目标市场法规更新设责任人和提前期，不能等到出货时才发现证书或测试依据失效。

## CERT-008：证据、验收与失败门禁

证据包括适用性清单、符合性矩阵、责任人评审、设计/风险文件、实验室原始报告、样机配置、关键件/材料证明、标签和声明。标准版本/产品类别不明、关键条款无追踪、正式样机与量产不一致或认证失败未关闭时禁止宣称合规和正式发布；AI 只能汇总，不能替代授权签字。
