# 测试、验证与质量保证详细约束

## TEST-001：适用范围与测试基线

适用于单元、集成、SIL/HIL、设备、系统、环境、回归和验收测试。每次执行锁定需求/用例版本、源码/固件哈希、硬件/BOM、配置/NVM、设备 ID、工具/工装版本、环境和时间；不同基线结果不得拼成一次 PASS。

## TEST-002：测试设计与追踪

- 每个用例有稳定 ID、关联需求/风险、测试层级、前置条件、输入、步骤、期望、容差、清理、证据和自动判定逻辑。
- 等价类、边界值、状态迁移、错误猜测和风险优先组合使用；至少覆盖正常、最小/最大、空/非法、超时、资源耗尽、重复、取消/恢复和兼容中的适用项。
- `PASS` 阈值必须在执行前来自需求/规范/批准计划；禁止看到结果后移动阈值。没有阈值的测试只能收集数据或 `NEEDS_REVIEW`。
- 建立需求→风险→用例→执行→缺陷→回归证据追踪；一条用例通过不能自动覆盖其未实际检查的多个需求。

## TEST-003：测试环境与可重复性

- 环境清单包含主机 OS、工具、插件、编译器、仪器、线缆、夹具、供电、负载、网络和环境条件；关键仪器记录校准状态。
- 执行前进行设备身份、固件、配置、时间同步、端口和工装自检；自检失败属于环境失败，不得判产品 PASS/FAIL。
- 随机/模糊/压力测试记录种子、生成器版本和最小失败输入；并发/时间测试记录调度或时间窗口，确保可复现。
- 测试数据按用例隔离；清理失败、残留连接、旧日志或缓存不得污染下一用例。并行运行必须证明设备和端口不共享冲突。

## TEST-004：自动化执行与超时取消

- 测试执行参数化调用，不拼接 Shell；每步有开始、进度、超时、停止、资源释放和最终状态。
- 超时区分被测超时、通信超时和框架失联；框架杀进程后还须关闭串口/网络、停止仪器、恢复设备安全状态。
- 重试只用于已分类的瞬态基础设施问题，记录每次尝试；产品功能失败不得通过自动重试隐藏。最终结果显示首次失败和重试历史。
- 测试判定基于结构化输出、测量或明确断言，禁止用日志中出现“success”或进程退出零作为唯一 PASS。

## TEST-005：软件、接口与硬件测试

- 单元测试隔离纯逻辑并覆盖错误返回和边界；mock 只证明调用合同，不证明真实驱动、时间和电气行为。
- 集成测试覆盖真实序列化、存储迁移、并发、队列满、断线、复位和版本组合；接口两端使用同一规范但独立实现检查器。
- HIL/设备测试关联真实固件哈希和设备 ID，采集原始通信/波形/测量；软件日志不能替代线上信号和物理输出。
- 测试危险输出、保护或故障注入前确认授权、限能、隔离、急停和观察者；未授权保持 `BLOCKED_BY_AUTH`。

## TEST-006：性能、耐久与压力

- 性能测试明确负载模型、预热、采样、时钟、统计量和置信条件；平均值不能替代最大时延、抖动、尾延迟或丢包。
- 压力测试规定速率、并发、持续时间、资源上限和停止条件，持续监测内存、句柄、队列、复位和数据完整性。
- 长稳测试要有心跳、日志轮转、断点恢复和故障时间线；测试结束未发现问题只证明规定条件/时长，不能外推寿命。
- Flash/继电器/电池等寿命测试基于实际循环和加速模型；模型、温度和外推假设必须记录。

## TEST-007：故障注入与恢复

- 故障矩阵覆盖断电/棕断、通信中断、坏帧、存储损坏、资源不足、传感异常、时钟/复位和依赖服务失效中的适用项。
- 注入必须可控、可确认实际发生并可恢复；仅在软件变量中模拟不得宣称硬件故障路径已验证。
- 检查故障检测时间、错误分类、安全状态、数据一致性、告警、自动/人工恢复和再次运行；不能只检查“没有崩溃”。
- 破坏性或可能损坏设备的注入必须单独授权并使用指定样机，生产设备不得默认作为测试对象。

## TEST-008：缺陷与回归管理

- 缺陷记录最小复现、基线、输入、期望/实际、首次原始证据、频率、影响和临时规避；截图不能代替可机器读取的日志/数据。
- 修复必须增加能在旧版本失败、修复后通过的回归用例；先验证根因路径，再跑影响分析确定的回归集合。
- 间歇缺陷不得因一次通过关闭；按批准的重复次数/统计条件验证。无法复现保持开放并记录观测增强。
- 测试变更和产品变更分开审查；禁止同一提交同时放宽断言并修改产品后声称缺陷修复。

## TEST-009：证据、报告与结果语义

- 原始证据只追加或有哈希保护；报告引用原始文件和偏移/时间。裁剪图表必须保留原始数据及生成方法。
- 每项结果严格用 `PASS/FAIL/BLOCKED/NOT_RUN/UNAVAILABLE`；跳过、xfail、无断言、环境失败不能计作 PASS。
- 报告汇总执行数、各状态、覆盖需求、未覆盖风险、缺陷和环境限制；通过率不得把非执行项排除后误导性呈现。

## TEST-010：验收与失败门禁

必需证据：计划/用例、追踪、环境清单、自检、结构化结果、原始日志/测量、缺陷和回归、覆盖与未执行项。证据与基线不匹配、阈值事后改变、清理污染、真实设备要求被 mock 替代或必要用例失败时禁止放行；保留首次失败并针对性整改。
