# Bootloader、安全启动与 OTA 详细约束

## BOOT-001：适用范围与启动链基线

适用于 ROM 启动、一级/二级 Bootloader、应用装载、A/B 分区、升级、恢复和安全启动。开始前锁定芯片启动机制、硬件版本、存储布局、链接地址、镜像格式、密钥策略、升级通道和回退需求；地址或擦除粒度未知时禁止任何写入。

- 描述从复位向量到应用入口的每一级镜像、验证、内存映射、所有者和失败状态。
- 分区表记录起止地址、大小、擦除/写粒度、保护、版本和用途，并与链接脚本、烧录配置交叉核对。
- Bootloader、应用、配置、校准、设备身份和恢复区不得重叠；空洞和保留区有明确填充值/保护。

## BOOT-002：镜像格式与身份

- 镜像头至少定义 magic、格式版本、产品/板卡、硬件范围、软件版本、长度、加载/入口地址、哈希和认证信息。
- 所有长度、偏移、地址和相加在使用前检查溢出与分区边界；未知格式/版本必须拒绝或进入明确兼容路径。
- CRC 只能用于传输完整性，不能证明来源；需要真实性时使用项目批准的签名/MAC 和密钥体系。
- 生成镜像的工具、参数、源 ELF、组件哈希和时间可追溯，文件名不能作为镜像身份。

## BOOT-003：安全启动与信任链

- 从不可变或受保护根信任逐级验证下一阶段及安全配置，明确公钥/哈希存储、撤销和算法迁移。
- 认证完成前不得跳转执行或使用不可信镜像提供的地址/长度；错误信息不泄漏密钥材料。
- 防回滚版本计数的存储、更新原子性、工厂/维修例外和恢复授权必须可测试。
- 调试解锁、恢复模式和量产模式不能形成通用后门；测试密钥与生产密钥严格隔离。

## BOOT-004：下载、写入与掉电安全

- 写入前验证目标设备、产品/硬件、分区、镜像和授权；擦除范围先解析并与受保护区比较。
- 数据按块校验，处理重复、乱序、截断、超时和传输中断；不得在仅接收部分镜像时标记有效。
- A/B、swap、copy 或单区方案必须说明任意指令点掉电后的可启动状态；元数据采用原子提交或冗余机制。
- 写入后从目标存储回读校验，而非只信任下载工具成功返回。

## BOOT-005：启动确认、回退与恢复

- 新镜像先进入候选状态，完成规定的启动、自检和关键服务健康条件后才永久确认。
- 确认前复位、看门狗、崩溃、超时或关键自检失败必须回退最近已验证镜像，重试次数有上限。
- 回退同时处理兼容的配置/NVM schema，防止新应用迁移数据后旧应用无法启动。
- 恢复入口的触发、认证、最小功能、镜像来源和退出条件明确；恢复失败不能破坏最后可用路径。

## BOOT-006：升级协议与资源控制

- 升级会话定义发现、能力、鉴权、下载、校验、激活、确认和取消状态，所有等待和重试有上限。
- 分块大小、缓冲、Flash 写时延和看门狗策略来自目标资源；升级不能无限占用通信、RAM 或日志。
- 断点续传必须绑定同一镜像身份和已校验块，不能将旧会话数据拼入新镜像。
- 远程升级失败不得阻塞本地安全功能；危险执行器在升级和重启期间保持批准的安全状态。

## BOOT-007：兼容、制造与现场运维

- 建立 Bootloader、应用、硬件、配置、密钥和升级服务器/工具兼容矩阵。
- 产线烧录、首次密钥注入、序列化和发布升级使用不同权限/配置，完整审计且敏感值不进日志。
- 现场批次发布支持灰度、暂停、失败率监测、版本查询和撤回；不得向身份不明设备推送。
- Bootloader 自身升级需要更严格的不可恢复风险分析、双重验证和授权。
- 单调版本计数、OTP/eFuse 或安全存储接近耗尽时必须有寿命预算和迁移策略，不得通过清零绕过防回滚。
- 离线恢复介质、维修下载器和服务器不可用场景分别验证，恢复镜像同样执行产品、硬件和签名检查。

## BOOT-008：测试、证据与失败门禁

至少测试有效升级、坏 magic/长度/哈希/签名、错误产品/硬件、禁止降级、每个写入阶段断电、确认前复位、启动失败、回退、恢复和配置兼容。证据绑定设备、硬件、Bootloader/应用哈希、工具和原始日志。测试签名、模拟 Flash 或主机单测不能证明真实目标掉电与启动通过；最后可启动镜像可能丢失时禁止发布。
