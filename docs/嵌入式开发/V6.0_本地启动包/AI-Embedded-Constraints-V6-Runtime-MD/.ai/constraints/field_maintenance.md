# 现场维护、诊断、日志与服务详细约束

## FIELD-001：适用范围与服务边界

适用于现场安装、诊断、维修、远程支持、日志、备件、升级、RMA 和退役。开始前明确设备身份、硬件/固件/配置、现场环境、服务角色、数据隐私、允许操作和恢复责任；远程可达不等于获得控制设备的授权。

- 区分用户、安装、服务、工厂和研发权限，最小化现场工具能力。
- 定义可现场更换件、不可修件、校准影响和维修后必测项。
- 危险设备现场操作具有隔离、确认、急停和人员责任，AI 不得自行执行。

## FIELD-002：设备身份与可追溯基线

- 每台设备关联序列号、硬件/BOM、Bootloader、应用、配置、校准、安装位置和服务历史。
- 读取身份失败或多个来源冲突时停止升级/写配置，不得凭标签或端口猜目标。
- 日志、工单、固件和备件都引用稳定设备 ID，显示名称变化不破坏追踪。
- 时间戳包含时区和时钟可信度；设备时钟错误时使用主机时间和关联序号。

## FIELD-003：可观测性与日志设计

- 关键模块提供状态、错误码、计数器、复位原因、最近失败和版本，不用大量自由文本代替结构化诊断。
- 日志分级、限频、轮转并设大小/保留上限；日志风暴或异常风暴不得耗尽 Flash、带宽或实时资源。
- 日志不得泄漏密钥、令牌、个人信息和完整敏感配置；导出前按角色脱敏。
- 日志语义和错误码版本化，现场工具能识别未知版本并保留原始数据。

## FIELD-004：诊断流程与最小复现

- 先锁定现象、时间、设备/固件/配置、环境和最近变化，再收集原始日志/测量，禁止直接更换参数试错。
- 使用分层诊断树区分供电、硬件、固件、配置、通信、云端、安装和操作问题。
- 每个远程命令记录目标、操作者、参数、结果和回退；只读优先，写入和复位逐级授权。
- 现场临时规避必须记录适用范围、风险、到期和永久修复计划，不能变成无版本默认配置。

## FIELD-005：远程升级、配置与恢复

- 升级前验证设备/硬件/版本、连接质量、供电、存储、兼容、回退和维护窗口。
- 配置变更有 schema、范围、差异预览、原值备份和原子提交；批量下发先小范围验证并支持暂停。
- 升级/配置失败保持本地安全和可诊断，重试有上限；状态未知的非幂等写入不得自动重复。
- 远程恢复、工厂重置和调试解锁的触发、认证、数据影响和退出条件明确。

## FIELD-006：维修、备件与返场分析

- 更换板卡/传感器/电池/模组后更新配置、身份、校准和兼容信息并运行规定测试。
- 备件完整料号、版本、固件要求和替代条件受控，外观相同不能证明可替换。
- RMA 保存故障现场证据、封存状态、复现、拆解、根因和纠正；清除用户数据前满足授权和保留要求。
- 无故障发现不能直接关闭，应检查环境差异、间歇性和观测覆盖。

## FIELD-007：车队/设备群与事件响应

- 批量监控按版本、硬件、地区和配置分组，避免总体平均掩盖局部故障。
- 告警具有去重、抑制、升级、责任人和关闭证据；告警风暴不能自动触发大规模危险动作。
- 安全事件支持受影响版本/设备识别、凭据撤销、升级、通知和证据保全。
- 远程处置先灰度、观察和可回退，批量发布需要明确授权和停止条件。
- 现场数据采集设置带宽、存储、隐私和保留上限；网络中断时有本地缓存与丢失标记，恢复后不得产生无界补传或重复命令。
- 服务工具和诊断脚本记录版本、适用产品、权限和校验值；工程师个人脚本不能未经评审直接批量操作客户设备。
- 远程会话必须能超时、撤销和审计；服务结束后关闭临时端口、账户和调试能力，防止维护入口长期暴露。
- 跨组织转交工单时保留责任、时间线和证据链。

## FIELD-008：证据、验收与失败门禁

证据包括设备/版本身份、权限、原始日志、诊断步骤、远程命令审计、配置差异、维修/校准、回归和现场结果。身份不明、日志被截断且无标记、敏感信息泄露、回退不可用或维修后必测未执行时禁止关闭工单和批量处置；实验室无法复现不能证明现场问题不存在。
