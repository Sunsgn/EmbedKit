# 软件架构、并发、资源与数据原子约束

## SAR-001：模块分层与依赖方向

- 触发条件：新增模块、公共接口、平台适配或跨层调用。
- 必须执行：明确应用/领域/服务/协议/HAL/BSP 的职责和依赖方向；硬件与 OS 差异通过适配器或注册表隔离。
- 禁止：应用层散落寄存器/Pin/编译器特例；页面或业务模块复制驱动/协议逻辑；循环依赖和公共头暴露内部可变状态。
- 必需证据：模块图、调用位置、接口头、构建依赖和替换/单测边界。
- PASS 条件：平台特例集中、依赖单向、公共接口最小且现有入口未回退。
- 失败处理：无法确定已有所有者时先调查，禁止创建第二套实现。

## SAR-002：接口合同与错误语义

- 触发条件：新增或修改函数、回调、消息、驱动或跨模块接口。
- 必须执行：定义参数范围/单位、空值、长度、所有权/生命周期、上下文、线程/ISR 安全、超时、取消、返回码和资源释放。
- 禁止：模糊 bool 覆盖多类失败；忽略关键返回值；输入输出共用缓冲却不说明别名；失败后留下部分提交状态。
- 必需证据：接口声明/文档、调用者检查、非法/超时/忙/离线/资源不足测试。
- PASS 条件：所有调用者处理适用结果，失败路径确定且无资源泄漏或状态污染。
- 失败处理：合同不完整时不得扩散为公共 API。

## SAR-003：RTOS、裸机与事件驱动执行模型

- 触发条件：新增任务、事件处理、主循环步骤、线程或调度策略。
- 必须执行：逐执行单元记录职责、优先级依据、周期/截止期、栈、阻塞点、同步对象、启动/停止和过载策略。
- 禁止：忙等、无界轮询、固定 sleep 拼接隐式时序；在高优先级任务执行长 Flash/网络/总线操作；仅凭任务名猜优先级。
- 必需证据：任务/事件表、调度与阻塞调用链、栈水位或分析、过载/停止测试。
- PASS 条件：截止期和优先级有来源，共享资源不会导致无界反转或饿死，停止后无后台访问失效对象。
- 失败处理：缺调度事实时保持 UNKNOWN，不得照搬 FreeRTOS 或其他内核 API。

## SAR-004：共享状态、锁与消息队列

- 触发条件：数据跨 ISR/任务/线程/核共享，或新增锁、队列、环形缓冲、对象池。
- 必须执行：为每个可变对象指定唯一所有者或同步方法；定义锁顺序、临界区上限、队列容量来源、满/空/丢弃策略和计数。
- 禁止：把 volatile 当互斥；未保护读改写；持锁等待慢设备；无限队列；丢弃安全/报警数据却不按需求处理。
- 必需证据：共享对象清单、同步位置、并发/满队列/超时/取消测试及竞争分析工具结果（可用时）。
- PASS 条件：无数据竞争、死锁和无界等待，溢出可观测，优先级和丢弃策略满足项目要求。
- 失败处理：所有权不明时禁止并发访问；先集中到单一所有者或保持串行。

## SAR-005：状态机、时间与重试

- 触发条件：新增连接、协议、设备、业务、升级或恢复状态逻辑。
- 必须执行：用枚举状态/事件集中迁移；每状态定义入口、允许事件、超时、退出和非法事件；时间比较处理 tick 回绕；重试定义单次/总上限和退避。
- 禁止：多个布尔量拼隐式状态机；无限等待/重试；连续固定 sleep 造成周期漂移；迟到响应污染下一事务。
- 必需证据：状态迁移表/图、超时来源、回绕/非法/迟到/取消/恢复测试。
- PASS 条件：每条迁移可达且确定，异常最终进入明确失败/降级，重复事件具有规定幂等性。
- 失败处理：语义或超时未知时不得补经验值，相关路径保持阻塞。

## SAR-006：内存、字符串与 C/C++ 安全

- 触发条件：新增数组、缓冲、指针、动态内存、任务栈、大对象或序列化。
- 必须执行：证明长度和容量关系，检查算术溢出、符号转换、对齐和生命周期；记录 Flash/RAM/栈增量；动态内存定义上限、失败和释放。
- 禁止：无界字符串函数、VLA/递归进入资源受限路径、使用释放后对象、整数溢出后分配、结构体填充直接上线格式、ISR/硬实时堆分配。
- 必需证据：边界测试、静态/动态分析（可用时）、MAP/ELF、栈水位及重复启停/资源耗尽测试。
- PASS 条件：0/1/最大/超限输入确定处理，无泄漏/越界/未定义行为，资源预算有当前证据。
- 失败处理：缺预算时不得盲目扩容，标记资源结论 UNKNOWN。

## SAR-007：数值、单位与传感换算

- 触发条件：缩放、滤波、平均、积分、控制、阈值、单位转换或浮点/定点变化。
- 必须执行：声明原始/工程单位、量程、缩放、偏置、精度和舍入；检查中间值、除零、移位、符号扩展、累计和饱和；阈值含滞回/抖动策略。
- 禁止：魔法数；单位隐式；未经范围校验的外部值参与安全判断；仅为性能把浮点换定点而无误差证明。
- 必需证据：公式来源、范围分析、参考向量、最小/最大/负值/溢出/NaN（适用时）测试和误差对比。
- PASS 条件：全量程无未定义溢出，输出误差在项目预算内，单位在接口和报告一致。
- 失败处理：量程或阈值来源未知时禁止用于控制/安全决策。

## SAR-008：NVM、配置与掉电一致性

- 触发条件：读写 Flash/EEPROM/文件配置、校准、身份或 schema 变化。
- 必须执行：记录 magic/类型/版本/长度/校验/有效状态；先验证元数据再读字段；多步更新设计任意指令点掉电一致性；提供旧版本兼容/迁移/回滚。
- 禁止：未知版本按当前结构解释；高频变化直接擦写；默认值覆盖生产/校准/密钥；写失败后破坏最后有效副本。
- 必需证据：分区/耐久依据、损坏/截断/旧版/掉电/空间不足/回滚测试和原始镜像。
- PASS 条件：任意测试中至少保留一份可识别有效数据，迁移失败安全回退，写频率符合器件寿命。
- 失败处理：地址、擦除粒度或生产数据边界未知时禁止写入。

## SAR-009：日志、诊断与故障上下文

- 触发条件：新增日志、计数器、崩溃记录、追踪或远程诊断。
- 必须执行：记录最小必要状态、错误码、时间/事务和版本；设置级别、限频、容量/轮转和脱敏；崩溃关联同哈希 ELF/MAP。
- 禁止：日志改变实时行为；输出密钥/令牌；异常刷屏；只写文本不保留可机读状态；用日志存在证明功能正确。
- 必需证据：容量与性能测试、脱敏检查、故障注入、导出/解析和符号化结果。
- PASS 条件：诊断可定位失败且资源有界，关闭/裁剪日志不改变功能语义。
- 失败处理：数据不足必须报告“无法判断”，不得报告“未发现问题”。

## SAR-010：构建、警告、产物与完成门禁

- 触发条件：任何软件修改准备判定完成。
- 必须执行：使用正式目标/工具链，记录命令、工作目录、版本、退出码、警告、产物时间/哈希和 MAP/ELF 资源；先定向后回归。
- 禁止：换工具链冒充正式构建；全局关警告；用旧 output；删除失败测试；退出零但缺预期产物仍判 PASS。
- 必需证据：当前 diff、构建/测试日志、产物清单/哈希、资源和未执行设备边界。
- PASS 条件：正式构建、必需回归、失败路径和兼容均满足，证据绑定当前工作区。
- 失败处理：构建/回归失败保持 FAIL；缺工具/设备分别标 `UNAVAILABLE/NOT_RUN`。
