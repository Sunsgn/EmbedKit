# 软件执行、外设与实时上下文原子约束

## SEIO-001：启动与初始化顺序

- 触发条件：新增或修改启动、板级初始化、驱动初始化、任务创建或业务启用。
- 必须执行：从复位入口列出电源/时钟/内存/Pinmux/驱动/中间件/任务/业务依赖；每步定义成功、超时、失败动作和可重入性。
- 禁止：依赖偶然调度、未注明来源的固定延时、未初始化全局对象或任务创建先后碰巧正确。
- 必需证据：启动调用链、配置位置、失败注入或日志、目标构建及适用设备启动记录。
- PASS 条件：依赖顺序确定，重复启动/局部重初始化不破坏其他模块，失败进入已定义安全状态。
- 失败处理：依赖或稳定时间未知时停止相应启用，标记 `UNKNOWN/BLOCKED`，不得以增加延时放行。

## SEIO-002：时钟、复位与时间基准

- 触发条件：修改系统/外设时钟、PLL、分频、复位、tick、波特率或动态频率。
- 必须执行：核对时钟源容差、锁定/切换条件、外设门控、复位域和失败回退；重新计算所有受影响的通信、定时器、PWM、ADC、看门狗和 RTOS tick。
- 禁止：只改主频宏或寄存器而不检查派生时钟；用忙等延时替代稳定标志；在外设活动时无协议地切钟。
- 必需证据：时钟树来源、计算表、寄存器/配置位置、编译结果和目标测频/时序证据。
- PASS 条件：所有派生频率与项目容差一致，切换和失败路径可恢复，无未解释的波特率或时间漂移。
- 失败处理：目标晶振、分频或外设时钟未知时禁止提交依赖数值，保持 `UNKNOWN`。

## SEIO-003：GPIO 与 Pinmux 配置

- 触发条件：新增或修改 GPIO、复用、上下拉、驱动能力、速度、开漏、外部中断或低功耗状态。
- 必须执行：逐信号核对原理图网络、管脚/复用、方向、电压域、有效电平、外部上下拉、上电默认和安全态；输出按“预装载安全值→配置方向/复用→允许外设驱动”或器件指定顺序初始化。
- 禁止：按相邻引脚、旧板或示例工程猜 Pin；输入悬空；推挽驱动开漏总线；输出方向生效前写入危险有效电平；多个模块重复配置同一 Pin。
- 必需证据：信号映射表、原理图/数据手册位置、Pinmux 配置、初始化调用链及适用电平/波形测量。
- PASS 条件：软件、原理图、封装和板卡版本一致，上电/复位/睡眠/唤醒均保持规定安全状态，无毛刺或争用。
- 失败处理：任一映射、电压或安全态未知时阻止真实输出；普通输入可仅完成静态实现并标设备验证 `NOT_RUN`。

## SEIO-004：中断注册、优先级与 ISR 内容

- 触发条件：新增/修改向量、优先级、触发方式、ISR、回调或中断中可调用 API。
- 必须执行：确认中断源、向量、触发极性、优先级依据、最大频率、清标志顺序、允许嵌套和 RTOS ISR-safe API；ISR 仅保存最少状态并通知后续上下文；记录每个中断的最大到达率 `f_i` 和 WCET `C_i`，计算 `U_isr = Σ(f_i × C_i)`，并将抢占干扰计入截止期分析。
- 禁止：ISR 中阻塞、sleep、普通锁、堆分配、格式化日志、Flash 写入、复杂解析、设备重连、无界循环或调用未经证明 ISR-safe 的 API。
- 必需证据：向量/优先级配置、完整调用图、官方 API 上下文依据、共享数据同步、`f_i/C_i/U_isr` 计算和目标优化配置下最大执行时间测量/上界。
- PASS 条件：`C + B + J` 及高优先级干扰不超过项目截止期，`U_isr` 不超过项目 CPU 预算，不违反内核优先级门限，不丢失/重复清除其他中断状态。
- 失败处理：上下文安全性或优先级规则未知时禁止调用该 API；实时测量缺失时不得报告实时性 PASS。

## SEIO-005：中断标志、抖动与中断风暴

- 触发条件：电平/边沿中断、共享向量、GPIO 外部中断、错误中断或高频事件。
- 必须执行：按器件规定读写顺序识别并清除本源；电平触发先解除源；定义伪中断、机械抖动、重复边沿、溢出和持续错误的限频/屏蔽/恢复策略。
- 禁止：进入 ISR 即清除全部状态；用长延时在 ISR 消抖；错误持续时无限进入 ISR；静默丢弃无法解释的中断。
- 必需证据：参考手册清除语义、异常计数、连续触发测试、恢复路径和 CPU 占用/时序。
- PASS 条件：有效事件不丢不重，异常源不会饿死系统，屏蔽后存在受控恢复和诊断。
- 失败处理：出现中断风暴必须进入有界保护并保留原因，不得靠关闭全部中断当正式修复。

## SEIO-006：DMA、Cache 与异步所有权

- 触发条件：使用 DMA、总线主设备、零拷贝、Cache 或异步收发缓冲。
- 必须执行：声明缓冲地址、长度、对齐、内存属性、生命周期、生产者/消费者和传输期间所有权；按目标规则执行 clean/invalidate、屏障和描述符同步；接收容量至少按 `ceil(R_peak × T_block) + F_max` 推导并与 DMA 分段/回绕要求取更严格值。
- 禁止：DMA 使用即将失效的栈对象；传输中修改/释放缓冲；把 Cache 问题用 volatile 掩盖；错误后遗留活动通道。
- 必需证据：内存布局、容量计算及单位、官方一致性规则、描述符/索引检查、0/1/边界/填满再多一项/回绕/超时/错误测试和目标数据比对。
- PASS 条件：传输前后所有权唯一，回绕和并发无越界，Cache 开关配置下结果符合项目要求，取消能释放资源。
- 失败处理：Cache 一致性或 DMA 可达区域未知时禁止启用真实 DMA，先使用安全同步路径或保持阻塞。

## SEIO-007：UART、I²C、SPI 与 CAN 驱动行为

- 触发条件：新增或修改串行总线初始化、收发、错误处理或恢复。
- 必须执行：明确实例、管脚、时钟、模式/速率、帧格式、超时、缓冲、所有者和并发；UART 按外设分频公式计算实际波特率和双方最坏相对误差；I²C 用 `R_min=(VDD-VOL_max)/IOL_max`、`R_max=t_r_max/(0.8473×C_bus)` 证明上拉存在可行区间并处理 NACK/仲裁/总线卡死；SPI 核对 `tCSS/tCSH/tSU/tH`；CAN 保存时间量子、采样点和实际波特率并处理错误状态/bus-off。
- 禁止：无限等待标志/ACK；调用者绕过所有者重配外设；忽略短传输；错误后直接开始下一事务而不清理状态。
- 必需证据：接口合同、参数计算表及来源页码、配置来源、错误码、边界/并发/断开恢复测试及接收端逻辑分析或总线记录。
- PASS 条件：UART 相对误差、I²C 上拉区间、SPI 时序和 CAN 位时序分别满足双方器件/协议来源值；正常与异常事务有确定结束，错误不会污染下一事务，共享实例序列化且恢复有上限。
- 失败处理：物理层或设备未接入时只报告逻辑/构建层；真实总线行为保持 `NOT_RUN`。

## SEIO-008：ADC、PWM、定时器与捕获比较

- 触发条件：使用 ADC/DAC、PWM、定时器、输入捕获、输出比较或计数器。
- 必须执行：ADC 明确参考、分辨率、采样时间、源阻抗、触发、量程和校准；PWM/定时器明确时钟、频率、极性、分辨率、更新点、回绕和禁用电平。
- 禁止：未经范围检查直接用原始 ADC 做安全判断；活动周期中产生不可控 PWM 毛刺；忽略计数器回绕；把软件日志时间当硬件时序测量。
- 必需证据：计算依据、寄存器/配置、边界值、饱和/回绕、同步更新和目标波形/测量。
- PASS 条件：换算、时序和输出安全态满足项目来源值，更新原子且异常输入可识别。
- 失败处理：参考、量程或执行器安全态未知时禁止形成控制输出。

## SEIO-009：看门狗、复位原因与低功耗恢复

- 触发条件：修改看门狗、软件复位、睡眠、唤醒、时钟门控或电源域。
- 必须执行：喂狗绑定关键周期真实完成；复位原因覆盖前保存；睡眠前收敛事务/DMA/锁，唤醒后恢复时钟、Pinmux、外设、时间和应用状态。
- 禁止：在空闲循环、死循环或恢复未完成时无条件喂狗；用整机复位作为普通外设错误默认恢复；假定睡眠后所有寄存器保持。
- 必需证据：看门狗预算、故障注入、复位原因、睡眠电流/时延和重复睡眠唤醒记录。
- PASS 条件：关键任务停滞会触发预期复位，正常最长操作不误复位，唤醒后接口和时间一致。
- 失败处理：缺真实目标时行为保持 `NOT_RUN`；低功耗恢复不完整则不得放行功耗优化。

## SEIO-010：本规则簇完成门禁

- 触发条件：任务宣称完成任何底层执行、GPIO、中断、DMA、总线、定时或低功耗修改。
- 必须执行：逐条标记适用/N/A，保存当前构建、静态检查、边界错误测试和适用目标证据。
- 禁止：以编译成功替代电气/时序/中断/DMA验证，或以开发板样例替代当前板卡映射。
- 必需证据：适用规则 ID、事实来源、diff、命令/结果、产物哈希和未执行边界。
- PASS 条件：所有适用条款满足且无阻塞性 UNKNOWN/CONFLICT；真实硬件结论有同一板卡与固件证据。
- 失败处理：仅降低相应验证层级，不得把未执行项写为 PASS。
