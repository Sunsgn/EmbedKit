# 嵌入式软件开发详细约束

## SW-001：适用范围、规则解释与事实来源

适用于裸机、事件驱动、不同 RTOS、BSP/驱动、Bootloader、协议、存储及资源受限软件。Linux 内核/设备树另叠加 `embedded_linux`；软硬件接口、通信和构建产物另叠加对应领域规则。

“必须”“禁止”是执行门禁。芯片、SDK、RTOS、引脚、UART 编号、时钟、地址、阈值、周期、超时、栈、缓冲区、构建/下载命令及日志路径只能按以下优先级取值：当前用户要求；作用域内 `AGENTS.md`/`CONSTRAINTS.md`/`.ai/PROJECT_PROFILE.md`；当前原理图、接口文件、协议、数据手册、SDK 文档和工程配置；当前源码与实测；适用版本的厂商官方资料。

来源冲突必须记录为 `CONFLICT`，不得自行选值。缺值标记 `UNKNOWN`；若影响安全、硬件、兼容、内存、构建目标或验收则相应修改为 `BLOCKED`。禁止把 BS20、STM32、FreeRTOS、LiteOS、Keil、GCC 或历史工程值当新工程默认值，不得用经验值补齐项目事实。

## SW-002：任务开始前的搜索范围与基线

- 先确认项目根、目标产品/板卡、硬件版本、软件基线、构建目标和任务边界；只读检查工作区，识别用户已有修改。
- 按“文件名/符号精确搜索 → 相关函数和调用者 → 同模块配置/测试 → 必要时平台层”搜索，禁止先全文读取 SDK、整个仓库、全部日志或所有领域规则。
- 修改前定位启动入口、模块入口、调用者、数据所有者、构建接入点和既有测试。先搜索是否已有实现，不得另造第二套驱动、协议栈、状态机或错误码。
- 只修改最小文件集；不得回退、格式化、覆盖或提交无关改动，不得用大范围重构掩盖局部缺陷。
- 历史产物和日志只能证明历史状态，不能作为本次修改 PASS。

## SW-003：平台、框架与执行模型识别

- 从构建文件、启动代码、链接脚本、SDK 配置和源码证据识别裸机、事件循环或 RTOS；未知时保持 `UNKNOWN_FRAMEWORK`，不得套用熟悉平台 API。
- 裸机必须明确主循环周期、ISR 数据交接、每步最大执行时间和低功耗入口；主循环禁止无界等待、无界解析或无界设备重试。
- 事件驱动必须明确事件来源、队列容量、投递失败、消费顺序和回调上下文；回调不得执行超出时延预算的阻塞工作。
- RTOS 必须列出任务职责、优先级依据、栈来源、周期/截止期、阻塞点、同步对象、启动顺序和停止/恢复路径；不得仅凭名称假定 RTOS。
- 平台差异集中在 BSP/HAL/适配器或注册表；业务代码不得散落芯片宏、寄存器地址、引脚、编译器属性或绝对路径。

## SW-004：模块分层与接口合同

- 应用层仅通过驱动/HAL 访问 GPIO、时钟、复位、DMA、UART、I²C、SPI、CAN、ADC、PWM、Flash；Pinmux、寄存器和硬件时序不得散落在业务层。
- 接口必须写清参数范围/单位、空指针、输入输出、缓冲长度、所有权/生命周期、调用上下文、线程/ISR 安全、重入、超时、返回码和取消/释放。
- 调用者必须处理适用的成功、忙、超时、参数错误、设备离线、资源不足和校验失败；禁止丢弃影响一致性或安全的返回值。
- 魔法数字改为有来源的具名常量；待确认值必须保持未决并阻塞相关路径。
- 公共头文件不得暴露内部可变状态；跨模块依赖应可被单元测试替换或适配。

## SW-005：任务、并发、队列与共享资源

- 每个共享可变对象必须有唯一所有者或明确的互斥、临界区、原子、事件、信号量、队列等同步方法。
- 禁止用未保护全局标志完成跨 ISR/任务协作；`volatile` 只解决可见性，不替代原子性、内存顺序或互斥。
- UART/I²C/SPI/CAN/ADC/Flash 和共享协议缓冲只能通过统一所有者访问；模块不得绕过驱动分别配置或收发。
- 队列、环形缓冲、对象池必须给出容量来源、项上限、满/空策略、优先级、等待上限、丢弃计数和恢复。安全数据丢失策略必须源于安全需求。
- 等待、锁、重试和轮询必须有上限；分析优先级反转、锁顺序和死锁。高优先级上下文不得等待低优先级长设备操作。
- 模块停止/设备断开/应用复位时停止定时器和 DMA、解绑回调、唤醒等待者并释放资源，禁止后台活动访问失效对象。

## SW-006：中断具体禁令与验收

- ISR 只允许读取/清除本中断源必要状态、保存最少数据、执行确定性握手并用 ISR-safe 原语通知后续上下文。
- ISR 中禁止：睡眠、阻塞、普通互斥、堆分配/释放、格式化日志、Flash/NVM 写入、复杂协议解析、浮点重计算、无界循环、设备重连及未经证明 ISR-safe 的 API。
- 清标志前核对外设要求的读写顺序，不得清除其他处理者状态；电平触发必须解除源，避免中断风暴。
- ISR/任务共享数据必须有一致性方法；目标架构非原子的多字节对象不得裸读写。
- 提供 ISR 最大执行时间实测或可复核上界，并与截止期比较；缺目标/工具写 `UNKNOWN/NOT_RUN`，不得宣称实时性通过。

## SW-007：DMA、Cache 与异步缓冲

- DMA 描述符/缓冲明确地址、对齐、内存属性、生命周期、生产者/消费者和传输期间所有权；栈缓冲不得提前失效。
- 有 Cache/非一致总线时按目标官方规则执行 clean/invalidate、屏障或不可缓存配置；规则未知不得猜测。
- RX 处理半满、全满、空闲、回绕、溢出、传输错误和停止竞态；TX 防止活动数据被修改或释放。
- 索引/长度防溢出，环形缓冲至少测试 0、1、容量减 1、容量、回绕、多圈和消费者滞后。
- DMA 超时/错误要停止或复位正确通道、清状态并恢复所有权，不得遗留活动 DMA。

## SW-008：GPIO、时钟、复位与通用外设

- Pinmux、方向、上下拉、默认电平、复用、驱动能力和电压域逐项对照当前原理图/接口表；输出软硬件映射差异。
- 输出初始化必须避免危险毛刺；按器件要求确定安全输出值与方向/复用的先后，无法确认时禁止控制真实执行器。
- 时钟核对源、分频、容差、切换、依赖和失败回退；禁止加固定延时掩盖锁定/稳定问题。
- 总线有超时、错误分类和恢复。I²C 要处理 NACK、仲裁丢失及 SDA/SCL 卡死；SPI 明确模式/位序/片选；UART 处理帧/奇偶/溢出；CAN 处理 error passive、bus-off 和恢复。
- PWM 明确频率、极性、分辨率、更新时机和禁用安全电平；ADC 明确参考、分辨率、采样时间、源阻抗、量程、单位、校准、滤波和饱和。
- 重复初始化、时钟门控和低功耗恢复必须幂等或受状态保护，不得破坏其他使用者。

## SW-009：启动、复位、看门狗与低功耗

- 列出电源/时钟/内存/板级/驱动/中间件/任务/业务依赖顺序、各步失败动作及最小安全状态；不得用偶然调度或固定 sleep 掩盖初始化竞态。
- 复位原因在覆盖前读取并受限保存；区分棕断、看门狗、软件和升级复位，重复复位有诊断计数或安全降级。
- 看门狗只在规定关键工作真实完成后喂；禁止在空闲任务、无条件循环、死循环或未恢复阻塞路径喂狗。
- 睡眠前处理事务、唤醒源和外设；唤醒后恢复时钟、Pinmux、DMA、通信和时间基准；新增周期任务评估功耗。
- 模组掉线、网络断开、总线异常和外设复位应局部恢复，整机复位不得作为默认修复。

## SW-010：时间、状态机、超时与重试

- 用显式枚举表示状态/事件并集中迁移；禁止分散布尔量拼隐式状态机。每状态定义允许事件、超时、出口和非法事件动作。
- 时间比较必须处理 tick 回绕；除非 API 保证任务寿命内不回绕，禁止简单 `now > deadline`。
- 周期任务说明周期来源、允许抖动、首次执行和过载策略；严格周期不得靠连续固定 sleep 累积漂移。
- 重试给出最大次数、单次超时、退避、总上限、取消点和最终失败状态；禁止无限等待 ACK、AT、网络、外设或锁。
- 超时后迟到响应必须丢弃或关联正确事务，不得污染下一请求。

## SW-011：内存、栈、C/C++ 与数值安全

- 新增数组、缓冲、任务栈、对象池和大结构体记录尺寸来源及 Flash/RAM/栈影响；禁止盲目扩大缓冲隐藏缺陷。
- 默认避免动态内存；确需使用时定义阶段、上限、失败、释放、碎片控制和重复启停测试；ISR/硬实时路径禁止动态分配。
- 禁止递归、可变长度数组、无界字符串函数、依赖填充的线格式和未定义行为；指针、索引、长度、移位使用前校验。
- 检查符号转换、乘加中间值、移位、取负最小值、除零和换算溢出；采用宽类型、饱和或拒绝。
- 传感/协议量声明原始和工程单位、缩放、偏置、精度、舍入；高频路径优先用经范围证明的定点，但不得无证据一律禁用浮点。
- 编译警告不得全局关闭；抑制必须局部说明工具链/版本/理由，并有测试覆盖风险。

## SW-012：NVM、配置、校准与掉电一致性

- 持久化记录有 magic/类型、版本、长度、完整性和有效状态；先验证元数据/长度，再校验内容和字段范围。
- 格式变更提供兼容读取或确定性迁移；未知版本不得按当前结构解释。失败时保留旧数据并进入明确默认/安全状态。
- 避免无谓擦写，记录频率和器件耐久依据；禁止在高频任务每次变化直接写 Flash。
- 多步更新必须考虑任意指令点掉电，用双副本、日志、commit 标志或等价原子方案；测试损坏、截断、掉电、回滚。
- 校准、身份、密钥和生产参数区分权限/来源；开发默认值不得覆盖生产数据，日志不得泄密。

## SW-013：协议、通信与外部字节流

- 先取得带版本协议依据，建立命令/字段/方向/长度/端序/单位/缩放/状态/超时/兼容表；不完整时只实现已确认部分。
- 解析顺序：同步/帧头 → 版本 → 声明长度和本地上限 → 命令 → 完整帧 → 完整性校验 → 字段范围；每次读字段前检查剩余长度。
- 禁止字节直接强转本地结构；显式编解码多字节值；编码器先核对容量，只发送实际长度。
- 流式接收处理半包、粘包、噪声、超长、坏校验、重复、乱序、超时和连续坏帧，并在有界步数重同步。
- 未知命令/保留字段/新版本按协议忽略、拒绝或协商，不得臆造；错误日志限频且脱敏。
- 通信不可用不得阻塞本地安全/采集/基本控制；回调只做有界解析/投递，耗时业务异步完成。

## SW-014：Bootloader、固件更新与 OTA

- 镜像关联产品/板卡身份、硬件范围、版本、长度、哈希和批准的认证方式；CRC 不能证明来源可信。
- 写入前验证目标分区和边界，不得覆盖 Bootloader、校准、身份或非目标槽；地址来源不明禁止写入/烧录。
- 激活抗掉电：完整验证后才候选启动，通过健康检查后才永久确认；失败/复位循环/超时回退最近已验证镜像。
- 防降级、密钥轮换和恢复遵循项目策略；缺密钥、硬件或授权标记 `BLOCKED_BY_AUTH/NOT_RUN`，测试密钥不得声称正式通过。
- 测试损坏镜像、错误产品/硬件、长度越界、更新断电、首启失败、确认前复位和回退。

## SW-015：构建、静态检查与产物证据

- 使用已识别的原工程入口、目标和工具链；不得擅自用 CMake/Make/另一编译器替代 Keil、IAR 或厂商工程，替代构建仅是独立适配验证。
- 构建前记录源码/工作区、目标、配置、工具版本；构建后记录命令、工作目录、退出码、错误/警告、产物、生成时间和哈希。
- 退出零但缺预期产物仍 FAIL；用时间、清单、哈希区分当前与旧 output，禁止旧 output 冒充本次证据。
- 先运行受影响编译/单测/静态检查，再必要回归；不得删失败测试、放宽断言、全局关警告或绕过路径变绿。
- 从当前 MAP/ELF 记录 Flash/ROM、RAM/BSS/data、堆、任务栈并对预算；无当前产物/测量写 `UNKNOWN/NOT_RUN`。

## SW-016：设备运行、日志与故障定位

- 操作前确认设备/端口、板卡版本、供电、固件哈希、连接和授权；烧录、保险位/安全位、执行器和危险设备不自动获权。
- 记录固件/设备身份、配置、时间、工具版本、原始日志或测量；“有串口输出”不能证明功能正确。
- 日志可裁剪、限频且不改变实时行为；禁止泄露密钥/令牌/敏感配置或无限增长。
- 崩溃保留复位原因、故障状态、PC/LR/栈和对应 ELF/MAP；必须是同一哈希产物，否则结论低可信度。
- 失败记录最小复现、输入、期望、实际、首次证据、根因、针对性修改和回归；禁止用长延时、无限重试、关功能或整机复位掩盖根因。

## SW-017：测试矩阵与完成判定

- 测试适用的正常、最小/最大、空/非法、超时、资源耗尽、队列满、竞态、断开/复位、重复、取消/恢复和旧数据兼容。
- 驱动关键电气/时序必须目标硬件验证；主机单测/模拟器不能替代 ISR 时延、DMA/Cache、真实总线、功耗或设备行为。
- 缺硬件/工具/许可证/授权时完成独立软件测试，并标 `UNAVAILABLE/BLOCKED/NOT_RUN`；禁止把 mock、桩或编译成功提升为设备 PASS。
- 只允许报告实际达到的验证层级。PASS 同时要求匹配 diff、当前构建、受影响测试、失败路径、当前产物身份及适用资源/设备证据。

## SW-018：记录、交接与 Git 约束

- 记录目标、需求/缺陷 ID、影响文件、接口变化、实现、构建/测试命令、结果、证据、未知项、风险和回退；不得只写“已优化/已通过”。
- 长任务保存阶段、完成/失败项、证据、下一安全动作和恢复命令；恢复时先核对基线和输入哈希。
- 提交前检查状态/diff，只暂存本次文件；缓存、密钥、运行日志、下载物和无关构建产物不得提交。
- 受影响测试通过且差异审查后才能创建单一目标检查点；提交不代表推送、标签、发布或生产授权。

## SW-019：本领域必需证据、验收与失败处理

证据至少包括事实来源/版本、源码定位、影响分析、最小 diff、实际构建命令/退出码/日志、当前产物哈希、测试输入/结果、资源结论、失败路径和未执行项；设备测试还要设备/固件身份及原始证据。

出现事实冲突、潜在越界、无界等待、未保护共享状态、错误硬件映射、关键返回值未处理、构建或必需回归失败时停止相应集成/放行，保留证据并针对性修复。可继续无依赖工作，但不得删除测试、扩大超时、关闭检查或声称模拟通过来改变结论。
