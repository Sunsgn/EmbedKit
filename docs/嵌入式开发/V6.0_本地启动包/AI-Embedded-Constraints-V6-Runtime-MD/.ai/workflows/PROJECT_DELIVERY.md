# 项目交付与归档工作流

1. 锁定需求、源码/设计、硬件/BOM、工具、配置和测试基线。
2. 建立需求→实现→测试→证据追踪，所有“已满足”必须引用当前版本证据。
3. 运行必要构建、检查、回归和交付前验证；失败和阻塞不得从报告中删除。
4. 清点源码、原生 EDA、配置、依赖、固件、制造、测试、证据、迁移和使用文档。
5. 排除密钥、凭据、缓存、临时下载、无关日志和未授权数据。
6. 为正式交付文件生成大小和 SHA-256，绑定版本、目标和用途。
7. 在干净临时目录解压，验证路径安全、清单、入口、文档链接及可执行的构建/测试恢复。
8. 汇总 `PASS/FAIL/BLOCKED/NOT_RUN/UNAVAILABLE`、剩余风险、工具/设备边界和回退方式。
9. 只有全部正式门禁满足且责任人批准时才能发布；否则保留 RC。

文件存在、ZIP 可解压或测试脚本退出零不能单独证明项目可交付。
