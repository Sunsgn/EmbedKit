# 底层驱动开发工作流

## 必须确认

- 当前芯片/板卡/SDK、原理图网络、Pinmux、电压域、时钟、复位、外设实例、中断和 DMA/Cache 规则。
- 资源所有者、调用上下文、超时、吞吐、缓冲、低功耗和恢复要求。

## 执行步骤

1. 对照板级权威资料和 SDK 当前接口，不按旧工程猜寄存器或 API。
2. 复用现有 BSP/HAL；平台差异保留在驱动/适配器，应用层不直接操作硬件细节。
3. 定义初始化、启停、读写、取消、错误、资源所有权和重复初始化合同。
4. ISR 只做最少状态和通知；DMA 定义对齐、Cache、生命周期、回绕、溢出和错误恢复。
5. 总线覆盖超时、忙、NACK/错误、卡死、断开和局部恢复；禁止无限等待或默认整机复位。
6. 使用主机/桩测试纯逻辑和边界，再用目标板及仪器验证真实 Pin、波形、时序、中断、DMA 和恢复。
7. 保存固件哈希、设备身份、逻辑分析/示波/日志和资源时序数据。

## 完成条件

编译或 mock 只能证明相应层级；没有目标硬件时设备结果为 `NOT_RUN`。Pin、电压、地址或安全状态未知时禁止真实驱动输出。
