# 缺陷定位、整改与回归工作流

## 强制执行合同

- 触发条件：出现可复现或间歇性的代码、构建、设计、设备或生产缺陷。
- 必须执行：保存首次失败、建立复现、形成可证伪假设、实施针对性修复并运行回归；跳过项必须说明证据。
- 禁止：未确认根因就用延时、重试、关功能、大范围重构或整机复位掩盖问题。
- 有效条件：修复前可复现失败、修复后同用例通过，且受影响回归没有新增失败。
- 失败处理：不能复现或证据不足时保持 OPEN/NOT_RUN，增加有上限的观测，不得关闭缺陷。

1. 保存首次失败的基线、输入、期望、实际、频率和原始日志/数据。
2. 建立最小复现，不立即增加延时、无限重试、关闭功能或大范围重构。
3. 定位错误层级、源码/设计位置、调用/数据/硬件链和最近变化，形成支持与反对证据的假设表。
4. 选择能区分主要假设的最小实验，一次只改变一个关键变量。
5. 确认根因后实施最小针对性修复，保留现有正常入口和兼容。
6. 增加在旧版本失败、修复后通过的回归用例。
7. 先运行最小复现，再运行影响分析确定的回归、构建和适用设备测试。
8. 更新缺陷记录、证据、状态、风险和回退方法；间歇问题不能因一次通过关闭。

不得删除失败测试、放宽阈值、伪造证据或把整机复位当默认修复。无法复现时增强有限观测并保持未关闭状态。
