# 协议新增与修改工作流

## 强制执行合同

- 触发条件：新增或修改帧格式、字段、命令、状态机、超时、重试或协议版本。
- 必须执行：取得权威版本，建立字段合同，复用现有收发路径并覆盖流式异常、兼容和资源边界。
- 禁止：从抓包猜语义、直接强转结构体、越界读写、无界重同步，或复制第二套完整收发流程。
- 有效条件：当前协议版本、有效/无效向量、兼容行为及真实链路边界均有匹配证据。
- 失败处理：依据或字段不完整时只实现已确认部分；真实链路未执行时对应结论保持 `NOT_RUN`。

1. 取得带版本的权威协议，建立命令、方向、长度、端序、符号、缩放、单位、状态、超时和兼容表。
2. 定位当前编码器、解析器、状态机、缓冲、调用者和历史测试；禁止平行复制完整收发流程。
3. 设计解析顺序：同步/帧头、版本、长度上限、完整帧、校验、命令和字段范围；每次读字段前检查剩余长度。
4. 流式链路处理半包、粘包、噪声、坏校验、超长、重复、乱序、超时和连续坏帧，并有界重同步。
5. 请求/响应定义事务 ID、最大并发、迟到响应、重试上限和幂等语义。
6. 测试有效向量、最小/最大、截断、非法、未知版本、资源耗尽和恢复；尽量用独立实现或权威向量交叉验证。
7. 真实 UART/CAN/网络使用原始帧、逻辑分析或 pcap 与软件日志关联。

PASS 要求当前版本测试和兼容行为均有证据；只有两端相同实现自洽、mock 或日志字符串不能证明真实协议正确。
