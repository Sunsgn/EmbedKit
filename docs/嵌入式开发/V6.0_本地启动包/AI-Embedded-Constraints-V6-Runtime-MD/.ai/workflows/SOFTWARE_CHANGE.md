# 软件修改闭环

## 开始前

1. 读取 `core.md`、`software.md` 及路由补充领域。
2. 确认用户需求、正式构建目标、工具链、源码基线和测试入口。
3. 检查 Git 状态，识别目标文件中的用户原有改动。
4. 定位现有实现、调用者、配置、错误码、并发上下文和既有测试，禁止重复实现。

## 实施

1. 建立影响分析和最小文件集。
2. 明确接口参数、单位、所有权、上下文、超时、错误和兼容。
3. 进行局部修改，保留现有入口、数据和平台适配边界。
4. 增加正常、边界、非法、超时和恢复中的适用测试。
5. 先运行定向编译、单测和静态检查，再运行受影响回归。
6. 使用正式工程入口构建，保存命令、工具版本、退出码、日志和新产物哈希。
7. 解析当前 MAP/ELF 或资源数据；没有数据保持 `UNKNOWN/NOT_RUN`。
8. 失败时保存首次失败，执行单一针对性修复并重新运行受影响测试。

## 完成条件

- 当前目标构建和必需回归通过。
- 失败路径、兼容、资源和设备边界已记录。
- diff 只包含本任务，证据与当前源码/产物匹配。
- 需要真实设备但未执行时不得报告完整功能 PASS。
