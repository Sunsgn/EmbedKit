# Codex 工程执行入口

本项目使用同一套纯 Markdown 嵌入式全栈工程规范。规范正文固定安装在 `.ai-engineering/`；本文只负责路由，不重复专业规则。

## 每个任务的最小加载顺序

1. 读取 `.ai-engineering/rules/00_规范效力与加载规则.md`至`03_证据与完成判定.md`四份通用底线；涉及修改时追加`04_Git与变更管理.md`，涉及接口或持久化时追加`05_数据版本与兼容性.md`。
2. 读取 `.ai-engineering/project/PROJECT_PROFILE.md`、`ENABLED_DISCIPLINES.md`，再按任务专业强制读取对应Profile；涉及构建、EDA、设备、仪器或外部服务时还必须读取`TOOL_CAPABILITIES.md`。只补充当前任务必需事实。
3. 沿项目根目录到目标文件逐级发现已有`AGENTS.md`、`CLAUDE.md`、`CONSTRAINTS.md`及等价局部规则，排除本规范的工具适配入口；记录已读取文件和冲突。
4. 按 `.ai-engineering/RULES_INDEX.md` 根据当前任务语义加载命中的专业规范。专业勾选是常态配置，不得阻止用户当前任务明确命中的专业。
5. 选择一个主工作流；出现跨专业交接、真实测试或发布门禁时，可追加必要交接工作流并记录触发原因。工作流不产生新的技术规则。
6. 任何产生代码/设计修改、正式审核结论、测试结果、放行判断或跨AI交接的任务，都必须在`.ai-engineering/work/<task-id>/`建立独立记录。
7. 在任务记录中按`.ai-engineering/templates/AI加载回执.md`保存实际加载的规则、Profile、局部约束和能力缺口；未成功加载不得声称遵循。

## 不可省略的工程行为

- 先识别真实项目、已有实现、用户改动、局部约束、工具能力和风险，再修改。
- 不得猜测芯片、引脚、地址、时钟、阈值、工具链、EDA规则或测试结果。
- AI不能直接操作EDA、仪器、烧录器或设备时，必须输出可执行步骤并将结果标为 `NOT_RUN`、`UNAVAILABLE` 或 `BLOCKED`，不得声称真实完成。
- 修改必须经过影响分析、最小实现、定向验证、受影响回归、证据归档和差异复核。
- 不得覆盖用户无关改动，不得以Mock、截图、旧日志、命令退出零或AI自述单独证明通过。
- 烧录、安全位、危险执行器、生产、发布、推送和破坏性操作仍需用户明确授权。

## 完成要求

只有符合当前专业规范，并能给出匹配当前源码、硬件版本、配置和测试对象的证据，才能标为 `PASS`。缺少真实硬件或工具不会阻止安全的分析和实现，但必须明确验证缺口、风险和后续操作。
