# 嵌入式工程 AI 开发入口

## 强制加载顺序

每个任务必须按以下顺序执行：

1. 读取本文件，不得预读全部专业约束。
2. 读取 `.ai/PROJECT_PROFILE.md` 和 `.ai/PROJECT_CONSTRAINTS.md`，确认项目事实、具体约束路由、未知项、冲突和授权边界。
3. 按当前任务只读取一个或多个 `.ai/project_constraints/*.md` 项目约束；禁止预读全部项目约束。具体值未初始化时先执行首次识别，不得用通用规则代替项目参数。
4. 读取 `.ai/constraints/INDEX.md`，按任务语义、目标文件和影响传播选择通用专业领域。
5. 始终读取 `.ai/constraints/core.md`，其余只读取路由命中的约束；复杂任务再读取一个匹配的 `.ai/workflows/*.md`。
6. 读取目标路径作用域内更具体的 `AGENTS.md`、`CLAUDE.md` 或 `CONSTRAINTS.md`。项目局部事实优先于通用规则，但不得绕过安全和证据底线。

## 不可省略的执行闭环

所有修改必须执行：

`识别事实 → 需求与影响分析 → 任务计划 → 检查工作区 → 最小修改 → 定向测试 → 收集证据 → 判断 → 针对性修复 → 受影响回归 → 更新状态与交接`

- 不得猜测 MCU、RTOS、引脚、地址、阈值、周期、超时、工具链、构建/下载命令或安全限值。
- 项目约束必须达到实例/路径/命令/接口/单位/上限/失败动作的具体粒度；“遵守规范”“执行测试”“注意安全”等宽泛文字不能替代 `.ai/project_constraints/` 中的当前项目值。
- `UNKNOWN` 不能变成经验值；`CONFLICT` 未解决前不得执行依赖该事实的写入、构建目标选择或设备动作。
- 文件存在、命令退出零、旧日志、mock、截图或 AI 自述均不能单独证明 PASS。
- 真实构建、EDA、设备和生产结论必须具有匹配当前源码、产物、设备和配置的原始证据。
- 不得删除失败测试、放宽验收、无限增加超时、关闭功能或伪造证据来使结果变绿。
- 不得回退、覆盖或提交用户无关修改；提交前检查状态和差异，只包含当前功能。

## 状态、恢复与证据

有实际修改或长任务时，使用 `.ai/templates/` 在 `.ai/work/` 建立并持续更新：

- `TASK_PLAN.md`
- `STATUS.md`
- `HANDOFF.md`
- `INPUT_HASHES.md`
- `evidence/`

新会话必须先核对上述状态、Git 工作区、关键输入和产物身份，再从最近验证通过的检查点继续。未知是否完成的烧录、生产写入、发布等非幂等动作不得自动重放。

## 权限边界

本文件允许项目内必要的只读调查、局部编辑和非破坏性测试，但不自动授权破坏性删除、覆盖重要数据、烧录、保险位/安全位、真实危险设备、外部系统修改、Git 推送、生产或正式发布。需要额外权限时先完成所有无依赖安全任务，再请求明确授权。
