# Codex 工程执行入口

本项目使用同一套纯 Markdown 嵌入式全栈工程规范。本文只负责路由，不重复专业规则。

## 每个任务的最小加载顺序

1. 读取 `rules/00_规范效力与加载规则.md`至`rules/03_证据与完成判定.md`四份通用底线；涉及修改时追加`rules/04_Git与变更管理.md`，涉及接口或持久化时追加`rules/05_数据版本与兼容性.md`。
2. 读取 `project/PROJECT_PROFILE.md`、`project/ENABLED_DISCIPLINES.md`，只补充当前任务必需的项目事实。
3. 按 `RULES_INDEX.md` 只读取命中的专业规范；禁止默认加载全部专业。
4. 需要执行步骤时读取一个匹配的 `workflows/` 文件；工作流不产生新的技术规则。
5. 有修改或长任务时在 `work/<task-id>/` 建立任务记录，禁止覆盖其他任务。

## 不可省略的工程行为

- 先识别真实项目、已有实现、用户改动、工具能力和风险，再修改。
- 不得猜测芯片、引脚、地址、时钟、阈值、工具链、EDA规则或测试结果。
- AI不能直接操作EDA、仪器、烧录器或设备时，必须输出可执行步骤并将结果标为 `NOT_RUN`、`UNAVAILABLE` 或 `BLOCKED`，不得声称真实完成。
- 修改必须经过影响分析、最小实现、定向验证、受影响回归、证据归档和差异复核。
- 不得覆盖用户无关改动，不得以Mock、截图、旧日志、命令退出零或AI自述单独证明通过。
- 烧录、安全位、危险执行器、生产、发布、推送和破坏性操作仍需用户明确授权。

## 完成要求

只有符合当前专业规范，并能给出匹配当前源码、硬件版本、配置和测试对象的证据，才能标为 `PASS`。缺少真实硬件或工具不会阻止安全的分析和实现，但必须明确验证缺口、风险和后续操作。
