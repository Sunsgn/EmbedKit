# 规范效力与加载规则

## 1. 唯一规则源

`rules/`定义跨专业强制底线，`disciplines/`定义专业强制规则。一个要求只能在其权威文件中定义一次；其他文件只能引用标题或路径，不得转抄后形成第二版本。

## 2. 冲突优先级

在不突破安全、事实和证据底线的前提下，按以下顺序处理：

1. 客户端、系统级安全、权限和高优先级指令；
2. 用户对当前任务的明确要求与授权；
3. 目标路径内更具体且已存在的项目约束；
4. 项目源码、配置、测量、项目文档或统一状态中有来源、版本、状态的已确认项目事实；
5. 当前命中的专业规范；
6. 通用工程规则；
7. 工作流和模板。

发现冲突必须列出双方内容、适用范围、风险和拟采用项。涉及安全、不可逆动作、接口兼容或验收口径时，在冲突解决前不得执行依赖该结论的动作。AI不得以项目习惯绕过安全和证据底线。

## 3. 按需加载

每轮只常驻短入口和状态顶部的会话恢复摘要。本文件仅在需要判断规则效力、冲突或加载范围时读取；任务路由使用关键词精确定位，不全文常驻。纯解释、只读检索或低风险小任务只追加真正命中的通用规则和专业章节；修改任务至少追加通用开发、适用安全、证据完成和 Git 规则，涉及接口或持久化时追加数据兼容规则。专业文件先查看标题并读取与当前对象和影响相关的章节；驱动、并发、硬件、安全、发布或跨专业高风险任务读取对应专业全文。选择一个主工作流，其他工作流只作必要检查表。不得为了“可能有用”预读全部规范，也不得以轻量加载为由跳过实际风险命中的规则。

## 4. 项目事实状态

- `CONFIRMED`：有文件、数据手册、配置、测量或用户确认等可定位来源，可用于决策。
- `ASSUMPTION`：为了继续分析暂定，必须显式标记，不能用于危险或不可逆操作。
- `UNKNOWN`：未知，不得替换成经验值。
- `CONFLICT`：来源冲突，解决前不得依赖。
- `NOT_APPLICABLE`：经说明确实不适用。

只补充当前任务所需事实。无关`UNKNOWN`不得阻塞工作；缺少信息会影响安全、接口、电气正确性、不可逆操作或结论有效性时才构成阻塞。

## 5. 专业启用

`profiles/`只提供按需事实采集检查表，不是强制加载项，也不是需要用户填写的运行状态。只有缺少会影响当前任务的关键事实时，AI 才读取对应 Profile 的相关字段，并将确认值及来源写入统一状态或项目已有权威文档，不修改只读模板。例如软件修改改变引脚、电压、时序或通信契约时，必须追加协同分析；纯软件重命名不因此加载硬件规范。不得因为 Profile 未填写而忽略明显命中的专业，也不得强迫用户补齐无关字段。

## 6. 状态词

所有专业和模板的最终状态只能使用`PASS`、`FAIL`、`BLOCKED`、`BLOCKED_BY_AUTH`、`NOT_RUN`、`UNAVAILABLE`或`NOT_APPLICABLE`。分类标签和阶段等级不得替代最终状态；`UNKNOWN`只表示项目事实未知。不得用“应该没问题”“基本通过”替代状态。
