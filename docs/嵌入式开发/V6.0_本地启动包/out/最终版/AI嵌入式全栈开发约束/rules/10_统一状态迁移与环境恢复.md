# 统一状态迁移与环境恢复

## 1. 唯一迁移对象

当前运行状态只使用 `.ai-work/PROJECT_STATE.md`。任务、决策、失败方案、证据索引和节点总结都保存在该统一状态或其引用的稳定证据中，不得为迁移再创建独立交接包、状态台账或按任务拆分的第二套状态树。

## 2. 旧资料导入

发现旧状态、交接文件、任务目录或其他历史记录时，将其视为只读历史来源：

1. 先备份原始内容并记录来源、哈希和适用项目；
2. 提取仍有效的目标、任务、决策、失败条件、保护项、证据和下一步；
3. 无法映射的章节原样保留在备份或历史证据中，并在统一状态建立索引；
4. 冲突、过期或无法回源的结论不得写成当前事实；
5. 核对成功后才递增状态格式版本，禁止原位覆盖旧资料。

不需要用户逐字段审批无损、可回退的状态格式整理；存在信息丢失、语义冲突、敏感数据外移或会改变项目方向时才请求用户决定。

## 3. 恢复执行检查

从旧会话、换机备份或其他环境恢复前，重新核对项目根、源码提交或文件哈希、固件与硬件版本、工作区变化、工具环境、设备身份、用户授权和证据有效性。无法证明一致时将相关结论标记为过期、待验证或 `BLOCKED`，不得自动重放烧录、校准写入、发布、生产操作及其他不可逆动作。

## 4. 换机与团队共享

长期项目必须在状态中记录保护模式；具体模式、一次性选择、自动维护触发和恢复校验执行 `../references/统一项目状态详细规则.md` 第4.3节。`.ai-work/backup/` 与活动状态位于同一故障域，只能用于短期回退，不能冒充灾难恢复。

最小恢复包只包含当前 `PROJECT_STATE.md`、仍被引用且不可重新生成的必要证据、相对路径清单和哈希，不得包含密钥、令牌、完整敏感配置或无关日志。是否纳入受控版本库或加密外部位置由用户决定；AI 不得默认上传、强制跟踪，也不得因为存在本地副本而声称状态已跨机器同步。未选择时可继续安全工作，但必须记录 `LOCAL_ONLY` 风险。

## 5. 完成判定

迁移或恢复只有在以下条件满足时才完成：当前目标和停止位置可恢复；失败方案和保护项未丢失；证据引用可定位；未知与冲突已保留；新环境差异已处理；下一步具体可执行；原始状态仍可回退；恢复清单与哈希已经核对。
