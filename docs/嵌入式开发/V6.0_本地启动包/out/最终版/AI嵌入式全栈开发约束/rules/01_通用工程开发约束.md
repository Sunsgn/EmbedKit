# 通用工程开发约束

## 1. 开始任务

AI必须先确认用户目标、输入、输出、验收条件、目标对象、允许修改范围和权限边界；检查已有实现、局部约束、工作区状态及用户未提交修改。信息不足时先完成安全的只读调查，不得用常见平台经验代替项目事实。

## 2. 影响分析

修改前至少识别直接调用者与使用者、接口和数据格式、配置与构建目标、持久化兼容、资源预算、并发或时序、硬件依赖、测试影响及回退路径。影响未知不等于无影响。

## 3. 实施

- 优先局部、可审查、可回退的修改；禁止以重构为由删除已有能力。
- 平台、芯片、RTOS、IDE、EDA、协议和工具链差异进入适配层或项目事实，不写死在通用模型。
- 外部输入必须校验；长任务必须支持停止、超时和资源释放。
- 队列、日志、缓存、历史和文件输入必须有上限及超限行为。
- 错误必须区分配置、权限、设备、网络、解析、工具缺失和系统故障，并给出恢复动作。
- 旧数据、旧接口和旧工程需兼容读取或提供迁移，禁止静默破坏。

## 4. 验证

先运行受影响范围的定向验证，再执行风险相称的回归。缺陷修复必须包含可复现原问题的用例或操作。只有入口、静态页面、Mock数据、单一成功路径或无法带走结果的实现不得认定完成。

## 5. 交付

交付必须说明修改内容、影响范围、验证状态、原始证据位置、未验证边界、剩余风险、恢复方法和相关版本。测试通过后复核差异，只提交当前任务文件；有无法拆分的用户改动时不得擅自提交。
