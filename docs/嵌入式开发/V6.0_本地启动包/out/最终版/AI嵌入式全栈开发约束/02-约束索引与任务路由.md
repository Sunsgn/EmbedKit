# 约束索引与任务路由

## 1. 加载原则

每轮基础上下文只包含：

- `00-AI嵌入式全栈约束入口.md`
- `.ai-work/PROJECT_STATE.md` 顶部不超过 4,000 字符的“会话恢复摘要”（存在时）

用当前任务关键词在本文件中定位匹配行，不为路由而读取整个索引。只读解释和精确检索按实际风险追加规则。修改文件时读取 `01-AI工作流与项目状态约束.md` 的相关章节，并追加通用开发、安全权限、证据完成和 Git 规则；修改接口、持久化数据或导入导出格式时再追加数据兼容规则。专业文件先读取标题目录，再读取命中的章节；只有影响广泛或高风险时读取全文。若用户只要求解释或审查，保持只读，不把“分析”扩张为“实施”。

加载级别：

- `READ_ONLY`：短入口和会话恢复摘要；只有回答需要时精确读取索引行、源码或专业章节。
- `EDIT`：追加日常状态规则的相关章节、`rules/01` 至 `rules/04`、命中的专业章节和一个主工作流。
- `HIGH_RISK`：设备操作、安全、发布、生产、跨专业或广泛重构，读取相关专业全文，并追加数据兼容、无人值守权限及测试规范。
- `STATE_RECOVERY`：状态缺失、损坏、旧格式、换机或团队恢复时，追加 `references/统一项目状态详细规则.md` 对应章节和 `rules/10_统一状态迁移与环境恢复.md`。

级别只控制读取范围，不降低任务完成标准；执行中发现风险扩大时立即升级加载。

## 2. 专业路由

| 任务信号 | 按需加载的专业规范 | 推荐主工作流 |
|---|---|---|
| 需求、架构、资源预算、接口分解 | 系统工程与需求规范 | 系统工程工作流 |
| 电源、时钟、复位、器件、接口电气、板级 Bring-up | 电子硬件工程总规范；涉及固件时追加嵌入式软件与协同规范 | 软硬件协同分析工作流 |
| 原理图设计或审查 | 电子硬件工程总规范、原理图审核规范 | 原理图设计或审核工作流 |
| PCB 布局、布线、DRC、Gerber、制造输出 | PCB设计与审核规范；按需追加电子硬件规范 | PCB设计工作流 |
| 固件、驱动、启动、ISR、DMA、RTOS、Bootloader、协议 | 嵌入式软件工程规范；验证任务追加真实测试规范 | 软件任务工作流 |
| Embedded Linux、设备树、内核驱动、rootfs、系统服务 | 嵌入式Linux工程规范；按需追加硬件、安全和测试规范 | 软件任务工作流 |
| 引脚、电压、时序、协议、设备联调、故障定位 | 软硬件协同分析规范、相关硬件/软件规范 | 软硬件协同分析工作流 |
| 测试、故障注入、回归、实机验收、交付证据 | 真实测试与交付规范；追加被测对象专业规范 | 测试与问题整改工作流 |
| 结构、公差、散热、环境与可靠性 | 机械热与可靠性规范；按影响追加硬件规范 | 系统工程工作流 |
| DFM、工装、生产测试、校准、追溯 | 生产制造与校准规范、真实测试规范 | 生产交付或生产校准工作流 |
| 威胁、安全启动、密钥、合规、发布 | 安全合规与发布规范；追加软件/测试规范 | 安全合规或发布交付工作流 |
| 替代料、停产、RMA、现场升级、退役 | 供应链与现场维护规范；追加受影响专业 | 系统工程工作流 |
| 陌生工程、未知框架、接手旧项目 | 与当前目标最接近的专业规范 | 项目识别与事实提取工作流 |
| EDA 自动化或未知 EDA 能力 | 对应硬件/PCB规范 | EDA工具能力探测工作流 |

任务同时跨越多个专业时加载多个专业规范，但只选择一个主工作流；其他工作流仅作为阶段检查表。发现影响传播后可追加专业，不得因为最初路由遗漏而忽略真实影响。

## 3. 未知平台降级

无法识别芯片、RTOS、工具链、工程格式或硬件版本时：

1. 保留原始文件、配置、日志和观察结果；
2. 先执行通用源码、二进制、接口、数据流和运行轨迹分析；
3. 将确认事实、推断、假设、未知项和冲突分开；
4. 给出覆盖范围、置信度、缺失证据以及提高置信度的下一步；
5. 禁止猜测成 STM32、FreeRTOS、Keil、GCC 或任何已知平台。

## 4. 资料和模板

- `profiles/` 是项目事实采集视图，只填写本任务需要的字段，不要求一次填满。
- `templates/` 只在需要独立可交付报告时使用；日常状态仍写入统一状态文件。
- `references/` 是可选目录整理参考，不得强制现有项目迁移目录。
- `examples/` 全部为非规范性示例，只说明方法，不构成平台默认值或测试通过证据。

## 5. 完成前交叉检查

任何任务完成前都应确认：真实输入是什么、实际执行了什么、输出和证据在哪里、失败如何定位和恢复、资源上限是什么、如何复用或回归、哪些内容仍未验证。跨专业任务还必须确认接口契约和变更传播已经闭环。
