# AI 嵌入式软件开发具体约束

> 本文件只约束嵌入式软件、固件、驱动、RTOS、通信协议、存储、Bootloader、构建与软件交付。硬件设计追加同目录 `电子硬件工程总规范.md`；测试设计与验收追加同目录 `真实测试与交付规范.md`；创建或整理目录时执行 `../rules/12_项目目录创建与资料归属.md`。

## 1. 软件任务开始门禁

- 确认项目根、产品/板卡版本、软件基线、正式构建目标、工具链和任务边界。
- 检查 Git/文件状态，识别目标文件中的用户已有修改；不得回退、覆盖、格式化或提交无关内容。
- 定位启动入口、模块入口、调用者、数据所有者、构建接入点和既有测试；已有驱动、状态机、协议栈或错误码不得重复实现。
- 芯片、SDK、RTOS、引脚、地址、周期、阈值、缓冲、超时和命令只能取自当前工程及适用官方资料。冲突标记 `CONFLICT`，缺值标记 `UNKNOWN`，不得用示例或经验补齐。
- 只修改完成当前任务所需的最小文件集；供应商 SDK、生成代码、生产参数和校准数据默认不得修改。

## 2. 软件架构与接口

- 应用层不得散落寄存器地址、Pin、DMA 通道、编译器属性、绝对路径或特定 RTOS API；平台差异进入 BSP/HAL、适配器、配置或注册表。
- 公共头文件不得暴露内部可变状态；跨模块依赖必须能替换或单元测试。
- 新增或修改接口必须定义：参数范围和单位、空值、长度/容量、输入输出、所有权、生命周期、调用上下文、线程/ISR 安全、重入、超时、取消、返回码和资源释放。
- 调用者必须处理适用的成功、参数错误、忙、超时、离线、资源不足、校验失败和内部故障；禁止忽略影响一致性或安全的返回值。
- 公共接口变化必须列出全部调用者、版本兼容、迁移方式和回退路径。

## 3. 裸机、事件驱动、RTOS 与并发

- 裸机必须明确主循环周期、每步执行上限、ISR 数据交接和低功耗入口；禁止无界等待、解析或重试。
- 事件驱动必须明确事件来源、队列容量、投递失败、消费顺序和回调上下文。
- RTOS 每个任务必须记录职责、优先级依据、周期 `T`、截止期 `D`、最坏执行时间 `C`、最大阻塞 `B`、最大抖动 `J`、栈、同步对象、启动和停止路径。
- 实时验收至少满足 `C + B + J <= D`；存在抢占时加入更高优先级干扰。
- 每个共享可变对象必须有唯一所有者或明确的互斥、临界区、原子、队列、事件或信号量；`volatile` 不能替代原子性和互斥。
- 定义全局锁顺序、最长持锁时间和超时；禁止持锁等待 Flash、网络或长总线事务。
- 模块停止、设备断开或取消时，停止定时器/DMA、解绑回调、唤醒等待者并释放资源。

## 4. 中断、DMA 与 Cache

- ISR 只允许读取/清除本中断源必要状态、保存最少数据、完成确定性握手并使用已证明 ISR-safe 的原语通知后续上下文。
- ISR 中禁止阻塞、sleep、普通互斥、堆分配、格式化日志、Flash/NVM 写入、复杂协议解析、设备重连和无界循环。
- 每个中断记录最大到达率 `f_i` 和 WCET `C_i`，计算 `U_isr = Σ(f_i × C_i)` 并与项目 CPU 预算比较；缺目标测量不得报告实时性 PASS。
- DMA 缓冲必须定义地址、长度、对齐、内存属性、生命周期、生产者、消费者和传输期间所有权。
- 禁止 DMA 使用即将失效的栈对象，禁止传输中修改、释放或复用缓冲。
- 有 Cache/非一致总线时，按目标官方规则执行 clean、invalidate、屏障和描述符同步；不得用 `volatile` 掩盖一致性问题。
- DMA 错误、取消或超时后必须停止正确通道、清状态并恢复所有权。

## 5. 缓冲、内存与数值

- 接收缓冲至少满足 `capacity >= ceil(R_peak × T_block) + F_max`；其中 `R_peak` 是峰值字节率，`T_block` 是消费者最长停顿，`F_max` 是最大完整帧。
- 队列/环形缓冲测试覆盖 0、1、容量减1、恰好填满、再多一项、回绕、多圈、消费者停顿、恢复顺序和溢出计数。
- 禁止无界字符串函数、VLA、资源受限路径递归、线数据强转结构体和依赖填充的持久化格式。
- 指针、索引、长度、乘加、移位、符号转换、取负最小值和除零必须检查。
- 新增数组、任务栈、对象池和大结构体记录 Flash/RAM/栈增量；禁止盲目扩大缓冲隐藏缺陷。
- 动态内存必须定义阶段、总上限、失败、释放和碎片控制；ISR/硬实时路径禁止动态分配。
- 传感和协议量声明原始单位、工程单位、缩放、偏置、范围、精度、舍入和饱和策略。

## 6. UART、I²C、SPI 与 CAN 软件行为

- UART 明确电气层、实例、时钟、数据/停止/校验、流控、空闲、最大帧、超时和错误恢复；实际波特率误差为 `|baud_actual-baud_target|/baud_target`，并核对双方最坏相对误差。
- RS-485 明确 DE 建立/保持、半双工仲裁和回声；发送完成以移位寄存器或硬件完成事件为准。
- I²C 处理 NACK、仲裁丢失、clock stretching、SDA/SCL 卡死和超时；资料允许时最多产生9个受控 SCL恢复脉冲，每一步必须有超时。
- SPI 明确 Mode、位序、字宽、SCK、CS 极性、`tCSS/tCSH/tSU/tH` 和事务边界。
- CAN 明确 Classic/FD、位时序、采样点、ID/DLC、过滤、错误状态和 Bus-Off 恢复；自动恢复必须符合项目安全策略。
- 所有错误必须有确定结束状态，不能污染下一事务，共享外设必须由统一所有者序列化。

## 7. 协议与网络

- 帧合同记录版本、帧头、类型、长度含义、序号、字段偏移、端序、符号、缩放、单位、完整性和兼容策略。
- 解析顺序固定为：同步/帧头→版本→长度与本地上限→完整帧→校验→命令/字段范围；每次读字段前检查剩余长度。
- 流解析必须处理半包、粘包、噪声、超长、坏校验、重复、乱序、迟到、超时和连续坏帧，并在有界字节/时间内重同步。
- CRC 必须明确多项式、初值、反射、结果异或、覆盖范围和权威测试向量。
- TCP 一次 `recv` 不等于一帧；UDP 不得假定可靠或有序；WebSocket 处理 fragment、ping/pong、关闭码和重连。
- 请求定义事务 ID、最大并发、幂等性和迟到响应；超时重试不得重复执行非幂等命令。
- 所有外部输入设置长度、连接数、速率、内存和计算上限；达到上限时执行明确的拒绝、背压或丢弃策略。

## 8. GPIO、时钟、ADC、PWM 与看门狗软件

- GPIO/Pinmux 逐信号核对当前原理图、Pin、复用、方向、电压域、有效电平、外部上下拉、上电默认和睡眠状态。
- 输出按“预装载安全值→配置方向/复用→允许外设驱动”或器件规定顺序初始化，禁止危险毛刺。
- 修改时钟后重新计算通信、定时器、PWM、ADC、看门狗和 RTOS tick；禁止用固定延时掩盖锁定或初始化竞态。
- ADC 明确参考、分辨率、采样时间、源阻抗、量程、单位、触发、校准、滤波和饱和；未经有效性检查的原始值不得用于安全控制。
- PWM 明确频率、极性、分辨率、更新点和禁用安全电平；更新不得产生不可控窄脉冲。
- 喂狗绑定关键周期真实完成；禁止在空闲任务、死循环或恢复未完成时无条件喂狗。
- 复位原因覆盖前保存，区分棕断、看门狗、软件和升级复位；重复复位必须有限制、诊断和降级。

## 9. NVM、Bootloader 与 OTA

- 持久化记录包含 magic/类型、schema版本、长度、完整性和提交状态；先验证元数据再读取字段。
- 未知版本不得按当前结构解释；格式变化提供兼容读取、确定性迁移或明确拒绝。
- 更新采用“写非活动记录→回读验证→原子提交→切换活动记录”或经证明的等价方案。
- 对每个持久化写步骤注入掉电，任一点失败都至少保留一个可识别有效版本。
- 写入寿命计算：`目标寿命秒数/最短写入间隔×最坏写放大`，并与器件耐久和有效槽数比较。
- 固件镜像关联产品、硬件范围、版本、长度、哈希和认证方式；CRC不能证明来源可信。
- 写入前核对目标分区和擦除边界，不得覆盖 Bootloader、校准、身份、密钥或非目标槽。
- 完整验证后才候选启动，健康检查通过后才永久确认；断电、坏镜像、错误硬件、禁止降级、首启失败和回退必须测试。

## 10. 软件构建与交付

- 使用当前工程正式入口、目标和工具链；不得用 GCC/CMake 等替代 Keil、IAR 或厂商工程后冒充正式构建。
- 记录工作目录、命令、目标、配置、工具版本、退出码、警告、产物、时间和 SHA-256。
- 退出码0但缺预期产物仍为FAIL；旧 output、不同目标或不同哈希不能作为本次证据。
- 从同一正式目标的当前 MAP/ELF 记录 Flash/ROM、RAM/BSS/data、堆和栈；无当前产物则资源结论为 `UNKNOWN/NOT_RUN`。
- 完成前执行定向测试和受影响回归，并按同目录 `真实测试与交付规范.md` 保存证据。
- 提交前检查 diff，只暂存本任务文件；Git提交不等于推送、标签或发布授权。

## 11. 实时性与调度分析（RTOS）

### 11.1. 任务模型
每个周期/偶发任务记录：周期或最小到达间隔 `T_i`、相对截止期 `D_i`、最坏执行时间 `C_i`、最大阻塞 `B_i`、释放抖动 `J_i`、优先级、栈、CPU亲和性（如适用）和关键共享资源。`C_i`必须说明来源：静态上界、目标板测量最大值加裕量或经审查的估算；平均执行时间不能代替WCET。

### 11.2. 固定优先级抢占响应时间
对单核、固定优先级、可抢占、任务独立且满足模型假设的任务，可用迭代式进行初步响应时间分析：
`R_i^(n+1) = C_i + B_i + Σ_{j∈hp(i)} ceil((R_i^n + J_j)/T_j) × C_j`。
从`R_i^(0)=C_i+B_i`开始迭代；收敛且`R_i <= D_i`才满足该模型下的任务响应时间条件。若不收敛或超过截止期，判FAIL。该式不自动覆盖ISR干扰、非抢占区、SMP、服务器任务、复杂自旋锁和多帧事务；这些必须另行建模。ISR干扰可按其最小到达间隔和执行时间加入干扰项，避免重复计入。

### 11.3. FreeRTOS具体核查
- 确认内核版本、端口层、抢占/时间片配置、Tick频率、`configMAX_PRIORITIES`、堆实现、静态/动态分配策略及`FreeRTOSConfig.h`。

### 11.4. 其他 RTOS 与未知内核
- Zephyr、RT-Thread、ThreadX、NuttX 或其他 RTOS 只在项目证据命中时使用其原生配置、对象模型和官方术语，不得套用 FreeRTOS API、优先级语义或内存模型。
- 对未知内核先从启动、调度点、中断交接、同步对象、超时、内存和停止路径提取通用模型；无法确认的专有行为标记 `UNKNOWN` 并给出验证方法。
- 嵌入式 Linux 内核、设备树、rootfs 或系统镜像任务追加同目录 `嵌入式Linux工程规范.md`，不得用 MCU RTOS 规则替代 Linux 生命周期和用户/内核边界检查。
- Cortex-M核对优先级位数、优先级分组和库优先级编码；使用`FromISR` API的中断优先级必须满足该端口的`configMAX_SYSCALL_INTERRUPT_PRIORITY`约束。区分逻辑优先级数值与寄存器移位后的编码，不能凭数值大小猜测。
- 任务栈单位以具体端口API定义为准；记录高水位、峰值调用路径、异常处理栈和中断栈。高水位是观测证据，不自动构成绝对最大栈证明。
- 临界区、挂起调度器和互斥量用途不同：临界区用于极短共享状态保护；挂起调度器不等于屏蔽中断；互斥量用于任务间资源互斥并可提供优先级继承。ISR不得调用任务级阻塞API或互斥量API。
- 每个队列/通知/信号量定义容量推导、满队列策略、丢弃/覆盖策略、超时、所有权和统计计数；禁止静默丢数据。

## 12. 中断、DMA、Cache与内存所有权

### 12.1. ISR边界
ISR只做有界、可重入性明确的工作：确认并清除中断源、采集必要状态、更新最小共享状态、使用已核实的ISR-safe API发通知。记录最坏ISR执行时间、嵌套关系和优先级。禁止阻塞、动态分配、无界循环、复杂协议解析、日志格式化和不可控驱动调用。

### 12.2. DMA缓冲区合同
每个DMA缓冲区明确：分配区域、地址/对齐约束、长度、缓存属性、所有者状态机、CPU/DMA交接时刻、完成/错误/超时路径、复用条件。必须保证DMA可访问该内存区域；不能仅因CPU可读写就认定DMA可访问。

### 12.3. Cache一致性
有D-Cache的MCU/SoC，先依据芯片手册确认DMA与Cache一致性机制。采用非缓存区、缓存维护或硬件一致性方案之一，并说明边界：
- CPU把数据交给DMA前，按平台要求清理相关Cache行并执行必要屏障；
- DMA写入后CPU读取前，按平台要求失效相关Cache行并执行必要屏障；
- 缓冲区按Cache line对齐，避免与无关变量共享Cache line；
- 不得对未按Cache line边界隔离的区域随意invalidate，避免丢失邻接变量脏数据。
无D-Cache平台不应机械添加Cache API。维护操作以芯片和编译器官方文档为准。

### 12.4. 缓冲区容量
容量至少考虑峰值输入速率、最大消费者阻塞时间、最大突发、帧/描述符开销、已有占用和安全裕量。记录溢出检测、计数、恢复策略和压力测试。环形缓冲区必须明确生产者/消费者并发模型；多生产者或多消费者不得直接套用单生产者单消费者实现。

## 13. C/C++、内存与异常路径
- 对整数运算检查有符号溢出、窄化、单位换算、移位宽度和边界；长度计算先防溢出再分配/拷贝。
- 禁止返回局部对象地址、使用释放后指针、重复释放、未初始化读取和不受控递归；资源采用明确所有权和单一释放路径。
- `volatile`只约束特定可观察访问，不提供原子性、互斥或线程间内存序。并发原子操作需核对目标编译器/CPU支持及锁自由属性。
- ISR、异常处理和低内存路径不得依赖可能阻塞或动态分配的日志设施。
- C++异常、RTTI、静态初始化和动态分配策略必须由项目明确；不得因个人偏好改变既有ABI或编译选项。

## 14. 通信协议与状态机
每个协议定义帧格式、字节序、长度上限、版本、校验/认证、转义、超时、重试、序号、重复帧、乱序、半包/粘包、流控和复位恢复。解析器采用有界状态机；输入长度先验证再访问字段。校验和CRC用于差错检测，不代表身份认证。重试必须有上限、退避和幂等语义；非幂等命令需事务ID或状态查询避免重复执行。

## 15. Flash、NVM与掉电一致性
记录擦写粒度、寿命、对齐、写入时序、掉电行为、ECC/坏块、数据版本和迁移策略。采用双页/双槽、日志结构或其他原子更新策略时，定义有效标记写入顺序、CRC、序列号回绕比较和启动恢复算法。测试应在每个关键写入步骤注入掉电/复位，验证旧数据或新数据至少有一个可恢复。禁止仅依赖一次整块写入假设原子性。

## 16. Bootloader、OTA与回滚
更新设计必须定义镜像格式、目标硬件兼容、签名验证、版本/防回滚策略、下载断点、分区布局、试运行确认、看门狗、掉电恢复和回滚触发。签名验证与CRC职责分离。升级前验证电源、空间和镜像身份；升级状态机必须可恢复且对重复请求幂等。真实烧录、密钥操作和生产发布按权限规则审批。

## 17. 构建、链接与调试
- 记录正式构建入口、配置、编译器完整版本、宏定义、优化级别、链接脚本、启动文件、库版本和环境变量。
- 构建成功必须核对目标产物、产物时间/哈希、MAP/ELF、Flash/RAM段、向量表、栈堆和分区边界；退出码0不等于目标正确。
- HardFault/异常分析记录堆栈帧、异常返回值、CFSR/HFSR/MMFAR/BFAR等适用寄存器、当前任务、栈边界和复现条件；先确认堆栈帧有效再解码。
- 断言、日志、Trace和调试器会改变时序/内存布局；关键实时性结论需在接近发布的优化配置下复测。

## 18. 软件任务交付模板
至少交付：需求/缺陷ID、修改文件、接口变化、状态机/时序变化、资源预算影响、工具链/命令、构建产物哈希、测试矩阵、未测项、回退方法和已知风险。没有目标编译或硬件验证时明确标记`NOT_RUN`，不得以主机测试替代。
