# 安全、合规与发布规范

本专业可独立用于产品安全分析、法规适用判断和发布审查。AI可以整理证据和发现缺口，但不得自行作法律结论、认证结论或风险接受决定。

- 建立资产、信任边界、攻击面、威胁、滥用场景、危害、缓解、残余风险和验证的追溯链。
- 身份、密钥、调试口、安全启动、固件签名、防回滚、更新、通信认证、权限和日志按产品生命周期设计；CRC不能证明来源可信。
- 密钥和凭据不得进入源码、普通日志、测试截图或交付包；生成、注入、轮换、吊销、备份和销毁均需授权与审计。
- 外部输入、文件、网络目标、进程参数和更新包执行严格校验；失败进入可恢复安全状态，不泄漏敏感信息。
- 适用标准和法规记录地区、产品类别、版本、范围、证据负责人和实验室/认证状态；预扫通过不等于正式认证。
- 发布前核对SBOM或依赖清单、已知漏洞、许可证、签名、兼容矩阵、回滚、支持期限和安全公告流程。
- 安全或合规豁免必须有批准人、期限、适用版本、补偿措施和关闭计划；AI不得自签。

## 可执行作业方法

### 风险分析流程
1. 列出资产、运行环境、外部接口、物理访问路径、维护通道和信任边界。
2. 按数据流和控制流识别入口、权限边界、敏感数据和危险动作。
3. 分别分析网络威胁、物理篡改、供应链风险、错误配置、误操作、失效状态和可预见误用。
4. 对每个风险记录原因、影响、发生条件、现有控制、残余风险、验证证据和风险接受责任人。
5. 安全控制必须映射到需求、设计、实现、测试和发布配置。

### 嵌入式安全检查
检查安全启动信任根、镜像签名验证、反回滚策略、调试接口生命周期、密钥注入/轮换/吊销、固件更新中断恢复、配置完整性、故障日志脱敏和恢复出厂行为。CRC用于检测偶发损坏，不得作为身份认证或防篡改机制。

### 发布门禁
发布候选必须绑定源码提交、工具链、构建配置、二进制哈希、SBOM/依赖清单、签名身份、测试报告、已知问题、兼容矩阵、升级/回滚方案和支持期限。签名密钥操作、生产发布、风险接受和法规声明由授权责任人执行，AI只准备证据与差距清单。

### 合规适用性
标准/法规清单记录地区、产品类别、适用版本、条款范围、证据负责人、实验室状态和认证状态。AI可提示候选标准和缺口，但适用性、法律解释和认证结论必须由合格责任方确认。
