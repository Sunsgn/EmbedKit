# 嵌入式 Linux、内核与系统镜像工程规范

## 1. 适用范围与基线

适用于 Bootloader、内核、设备树、驱动、rootfs、服务、交叉构建、系统更新和现场诊断。开始前确认 SoC/板卡版本、Bootloader、内核树与配置、DTS、工具链、rootfs/包清单、分区和实际镜像标识。宿主机或桌面发行版行为不得直接外推到目标机。

## 2. 启动链与分区

- 描述 ROM → 一级/二级 Bootloader → 内核 → initramfs/rootfs → init/systemd → 应用的镜像、地址、验证和失败路径。
- 分区表、擦除块、文件系统、A/B 槽、环境变量和恢复分区只能来自当前设备权威来源；地址未知时禁止写入。
- 保存完整串口启动日志并按阶段定位；无日志时区分供电/复位、Boot、内核早期控制台和用户态问题。
- 内核命令行、root、console 和安全选项纳入版本控制，临时调试参数不得成为发布默认。

## 3. 内核配置与交叉构建

- 记录内核版本与补丁、defconfig、配置片段、架构、交叉工具链和构建命令；`.config` 手工变化应回写受控配置。
- 驱动内建或模块化选择基于启动依赖、安全和更新策略；模块 vermagic、符号版本和签名必须匹配运行内核。
- 构建输出隔离，保留 Image/zImage、DTB/DTBO、模块、System.map、配置和哈希；禁止宿主机头文件或库意外进入目标构建。
- 上游和厂商补丁记录来源、适用版本及冲突处理；能编译不等于可维护或目标板可用。

## 4. 设备树

- 核对 DTS/DTSI、include 和 overlay 最终展开结果与原理图，检查 compatible、reg、interrupt、clocks、resets、pinctrl、GPIO 极性、供电和总线地址。
- `status = "okay"` 前确认硬件存在且资源无冲突；禁止复制参考板节点后未经板级核对直接启用。
- address/size-cells、中断父与触发、时钟索引、phandle 和 regulator 依赖以当前内核 binding 为准；dtc 无警告不能证明语义正确。
- 编译后检查实际 DTB，并在目标 `/proc/device-tree` 或等价接口确认运行版本；源码 DTS 不代表设备实际加载了它。

## 5. 内核驱动、ABI 与并发

- 遵循 probe/remove、defer、runtime PM、suspend/resume 和错误 unwind；所有已获取资源在每条失败路径对称且仅释放一次。
- MMIO、IRQ、DMA、clock/regulator/reset、GPIO 和 pinctrl 使用适用的内核资源 API；禁止硬编码虚拟地址或绕过所有权。
- 中断顶半保持短小；线程化 IRQ、workqueue 等选择必须符合上下文。明确锁顺序、睡眠上下文、引用计数、热拔插和卸载生命周期。
- ioctl、sysfs、netlink 或字符设备 ABI 定义版本、定长字段、字节序、权限、长度、阻塞行为及 32/64 位兼容；校验用户指针和所有外部输入。
- 覆盖 open/close、并发访问、probe 失败、延迟 probe、suspend/resume、卸载及设备消失等路径；保留 oops、lockdep 和目标日志。

## 6. Rootfs、服务与持久数据

- rootfs 包、许可证和版本可追溯；删除组件前检查启动、恢复、调试和脚本依赖。
- 服务声明用户/组、能力、文件权限、依赖、启动超时、重启退避、资源上限、停止合同和日志轮转；不得用 root 常驻或无限重启掩盖问题。
- 明确只读根、overlay、数据分区和工厂重置边界；更新不得覆盖设备身份、密钥、校准或用户数据。
- 配置具备 schema、版本、兼容读取、迁移和原子写入；掉电或存储只读时必须有确定恢复行为。

## 7. 网络、安全与现场诊断

- 只开放需求端口，明确绑定地址、认证、TLS/证书、权限和防火墙；SSH、Telnet、ADB 等调试入口不得默认进入发布镜像。
- 根据风险使用能力限制、seccomp/LSM、只读文件系统和最小权限；不得用 `0666` 设备节点规避权限设计。
- SBOM、CVE 和补丁结论绑定具体内核、包版本和配置，记录适用性及缓解；扫描无发现不能证明没有漏洞。
- 诊断按权限收集 dmesg/journal、proc、pstore、core 和版本信息，设置大小、轮转及隐私边界；地址解析必须匹配同版 vmlinux/System.map。

## 8. 性能、存储、更新与验收

- 在目标负载下测量启动阶段、CPU、内存、IO、网络、调度延迟、OOM、泄漏和日志增长。
- Flash/eMMC 文件系统验证掉电、坏块、写放大、只读恢复和 fsck；桌面磁盘测试不能替代目标介质。
- 更新验证镜像身份、硬件适配、签名、分区和完整组件版本组，支持断电恢复、启动健康确认和回退；不得接受混合的不兼容 Bootloader、内核、DTB、模块和 rootfs。
- 证据至少包含启动链、配置与工具链、DTS/binding 核对、实际 DTB、镜像/模块哈希、目标日志、服务、安全、掉电及回退结果。
- QEMU、容器或宿主测试不能证明板级驱动、时序、DMA、功耗和目标存储通过；无目标板标记 `NOT_RUN`。分区、电压或设备树资源不确定时禁止写镜像或启用硬件。
