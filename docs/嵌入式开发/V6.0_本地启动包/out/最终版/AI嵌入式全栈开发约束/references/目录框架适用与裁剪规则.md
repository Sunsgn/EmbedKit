# 目录框架适用与裁剪规则（可选参考）

1. 本参考不定义强制目录树。已有项目优先沿用现有结构，不得为了形式一致重排工程。
2. 先识别源码、硬件资料、构建配置、测试、发布、生产资料和证据的现有权威位置，只补充真实缺失的职责。
3. 小型项目可合并职责目录，大型项目可按产品、板卡、固件、硬件版本或测试层级拆分，但稳定标识和关联关系不得依赖可变显示名称。
4. 构建产物、缓存、依赖下载、临时日志和大文件应有清晰边界、大小上限和清理策略，不得无控制进入源码历史。
5. 目录迁移只有在职责缺失、名称冲突、证据无法追溯或用户明确要求时执行，并提供映射、备份、引用更新、验证和回退。
6. 约束运行状态固定使用 `.ai-work/`，不要求业务资料迁入该目录。
