
# 案例：FreeRTOS UART DMA接收功能（流程示例，非产品参数）

## 1. 输入与目标
目标是在既有FreeRTOS工程中增加UART DMA接收。具体MCU、UART实例、DMA通道、缓存策略、波特率和缓冲区大小均从工程配置及芯片手册提取；本案例不提供可直接照搬的数值。

## 2. 识别与锁定
读取工程入口、启动文件、HAL/LL版本、FreeRTOSConfig、UART初始化、IRQ处理、链接脚本和构建命令。记录Git状态及目标文件哈希。核对目标UART是否已被其他模块占用。

## 3. 设计决策
定义DMA缓冲区所有权状态、半传输/全传输/空闲线事件处理、消费者任务通知、溢出策略、帧解析超时和错误恢复。若有D-Cache，按MCU手册设计非缓存区或Cache维护；不得假设DMA与CPU自动一致。

## 4. 验证用例
正常连续帧、半包、粘包、最大帧、坏校验、DMA错误、UART overrun、消费者延迟、队列满、连续突发、对端断线、任务停止/重启。记录丢帧计数、最大处理延迟、CPU占用和栈水位。

## 5. 交付
正式工具链编译、MAP资源、测试日志、目标板版本、固件哈希、未测项和回退方法。主机模拟通过不能替代真实DMA/中断/Cache验证。


## RC2案例验收补充（示例流程，非真实板级测试报告）
### 失败注入与定位
注入场景：DMA接收缓冲区长度配置小于协议最大帧长；预期表现为帧截断或协议CRC失败。定位证据应包含DMA配置、缓冲区定义、原始接收字节、错误计数和时间戳。
### 整改与回归
整改前先确认DMA传输模式、环形/普通模式、缓存维护要求和中断回调边界；修复后验证最大帧、连续帧、背靠背帧、缓冲区回卷、超时、CRC错误及并发消费者。
### 交付证据
必须绑定MCU型号、芯片修订、编译器版本、FreeRTOS版本、构建配置、固件哈希、测试命令/仪器及原始日志。本文不提供虚构的PASS结果；未接真实目标板时状态为NOT_RUN。
