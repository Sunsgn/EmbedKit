# 原理图设计工作流

## 1. 适用范围
从需求新建电路、修改现有电路、器件替换和原理图审核。纯审核任务可跳过设计步骤，但必须记录范围。

## 2. 输入锁定
确认需求/接口、目标MCU及数据手册版本、供电输入范围、负载、环境、安规类别、器件生命周期、原理图库/封装库版本、现有网表和局部规则。未知关键参数不得用经验值填充。

## 3. 需求分解
建立功能块、供电域、信号域、接口表、关键器件表、保护需求、测试点需求和软硬件信号矩阵。每个接口记录电压范围、方向、时序/速率、上电默认状态、容错和连接器定义。

## 4. 电路设计
按电源入口与保护、稳压/电源时序、MCU最小系统、时钟复位、调试下载、通信接口、传感器模拟前端、驱动与执行器、存储和扩展接口逐块设计。每块必须引用器件数据手册的具体限制，并计算额定值、最坏情况、热耗散和容差。

## 5. 器件与引脚核对
逐项核对符号引脚号、器件实际引脚、封装Pad号、未连接脚处理、NC定义、供电脚、隐藏电源脚、替代料差异及生命周期。封装匹配不得只凭器件名称。

## 6. 电气审查
检查电源短路/反灌、逻辑电平、上电时序、复位、时钟、输入保护、驱动能力、上拉下拉、模拟输入范围、ADC参考、隔离与安全距离。计算必须列公式、单位、输入来源、最坏条件和裕量。

## 7. EDA执行
探测具体EDA版本和可用API。AI未实际修改原生数据库时标记 `PLAN_ONLY`；执行修改前保留可恢复副本或版本控制检查点。ERC结果绑定当前源文件哈希和规则集。

## 8. 输出与门禁
交付原生原理图、网表、BOM初稿、接口/电源树、关键计算、ERC报告、问题清单和版本身份。进入PCB前必须完成器件符号-引脚-封装映射及网表一致性检查。ERC通过不等于电路功能正确或安全认证通过。
