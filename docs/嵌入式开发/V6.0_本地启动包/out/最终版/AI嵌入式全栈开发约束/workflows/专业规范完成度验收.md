
# 专业规范完成度验收

任何专业分册在标记为`READY_FOR_PILOT`前，必须逐项核对下表。文件存在、章节数量或篇幅不能作为完成依据。

| 维度 | 必须内容 | 验收证据 |
|---|---|---|
| 适用范围 | 适用/不适用任务、边界 | 路由规则 |
| 输入 | 必需资料、版本、未知项 | 输入清单 |
| 原理 | 关键机制、限制和适用假设 | 技术说明及来源 |
| 设计方法 | 可执行的分析/设计步骤 | 工作流 |
| 计算 | 公式、符号、单位、边界、示例 | 可复核计算 |
| 工具 | 具体工具、版本、能力和限制 | 工具探测报告 |
| 诊断 | 典型故障、症状、定位路径 | 故障树/检查表 |
| 整改 | 修复方法、回归范围、回退 | 问题闭环记录 |
| 验收 | PASS/FAIL判据及证据要求 | 门禁模板 |
| 案例 | 完整输入、决策、失败、修复、交付 | 案例目录 |

## 状态等级
- `DRAFT`：内容正在编写。
- `REVIEWED`：完成技术审阅，仍未真实项目试点。
- `READY_FOR_PILOT`：九项/十项内容齐全，可进入受控试点。
- `PILOT_VERIFIED`：至少一个真实项目完成试点，问题关闭或明确遗留。
- `PRODUCTION_APPROVED`：多个适用项目、工具和责任人按组织质量流程验收批准。

AI不得自行将规范从`PILOT_VERIFIED`升级到`PRODUCTION_APPROVED`。无法提供证据的项目保持`NOT_RUN`或`BLOCKED`。
