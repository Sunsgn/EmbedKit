
# EDA工具能力探测工作流

## 1. 目标
对当前机器上的具体EDA版本，分别验证原理图/PCB读取、对象查询、对象修改、保存、ERC/DRC、布局、布线、制造导出和独立回读能力。该工作流不预设任何工具已经具备自动化能力。

## 2. 输入
用户指定EDA及版本、工程路径、许可证/插件状态、原生工程副本、目标操作、官方文档和可用API。不得在唯一生产工程上进行接口探测。

## 3. 探测步骤
1. 记录操作系统、EDA完整版本、安装路径、许可证状态和插件版本。
2. 读取该版本官方帮助/脚本API文档，记录文档版本和接口名称。
3. 在隔离副本中执行只读打开和对象查询，核对器件/网络/板层数量。
4. 在测试副本中执行无风险对象修改（例如测试标记/属性），保存后关闭并重新打开，独立回读确认。
5. 探测ERC/DRC调用，保存完整原始日志和规则配置。
6. 单独探测布局、布线接口；记录自动布线器名称、版本、输入约束、失败网络和输出。
7. 导出制造文件，在独立查看器中回读并核对。
8. 每项能力标记`VERIFIED/PARTIAL/UNAVAILABLE/NOT_PROBED`。

## 4. 禁止推断
CLI存在不代表可编辑原生对象；脚本API存在不代表支持自动布局；DRC可运行不代表可自动整改；能够生成Gerber不代表制造文件正确。AD19与KiCad不同版本必须分别探测。

## 5. 输出
生成TOOL_PROBE_REPORT.md，附命令、脚本、原始输出、测试工程哈希、工具版本、成功/失败能力、未验证边界和人工步骤。未经探测的功能保持NOT_PROBED。
