# 软件任务工作流

1. 从统一项目状态恢复目标、停止位置、保护项、失败路线和下一步。
2. 明确需求、目标硬件、运行模型、工具链、构建变体、验收条件和禁止变更范围；未知项保持未知。
3. 检查工作区、局部约束和现有入口，定位启动、调用、任务/事件/中断、数据流、硬件依赖和构建配置。
4. 分析接口、时序、并发、内存、功耗、持久化、兼容性及软硬件影响。
5. 选择最小充分实现，保留已有能力和异常处理，不为通过编译删除断言或弱化错误。
6. 新增并发路径时明确所有权、同步、取消和超时；新增持久化路径时明确掉电恢复；新增协议路径时覆盖坏帧、重复、乱序、超时和资源耗尽。
7. 执行适用的格式、编译、静态检查和受影响单元测试，再按风险执行仿真、集成或目标板验证。
8. 对失败定位根因并增加回归用例；无法执行的测试保留 `NOT_RUN` 或 `UNAVAILABLE`，不得汇总为通过。
9. 复核差异、接口和资源变化，检查 MAP/ELF、警告、链接段、固件标识及回退方法。
10. 更新统一状态和证据；测试通过后按项目 Git 规则创建单一目标检查点，不能安全拆分时说明原因。

## 实时与资源分析

按任务类型建立任务/中断表、优先级、周期、截止期、WCET、阻塞、抖动、栈、队列和 DMA 缓冲区预算。存在抢占时进行适用的响应时间分析；检查 Flash、网络和总线长操作是否阻塞关键任务。估算、仿真与目标板实测必须分开记录。

## 退出条件

当前范围验收满足；正常和失败路径经过与风险匹配的验证；证据与当前源码、构建产物和目标硬件匹配；未验证项、硬件边界、剩余风险和下一步已明确。
