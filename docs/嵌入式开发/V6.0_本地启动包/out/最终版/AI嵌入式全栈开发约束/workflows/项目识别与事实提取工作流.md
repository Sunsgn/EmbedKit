# 项目识别与事实提取工作流

## 1. 目标
在不修改项目的前提下，识别当前工程类型、入口、依赖、构建工具、专业分支和约束来源，为本任务建立最小充分的项目事实集。

## 2. 执行步骤
1. 确认用户指定工作目录、主机/容器环境和允许访问范围。
2. 只读扫描顶层目录、版本控制状态、已有AI入口和局部约束文件。
3. 根据文件特征识别工程候选：Keil/IAR/CMake/PlatformIO/STM32CubeIDE、Linux构建系统、KiCad、Altium等。
4. 对候选工程读取权威配置和构建入口，交叉核对源码、生成文件和注释。
5. 探测本机工具是否存在及版本；仅查询版本，不自动安装或升级。
6. 需要独立报告时使用 `../templates/PROJECT_DISCOVERY_REPORT.md`：记录 Fact ID、值、来源路径/位置、版本、状态和置信限制；否则写入统一状态。
7. 识别局部约束、项目目录映射、子模块和用户未提交修改。
8. 对当前任务命中的专业加载相应Profile、规范和工作流；未命中专业不加载。
9. 形成未知项、冲突项、影响和需用户确认事项。
10. 完成输入锁定后才进入修改计划。

## 3. 工程识别规则
扩展名只能用于候选识别，不能单独证明工程类型或工具链。至少用两个相互独立的证据交叉确认关键事实；如仅有一个来源，标记其局限。

## 4. 输出
输出工程树摘要、识别到的工程/目标、构建入口、工具探测、专业路由、项目事实表、冲突/未知、扫描范围和排除范围。只记录与任务相关的信息，避免把整个仓库内容复制进报告。

## 5. 门禁
识别结果足以确定目标、输入和安全边界时可进入规划。影响安全、电气正确性、接口或不可逆操作的关键事实为UNKNOWN/CONFLICT时，阻断依赖该事实的动作。
