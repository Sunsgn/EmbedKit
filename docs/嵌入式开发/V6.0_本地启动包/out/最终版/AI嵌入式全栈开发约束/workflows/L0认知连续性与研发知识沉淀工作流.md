# 认知连续性与研发知识沉淀工作流

## 1. 启动与恢复

1. 读取 `.ai-work/PROJECT_STATE.md` 中最终目标、当前任务、停止位置、下一步、保护项、风险和最近节点总结。
2. 定向检索与当前任务相关的决策、失败方案、证据和历史摘要，不全文加载全部历史。
3. 检查工作区、源码/硬件/固件基线和工具环境是否仍与记录一致。
4. 记录过期、冲突或无法回源的信息；不得用旧结论覆盖当前事实。
5. 明确本轮范围、验收、授权和最小下一步后开始工作。

## 2. 执行中

- 每个重要修改单元后核对是否仍服务于当前目标、是否扩大范围、是否影响保护成果或跨专业接口。
- 工具失败后不得声称依赖它的后续步骤成功。相同条件下连续失败时停止重复尝试，记录证据、根因假设和允许重试条件。
- 大日志、完整报告和二进制证据保存到 `.ai-work/evidence/` 或项目既有证据目录；状态文件只保存摘要、结果和定位信息。
- 用户在工作期间修改文件或改变目标时，重新读取差异并按统一状态规则处理，不覆盖用户改动。

## 3. 节点总结触发

以下情况自动更新“最近节点总结”：阶段完成、复杂问题解决、问题关闭、一轮修改及回归完成、里程碑完成、会话即将结束、上下文接近上限或出现不可绕过阻断。

节点总结至少包含：目标、实际完成、关键结论、修改范围、验证及证据、失败路线、未解决风险、准确停止位置、唯一优先下一步。普通小改动只更新现有记录，不生成冗余独立文档。

## 4. 长期知识

只有可复用且有来源的结论才生成独立技术说明、问题闭环、阶段总结或复盘。项目已有文档目录优先沿用；没有合适位置时可使用 `templates/` 中模板。独立文档路径写回状态文件，不复制全文。新证据推翻旧结论时标记旧结论失效原因和替代项，不删除历史依据。

## 5. 会话结束

更新当前进度、停止位置、下一步、证据、失败方案和最近节点总结，确保新会话只读取入口、路由、状态和少量相关文件即可继续。不得要求用户手工生成交接文件或维护多个状态表。
