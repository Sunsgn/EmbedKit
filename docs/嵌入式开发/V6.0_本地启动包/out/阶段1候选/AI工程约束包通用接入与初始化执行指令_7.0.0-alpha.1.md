# AI 工程约束包通用接入与初始化执行指令

> 配套版本：`7.0.0-alpha.1`  
> 配套文件：`通用ai约束文档_7.0.0-alpha.1.zip`  
> ZIP SHA-256：`87D4EBBB9EDD45FC2061B3FBC397BE71E5E2AAE435F1D15FD58926EDD57ECCCF`

## 1. 给执行 AI 的强制指令

你正在为一个已有或新建工程安装 AI 工程约束系统。必须将本 Markdown 与上面的 ZIP 作为一组使用；版本、文件名或 SHA-256 任一不一致时立即停止，不得猜测、替换或继续安装。

安装目标是用户明确指定的**唯一项目根目录**，不是 ZIP 所在目录、父级工作区、磁盘根目录、用户主目录或临时目录。项目根无法唯一确定时必须先向用户确认。安装前不得修改项目文件，不得自动执行 `git add`、`git commit`、`git push`，也不得清理用户现有改动。

必须使用 Python 3.10 或更高版本。所有 ZIP 检查、计划文件、事务目录和备份必须位于目标项目之外。禁止直接把 ZIP 全量解压或覆盖到目标项目中；只有 `bootstrap.py apply` 可以根据已验证计划写入项目。

## 2. 安装前确认

先确定并记录以下绝对路径，后续命令不得依赖模糊的当前目录：

- `ZIP_PATH`：配套 ZIP 的绝对路径；
- `PROJECT_ROOT`：唯一项目根绝对路径；
- `WORK_DIR`：位于项目外的本次安装工作目录；
- `BOOTSTRAP`：从 ZIP 中单独安全提取到 `WORK_DIR` 的 `bootstrap.py`；
- `PLAN_PATH`：位于 `WORK_DIR` 的计划 JSON 路径。

执行前检查：

1. 确认两个交付文件版本均为 `7.0.0-alpha.1`；
2. 使用系统哈希工具计算 ZIP SHA-256，并与本文顶部的完整值逐字节比较；
3. 检查 Python 版本满足 `3.10+`；
4. 确认 `WORK_DIR` 不在 `PROJECT_ROOT` 内，也不是项目的 Git 跟踪目录；
5. 记录项目当前 Git 状态（若不是 Git 工程则明确记录），仅用于安装前后比对；
6. 从 ZIP 中只读取根目录下名称完全等于 `bootstrap.py` 的普通文件，安全复制到 `WORK_DIR`。不得在完成预检前把其他成员解压到项目或工作目录。

Windows PowerShell 可用以下方式校验哈希和 Python 版本；路径应替换为实际绝对路径：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '<ZIP_PATH>'
python --version
```

若无法以“只提取指定普通文件且不解析 ZIP 内路径”的方式取得 `bootstrap.py`，停止并报告，不得退化为直接向项目解压整个 ZIP。

## 3. 强制执行顺序

### 3.1 全包只读预检

```powershell
python '<BOOTSTRAP>' inspect --zip '<ZIP_PATH>' --target '<PROJECT_ROOT>' --expected-sha256 '87D4EBBB9EDD45FC2061B3FBC397BE71E5E2AAE435F1D15FD58926EDD57ECCCF' --json
```

只有命令成功，且结果未报告路径穿越、重复路径、特殊文件、异常大小、异常压缩比、清单错误或目标边界错误，才可继续。

### 3.2 在项目外生成安装计划

```powershell
python '<BOOTSTRAP>' plan --zip '<ZIP_PATH>' --target '<PROJECT_ROOT>' --output '<PLAN_PATH>' --expected-sha256 '87D4EBBB9EDD45FC2061B3FBC397BE71E5E2AAE435F1D15FD58926EDD57ECCCF' --json
```

读取结构化结果和计划文件，至少确认：

- `can_apply` 为 `true`；
- 目标根目录与用户确认的 `PROJECT_ROOT` 完全一致；
- 未出现未知文件冲突、无法证明归属的本地修改或边界逃逸；
- 将创建、更新、保留、备份的文件符合预期；
- 计划文件确实位于项目外。

`can_apply` 不是 `true` 或存在任何冲突时必须停止，原样保留证据并向用户说明；不得删除冲突文件、强制覆盖、临时改名规避或手工拼接安装内容。

### 3.3 应用经过验证的计划

计划生成后不要修改 ZIP、项目目标文件或计划 JSON。确认无漂移后执行：

```powershell
python '<BOOTSTRAP>' apply --plan '<PLAN_PATH>' --json
```

保存命令输出中的事务目录绝对路径。若应用程序检测到计划后漂移、清单变化、哈希变化或目标变化，必须重新从 `inspect` 开始，不得绕过检查。

### 3.4 安装后验证

应用成功后执行：

```powershell
python '<PROJECT_ROOT>\.ai\system\aic.py' status --verify --json
```

只有命令成功、安装版本正确且包拥有文件的哈希验证全部通过，才能判定阶段 1 安装成功。随后还要确认根目录的 AI 入口文件已生成或受控块已正确合并，同时用户原有入口内容、现有文件和未提交改动仍被保留。

最终安装报告至少记录：项目根、包版本、ZIP SHA-256、执行时间、安装状态、事务目录、创建/更新/保留/冲突摘要、验证结果、Git 前后状态差异以及尚未实现的能力边界。

## 4. 中断恢复与安全回滚

应用中断或失败后，不要再次执行新的 `apply`。使用上一轮输出中记录的项目外事务目录：

```powershell
python '<BOOTSTRAP>' resume --transaction '<TRANSACTION_DIR>' --json
```

若用户决定撤销本次安装，执行：

```powershell
python '<BOOTSTRAP>' rollback --transaction '<TRANSACTION_DIR>' --json
```

回滚只允许恢复本事务拥有且自安装后未被外部修改的内容。回滚报告出现“外部修改”“无法安全恢复”或类似冲突时必须停止并保留现场，禁止强制覆盖用户的新修改。

在用户完成验收并明确不再需要恢复前，**不得删除事务目录、备份、计划文件或执行报告**。验收后如需清理，也必须再次确认其绝对路径位于本次项目外 `WORK_DIR` 或已记录的事务目录内。

## 5. 安装完成后的 AI 工作入口

后续 AI 会话应先读取项目根的对应入口文件（优先 `AGENTS.md`，其他客户端使用各自标准入口），再按其中指引进入 `.ai/system/ENTRYPOINT.md`。不得跳过入口直接凭聊天上下文判断工程状态。

本阶段安装的入口和运行时文件属于约束包管理内容。需要完善约束系统时，应先检查包状态和所有权，再做可追踪的增量修改；不得用重新解压 ZIP 的方式覆盖运行中的约束系统。

## 6. `7.0.0-alpha.1` 的明确边界

本版本是**阶段 1 安装基础候选版**，已提供包完整性校验、安全计划、事务应用、续跑、回滚、入口安装和安装后校验。它不代表最终目标已经完成。

以下能力仍属于后续阶段，不得在报告中声称已具备：

- 统一结构化工程状态中心；
- 跨会话、多 AI 并发写入和冲突保护；
- 自动判断“当前做到哪里、下一步做什么”的完整状态机；
- 研发节点自动总结、证据闭环和历史比较；
- 面向约束自身演进的完整迁移、验证与发布流程。

如果用户要求继续开发，应基于已安装系统和目标基线逐阶段补齐这些能力，并为每个阶段提供可验证证据、失败恢复和独立 Git 检查点。
