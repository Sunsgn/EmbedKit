# EmbedKit 协议工程工作台实用化方案

更新日期：2026-10-13

## 1. 产品重新定位

通用 AI 已经能够阅读协议文档并生成 C、Python 或 JavaScript 解析代码，因此“能够解释协议、生成一帧、解析一帧”不能作为 EmbedKit 的核心优势。

协议模块重新定位为：

> AI 将厂家文档转换为协议草案；EmbedKit 将草案验证为可重复执行、可连接真实设备、可进入自动化测试并可长期维护的协议工程资产。

统一闭环：

```text
厂家 PDF / Word / Excel / DBC / 文本
              ↓
本地提取文字、表格、页码和原始位置
              ↓
AI 生成受约束的协议模型草案和待确认项
              ↓
Schema、边界和安全规则确定性校验
              ↓
厂家样例、真实抓包和测试向量双向验证
              ↓
绑定串口 / TCP / UDP / WebSocket / CAN
              ↓
实时拆包、字段解析、请求响应关联和录制
              ↓
生成并执行多步骤设备测试
              ↓
输出原始数据、失败位置、协议版本和报告
```

AI 输出只能是待验证草案。拆包、长度、CRC、端序、字段转换、超时、设备收发和测试判定必须由本地可测试的确定性代码执行。

## 2. 真实使用场景

### 2.1 模组 AT 指令联网

导入 AT 手册后识别命令、参数、同步响应、异步 URC、超时和错误码，生成并执行：

```text
发送 AT → 等待 OK → 查询 SIM → 等待注册 URC
→ 设置 APN → 建立 TCP → 发送业务数据 → 校验响应
```

失败必须定位到步骤、TX/RX 原文、时间、超时条件、实际响应和未满足断言。

### 2.2 私有二进制串口协议

导入协议和真实日志，形成帧头、长度、命令、序号、负载、转义和校验规则。连续接收能够处理噪声、半包、粘包、坏校验和重新同步，并保留绝对字节偏移。

### 2.3 厂家 Modbus 点表

AI 辅助识别非标准列名、合并单元格、单位和备注；本地规则负责地址区域、类型、倍率、端序和范围。确认后的点表用于解析真实 RTU/TCP 响应、批量轮询和异常报告。

### 2.4 CAN DBC 与现场日志

导入 DBC 和 candump/CSV，批量解码并统计坏行、未匹配 ID、DLC 错误和越界信号。后续同一模型可绑定 Local Agent CAN 通道并复用为测试断言。

### 2.5 协议版本升级

比较新版文档或 DBC 中的命令、字段、长度、枚举、校验、时序和错误码，列出受影响的解析规则、快捷指令和测试流程；未经确认不得覆盖已验证版本。

## 3. 核心优势与非目标

### 3.1 必须形成的产品优势

1. **真实输入**：直接接受厂家原文、抓包、设备日志和通信会话。
2. **确定性执行**：同一模型和输入产生一致结果，错误定位到文档、日志行或字节偏移。
3. **双向验证**：同时验证“字段 → 编码 → 字节”和“字节 → 解码 → 字段”。
4. **真实设备闭环**：协议可绑定通信通道、执行收发、处理异步消息并生成测试。
5. **版本化资产**：模型、证据、测试向量和设备适用范围可比较、迁移和导出。
6. **批量复现**：稳定重复处理日志、抓包和测试流程，不依赖 AI 每次回答的一致性。
7. **本地证据链**：默认本地处理日志和设备数据，报告不依赖 AI 会话记录。
8. **跨工具联动**：通信日志进入协议解析，协议消息生成快捷指令和测试步骤。

### 3.2 明确不做

- 不把聊天解释协议原理作为核心功能。
- 不为每个厂家创建写死的独立页面。
- 不直接执行 AI 生成的任意 C/Python/JavaScript 代码。
- 不在缺少样例和真实数据时宣称协议已验证。
- 不自动发送 AI 推断出的写寄存器、升级、复位或控制命令。
- 不要求先创建项目才能使用协议或通信工具。
- 不默认向外部 AI 上传完整协议、源码、日志、密钥或设备身份信息。

## 4. 统一协议资产模型

协议采用版本化声明模型，而不是把生成代码作为唯一真相：

```ts
interface ProtocolDefinitionV1 {
  schema: 'embedkit.protocol.v1';
  id: string;
  name: string;
  revision: string;
  transport: {
    families: Array<'serial' | 'tcp' | 'udp' | 'websocket' | 'can'>;
    textEncoding?: 'ascii' | 'utf-8' | 'gbk';
    lineEnding?: 'none' | 'cr' | 'lf' | 'crlf';
  };
  framing: {
    mode: 'delimiter' | 'length-field' | 'fixed-length' | 'can-message';
    header?: number[];
    delimiter?: number[];
    lengthField?: FieldLocation;
    escape?: EscapeRule;
    maximumFrameBytes: number;
    resynchronization: ResynchronizationRule;
  };
  messages: ProtocolMessage[];
  checksums: ChecksumRule[];
  transactions: TransactionRule[];
  timing: TimingRule[];
  evidence: ProtocolEvidence[];
  ambiguities: ProtocolAmbiguity[];
  testVectors: ProtocolTestVector[];
}
```

模型必须表达请求、响应、主动上报、条件字段、数组、位域、枚举、端序、倍率、长度范围、校验范围、转义、序列号、超时、重试、结束条件以及每条规则的来源。

### 4.1 关联实体

| 实体 | 作用 | 必须保留的证据 |
| --- | --- | --- |
| `ProtocolDocument` | 原始文档及提取结果 | 文件指纹、页码、表格位置、提取方式 |
| `ProtocolDraft` | AI 或规则生成的草案 | 模型版本、来源片段、未确定项 |
| `ProtocolRevision` | 用户确认后的不可变版本 | 版本号、变更说明、兼容范围 |
| `ProtocolSample` | 厂家样例、抓包或日志 | 来源、方向、时间、原始数据、预期结果 |
| `ProtocolValidationRun` | 一次确定性验证 | 引擎版本、结果、失败位置、输入指纹 |
| `ProtocolBinding` | 与通信通道的可选关联 | 通道、设备、固件版本 |
| `ProtocolTestSuite` | 从事务生成的测试流程 | 前置条件、步骤、断言和清理 |

原始文档、日志和凭据不进入普通工作区备份；模型与脱敏证据只能由用户显式导出。

## 5. AI 与确定性代码边界

### 5.1 AI 负责

- 从自然语言和复杂表格中提取字段候选；
- 识别命令、响应、错误码、枚举和时序描述；
- 为非标准列名提出映射建议；
- 生成协议草案、测试向量和待确认问题；
- 汇总版本差异并解释确定性引擎的错误。

### 5.2 AI 不负责最终判定

- CRC、长度、端序和位域的运行时计算；
- 帧边界、粘包、半包和重新同步；
- 真实设备命令发送、超时和重试控制；
- 测试通过/失败及版本兼容性的最终结论；
- 没有来源证据的默认字段和危险操作授权。

### 5.3 AI 输出合同

AI 只返回符合 JSON Schema 的草案，依次通过：

1. JSON 与 Schema 校验；
2. 字段偏移、长度和数值范围校验；
3. 字段重叠、帧长和校验覆盖范围校验；
4. 危险命令、缺少来源和未确定项检查；
5. 测试向量确定性执行；
6. 用户确认歧义后创建正式版本。

失败时保留 AI 原始输出和 JSON 路径错误，但禁止进入真实设备写操作。

### 5.4 隐私模式

| 模式 | 处理方式 | 适用范围 |
| --- | --- | --- |
| 完全本地 | 复制文本或导入 JSON/DBC，本地验证 | 保密协议、离线环境 |
| 用户自带 AI | 用户选择模型和发送片段 | 普通厂家文档 |
| 外部 OCR/AI | 明示服务商、范围和风险后执行 | 扫描 PDF、复杂表格 |

扫描件没有 OCR 结果时只能显示无法提取，不得伪造识别成功。

## 6. 确定性协议引擎

### 6.1 Framing Engine

- 固定长度、分隔符、帧头加长度字段和 CAN 消息；
- 噪声跳过、最大帧长、半包保留和超时结束；
- 转义前后长度及校验顺序；
- 坏帧后的有限重新同步；
- 每帧保存流偏移、时间、方向和原始字节。

### 6.2 Codec Engine

- 整数、浮点、BCD、字符串、位域、枚举和数组；
- 大小端及 Modbus 字序；
- 倍率、偏移、单位和合法范围；
- 条件字段和长度依赖；
- 编码后再解码的往返一致性检查。

### 6.3 Checksum Engine

复用现有 CRC 命名模型和自定义参数。协议规则保存参与范围、是否包含帧头/长度、结果端序和标准检查向量。

### 6.4 Transaction Engine

- 按命令、序号或地址匹配请求响应；
- 允许中间 URC、多个合法响应和结束条件；
- 支持超时、重试、退避和取消；
- 区分协议异常、设备错误、传输断开和测试断言失败；
- 清理步骤即使部分失败也继续释放资源。

### 6.5 Validation Engine

| 等级 | 含义 | 允许能力 |
| --- | --- | --- |
| 草案 | 只通过 Schema，没有有效样例 | 禁止真实设备写操作 |
| 样例验证 | 厂家样例和往返测试通过 | 离线解析和生成帧 |
| 抓包验证 | 多份真实日志和坏帧路径通过 | 绑定只读实时观察 |
| 设备验证 | 明确设备和固件上完成收发 | 同适用范围内自动化测试 |

“未发现错误”与“证据不足无法判断”必须分别显示。

## 7. 页面和交互

### 7.1 协议工作台

复杂流程使用单一工作区，一次只显示当前步骤：

```text
协议目录
  ├─ 文档与来源
  ├─ 协议模型
  ├─ 样例与验证
  ├─ 实时联调
  ├─ 测试流程
  ├─ 版本差异
  └─ 报告与导出
```

原文、日志字节和失败详情放入统一证据抽屉，避免多个永久面板破坏布局。

### 7.2 文档导入

1. 显示文件类型、大小、能否提取文字和隐私模式；
2. 本地提取文字、表格、页码，扫描件提示 OCR；
3. 用户选择发送给 AI 的页面或表格，不默认上传全文；
4. AI 返回草案、来源引用和待确认问题；
5. 用户只确认影响执行的歧义，不逐字段重新录入。

### 7.3 模型审查

默认按消息和字段编辑，高级模式才显示 JSON。字段显示偏移、长度、类型、端序、来源、AI 置信度、人工确认状态以及关联测试向量。

### 7.4 验证实验室

支持粘贴、文件导入和从通信会话选取真实数据，同时显示原始字节、帧边界、字段树、校验中间值、噪声、坏帧、不完整尾部、批量通过率和首个失败位置。

### 7.5 实时联调

通信调试保持独立。用户主动选择协议版本后，通过公共会话模型订阅 RX/TX，不直接侵入串口页面状态。原始终端与结构化帧互相定位；发送前显示目标通道和完整字节，危险命令二次确认。

### 7.6 测试生成

从已验证事务生成现有集成测试步骤，包含通信通道继承、前置检查、发送、等待、变量提取、断言、异步事件、重试和清理。测试报告保存协议版本和字段级失败证据。

## 8. 现有功能迁移

| 能力 | 处理方式 | 新定位 |
| --- | --- | --- |
| 串口/TCP/UDP/WebSocket | 保留独立界面 | 协议工作台可选订阅会话 |
| CRC | 保留独立工具 | 协议校验确定性底座 |
| 自定义协议帧 | 保留单帧和连续流 | Framing/Codec 初始实现 |
| Modbus | 保留 RTU/TCP 和表格解析 | 标准协议适配器 |
| CAN DBC | 保留单帧和批量日志 | CAN 协议适配器 |
| 集成测试 | 保留流程和共享通道 | 承载生成的事务步骤 |
| AI 助手 | 保留独立入口 | 文档草案和解释入口之一 |

公共引擎稳定后，现有工具逐步改用公共模型。不得删除既有入口、批量能力和导出；旧数据必须兼容读取或迁移。

## 9. Web 与 Local Agent 分工

浏览器直接完成模型编辑、Schema 校验、离线编解码、日志批量解析、测试向量、报告导出、WebSocket/Web Serial 关联和用户授权的 AI 请求。

Local Agent 只增强系统串口后台会话、原始 TCP/UDP、CAN、超大文件分块、本地 OCR/转换和长时间测试恢复。Agent 离线时模型、日志、样例验证和报告仍可用；网页不得通过 Agent 执行任意命令。

## 10. 建议程序结构

```text
frontend/src/protocol/
├─ model/          # Schema、迁移、证据和版本
├─ engines/        # framing、codec、checksum、transaction、validation
├─ adapters/       # Modbus、DBC、AT、声明式二进制协议
├─ documents/      # 本地提取、AI 输出合同、歧义审查
├─ sessions/       # 协议会话和通信桥接
├─ reports/        # 验证报告和版本差异
└─ workspace/      # 协议工作台及互斥面板

proxy/src/
├─ protocolSessionManager.js
├─ canProviderRegistry.js
└─ documentConversionProvider.js
```

领域引擎不依赖 React、Local Agent 或特定 AI。适配器只转换格式，不改变公共模型含义；AI 服务不能直接调用通信接口。

## 11. 开发阶段

### P0-A：协议模型与验证内核

- 定义 `ProtocolDefinitionV1`、JSON Schema、错误和迁移接口；
- 完成长字段、固定长度、分隔符拆包；
- 完成整数、位域、枚举、字符串、数组、倍率和端序；
- 接入 CRC；
- 实现往返测试和坏帧隔离；
- 通过适配器兼容现有自定义帧工具。

验收：噪声、粘包、半包、坏 CRC 和恢复全部有测试；错误定位到字段和字节；未知规则安全失败；模型和验证报告可导入导出。

### P0-B：AI 文档草案

- 本地提取可选文字和表格并保留位置；
- 建立 AI 结构化输出合同；
- 显示未确定项、冲突来源和危险命令；
- 只发送用户选择的页面或表格；
- 用户确认后创建不可变版本。

验收：覆盖 AT、二进制串口、厂家 Modbus 三类独立样本；AI 不可用时仍能导入和编辑模型；扫描件不伪识别；AI 错误不影响已有版本。

### P0-C：验证实验室与实时通信

- 导入厂家样例、串口/网络/CAN 日志；
- 批量显示通过、坏帧、未知消息和尾部；
- 通信会话可选绑定协议版本；
- 原始终端与结构化帧同步定位；
- 请求响应、超时和异步事件留证；
- 实时帧可保存为测试向量。

验收：离线可验证日志；Agent 断开只影响对应通道；结论可回到原始字节；协议错误不停止终端接收；发送前确认目标。

### P1-A：测试流程与报告

- 将消息和事务转换为现有测试步骤；
- 支持变量、条件等待、URC、重试和清理；
- 流程默认继承第一个通信通道；
- 报告包含协议、设备、固件、原始收发和字段差异。

验收：完成一条 AT 联网流程和一条二进制请求响应流程，失败能定位到步骤、帧和字段。

### P1-B：版本比较与代码导出

- 比较命令、字段、枚举、校验和时序；
- 列出受影响的样例、快捷指令和测试；
- 导出 C、Python、TypeScript 参考实现；
- 生成代码携带模型版本和测试向量；
- 通过同一组黄金向量后才标记为已验证生成物。

## 12. 测试矩阵

| 维度 | 必测场景 |
| --- | --- |
| 文档 | 文本 PDF、复制表格、DOCX/XLSX、扫描件、损坏和超限 |
| 协议 | AT、长度型二进制、分隔符、Modbus、DBC、未知格式 |
| 数据流 | 单帧、粘包、半包、噪声、坏长度、坏 CRC、转义错误 |
| 字段 | 端序、有符号、位域、枚举、数组、条件、编码、越界 |
| 事务 | 正常/异常响应、URC、超时、重试、取消、断线、清理失败 |
| AI | 非法 JSON、字段重叠、无来源、危险命令、服务不可用 |
| 版本 | 兼容升级、字段移动、校验变化、命令删除、旧数据迁移 |
| 平台 | 纯浏览器、Agent 在线/离线、Web Serial、网络、CAN |
| 规模 | 5 MiB 日志、100000 帧、上限、取消和资源释放 |

规则引擎至少使用三个独立通用样本，不得只依赖当前导入工程或单一模组。

## 13. 完成判定

单项能力必须同时满足：

1. 从真实文档、模型或日志进入；
2. 正常与损坏输入均有确定结果；
3. AI 推断、人工确认、确定性验证明确分离；
4. 批量处理带大小、帧数和错误数上限；
5. 失败定位到页、行、帧偏移或字段；
6. 结果可导出或进入通信/测试；
7. Agent 离线时无关能力可用；
8. 数据带版本和迁移；
9. 具备领域、组件和真实设备验收；
10. 独立 Git 检查点且不回退现有功能。

建议持续统计草案 Schema 通过率、人工歧义数、样例/抓包/设备验证率、坏帧恢复率、首次解析真实帧耗时、升级影响识别率和报告复现率，但不能以“AI 自动化率”替代正确性。

## 14. 下一步执行顺序
