# EmbedKit 工程档案与开发环境工作台实施方案

状态：实施中  
制定日期：2026-10-14  
适用范围：工程中心、开发环境、Local Agent、资料中心、学习中心、工具箱、数据迁移与发布

## 1. 目标

EmbedKit 在保留现有芯片/器件查询、官方资料导航、教程学习、通信调试、集成测试和嵌入式工具箱的基础上，新增工程档案与开发环境管理能力。

系统需要回答：

1. 当前程序实现了什么功能，功能依据和验证状态是什么；
2. 工程需要哪些 IDE、编译器、SDK、芯片包、调试器和辅助软件；
3. 当前计算机已安装哪些版本，是否满足工程要求；
4. 环境缺失时，哪些软件可以安全自动安装，哪些只能由厂商安装器辅助安装；
5. 应当使用哪个软件实例打开工程或构建产物。

系统不替代 Keil、IAR、编译器、烧录器或外部 AI。代码理解和修改可由用户现有 AI 完成，EmbedKit 负责保存经确认的程序功能、管理工程环境、执行确定性检查并关联资料和工具。

## 2. 保留与调整范围

### 2.1 原样保留并持续维护

- 资料中心中的芯片、器件、数据手册、参考手册、勘误和官方来源查询；
- 学习中心中的教程、学习路线、学习进度和实践证据；
- 串口、TCP、UDP、WebSocket 通信调试；
- 集成测试、测试历史、证据报告和基线比较；
- ELF、MAP、HEX、BIN、SREC、SVD、DBC、HardFault、CAN、CRC、定时器、ADC 等独立工具；
- Local Agent、本地文件授权、构建产物和生命周期公共模型；
- GitHub Pages `/EmbedKit/` 部署与 Agent 离线降级能力。

所有上述模块继续保留独立入口，不要求先创建工程。

### 2.2 增量调整

- 工程中心只管理工程功能、环境需求和资料索引，不保存测试设备或通信通道；
- 工程增加结构化程序功能、开发环境需求、资料关联和确认状态；
- 工程分析只处理真实导入内容，移除默认 MCU 示例和可能被误认为真实编译的演示流程；
- AI 助手保留为可选能力，AI 结果必须经用户确认后才能进入工程功能档案；
- Local Agent 增加软件发现、版本检测、受控安装和参数化启动能力。

## 3. 最终信息架构

```text
工作台
├─ 工程中心
├─ 开发环境
├─ 工程分析
├─ 通信调试
├─ 集成测试
└─ 嵌入式工具箱

知识中心
├─ 资料中心
└─ 学习中心

系统
├─ AI 助手（可选）
├─ 本地助手
└─ 数据管理
```

## 4. 工程档案模型

工程档案 v3 沿用原工程稳定 ID。旧项目自动迁移工程名称、型号、芯片、说明、标签、功能、环境需求和资料索引；废弃的测试设备、工程通道及活动设备选择不再迁移。通信调试和集成测试继续独立管理真实会话。

### 4.1 程序功能

每项程序功能记录：

- 名称和说明；
- 输入、输出和使用的硬件/软件资源；
- 相关源码位置和资料 ID；
- 来源：用户、项目文档、确定性分析、导入或外部 AI；
- 状态：草稿、已确认、已验证；
- 更新时间。

外部 AI 内容默认是草稿，不能自动显示为已验证功能。

### 4.2 开发环境需求

每项需求记录稳定能力 ID、显示名称、版本范围、是否可选、来源和依据。例如工程依赖 `compiler.arm.ac5`，而不是依赖某个本机绝对路径。

同一能力可以由多个本机软件实例提供。工程共享文件不保存许可证、密钥、本机绝对路径或用户凭据。

## 5. 软件与环境模型

```text
SoftwareDefinition      软件及能力定义
SoftwareInstallation    本机已安装实例
ProjectRequirement      工程环境需求
EnvironmentResolution   需求与本机实例的匹配结果
InstallManifest         受控安装清单
InstallTask             下载/安装/验证任务
LaunchAdapter           参数化启动适配器
```

软件检测顺序：操作系统安装信息、PATH、已知官方目录、软件版本命令、用户通过系统选择器手工绑定。自动检测失败必须允许手工确认，不得直接判定软件不存在。

## 6. 安装策略

环境缺失时，用户可以选择版本和安装目录。安装分为：

1. **全自动安装**：官方便携包或具有公开、稳定静默安装参数的软件；
2. **辅助安装**：EmbedKit 下载并校验官方安装器，用户在厂商界面完成许可证、账号或组件选择；
3. **仅提供指导**：厂商不允许自动获取或安装时，只提供已核验的官方入口和完成后的重新检测。

Keil、IAR 等商业软件首期只做检测、官方导航、启动安装器和安装后复检，不绕过账号、许可证或厂商限制。

### 6.1 受控安装清单

正式安装清单必须声明：

- 软件 ID、版本、操作系统和 CPU 架构；
- 官方 HTTPS 来源、下载大小、SHA-256 或厂商签名；
- 许可证、是否需要用户接受、是否需要管理员权限；
- 安装模式、是否支持自定义目录、依赖项和磁盘空间；
- 版本检测、健康检查、卸载或安全回滚边界；
- 清单维护时间和验证样本。

Local Agent 只接受注册表中已知的清单 ID 和结构化参数，不接受网页传入任意 URL、Shell 命令或未声明的安装参数。

### 6.2 安装流程

```text
解析工程需求
→ 检测本机实例
→ 展示缺失项、来源、许可证、大小和权限
→ 用户选择版本与目录并确认
→ 下载到受控临时目录
→ 校验摘要或签名
→ 解压或参数化启动官方安装器
→ 重新检测版本与能力
→ 运行健康检查
→ 保存本机绑定和安装回执
```

默认使用具体可执行文件路径，不自动污染系统全局 PATH。必须修改环境变量时，需要展示变更内容并再次确认。

### 6.3 失败与恢复

覆盖网络中断、来源失效、校验失败、磁盘不足、目录不可写、管理员授权拒绝、用户取消、已有版本冲突、工具被占用、部分安装、复检失败和需要重启等路径。

只有 EmbedKit 自己管理的便携包可以自动回滚。第三方安装器失败后不得擅自删除厂商目录。安装日志必须脱敏并设置大小和保留数量上限。

### 6.4 离线环境包

允许在联网计算机生成带版本化清单和摘要的离线环境包，在目标计算机校验后安装。商业软件只有在许可证允许时才能打包，否则只导出需求、来源和安装说明。

## 7. Web 与 Local Agent 边界

Web 前端负责工程档案、软件目录、需求匹配、安装确认、进度展示、资料和工具。Local Agent 负责本机扫描、文件授权、下载校验、磁盘检查、受控解压、参数化进程启动、取消和复检。

Agent 离线时，工程档案、资料、教程和纯浏览器工具继续可用；软件扫描、安装和启动显示明确降级状态。

## 8. 实施阶段

1. 建立工程档案 v2、程序功能和环境需求模型，完成旧数据迁移、导入导出和上限校验；
2. 将旧设备项目页升级为独立工程中心，移除设备与通道配置，增加功能和环境编辑；
3. 建立软件定义、安装实例、需求解析和匹配服务；
4. 扩展 Local Agent 软件扫描与版本检测，实现独立开发环境页面；
5. 实现安装清单、下载校验、任务状态、取消和安全回滚；
6. 先支持 Arm GNU Toolchain、CMake、Ninja、OpenOCD 等可验证工具，再做商业软件辅助安装；
7. 清理工程分析页的示例生成与模拟能力，关联真实工程档案；
8. 增加资料、教程和工具的可选关联；
9. 完成真实工程、多版本软件、离线、失败恢复、备份迁移和 GitHub Pages 验收。

## 9. 完成判定

至少使用 Keil、IAR、GCC+CMake/Make 三类真实工程验证：

- 旧项目升级后工程说明、功能和环境需求不丢失，废弃的设备与通道字段明确删除；
- 程序功能可保存、确认、检索、导出和恢复；
- 环境需求能匹配多个本机版本并解释选择依据；
- 缺失工具可以安全安装或进入明确的厂商辅助流程；
- 下载来源和摘要可核验，失败可取消、重试和诊断；
- 芯片查询、教程、通信、测试和工具箱不回退；
- Agent 离线和未知软件安全降级；
- 正式构建保持 `/EmbedKit/` 资源前缀。

单纯增加软件图标、下载链接、静态页面或无法复检的“安装成功”提示，不能认定为完成。
