# EmbedKit 嵌入式工具箱实用性审计

更新日期：2026-10-13

## 1. 完成标准

工具“能算出一个结果”不等于可用于工程。每个工具必须形成以下最小闭环：

1. 接受工程师真实拿到的输入：厂家文档、日志、构建产物、抓包或批量数据，而不只接受演示参数。
2. 给出可复核结果：保留原始值、计算依据、字节序、地址范围、错误位置和能力边界。
3. 支持迭代：历史对比、批量处理、筛选、重新映射或参数复用，而不要求逐项手工重复输入。
4. 结果可带走：复制、CSV/JSON/文本报告、代码片段或跨工具传递。
5. 失败可恢复：格式错误行隔离、大小与条数上限、未知格式降级，绝不静默猜测。
6. 浏览器可完成的能力不依赖 Local Agent；只有原始套接字、本地大文件和 ELF 等受限能力才使用 Agent。

统一验收模型为：`真实输入 → 可控操作 → 可核验证据 → 导出/联动 → 失败恢复`。

相对通用 AI，EmbedKit 的核心优势不是再解释一次原理，而是对用户本地的真实文件、日志、抓包和设备数据进行确定性处理。每项能力至少应具备批量与可重复执行、严格校验、原始位置证据、版本对比、跨工具联动、可审计导出中的一项；AI 只辅助解释和提出假设，不能替代协议计算、格式解析、设备操作与证据链。界面和报告必须明确区分“确定性结论”“启发式建议”和“证据不足”。

## 2. 优先级与当前结论

| 优先级 | 工具 | 当前可用能力 | 影响实用性的主要缺口 | 下一次验收目标 |
| --- | --- | --- | --- | --- |
| P0 | Modbus | RTU/TCP 帧、厂家寄存器表、工程值 | PDF/DOCX/XLSX 原文提取、多个表格与合并单元格 | 文档提取后预览表格；用户确认列映射；保留未识别行；扫描件明确要求 OCR |
| P0 | CRC 与字节序 | 常用/自定义参数、校验范围、批量帧、C 参考代码 | 从协议文档自动提取参数、附加/验证帧尾 CRC | 从协议参数文本建立模型；验证“数据+CRC”整帧；批量结果导出 CSV |
| P0 | 自定义协议帧 | 单帧生成/解析、连续日志拆包、噪声与坏帧隔离 | 条件字段、转义、可配置校验覆盖范围、模板持久化 | 字段模板版本化；支持转义和多长度字段；解析结果可关联通信会话 |
| P0 | HardFault | 手工寄存器、真实日志提取、SCB 解释、ELF 联动 | 调查过程归档、多个异常帧、RTOS 任务栈证据 | 输出逐步调查清单；保存脱敏证据；批量符号化多个 PC/LR 地址 |
| P0 | MAP | 双版本独立解析、容量/模块/符号比较、模块内存分类与节区/符号下钻、JSON/CSV 证据 | 跨归档库成员归一、源码与提交关联、历史趋势 | 将增长对象关联到源码和构建版本；连续多版本趋势；优化建议完成前后验证 |
| P0 | 固件合并与比较 | BIN 分段合并、冲突与差异 | HEX/SREC 混合输入、发布布局、差异补丁 | 多格式分段布局、重叠图、空洞策略、版本差异和发布清单可导出 |
| P1 | CAN DBC | DBC 文件与单帧信号解码 | 批量 CAN 日志、时间轴、复用信号、异常统计 | 导入常见 candump/CSV；筛选 ID；批量解码与曲线/CSV；坏帧隔离 |
| P1 | CAN 帧分析 | 单帧位数和最坏占用 | 总线负载依赖消息集合而非单帧 | 导入周期报文清单；计算平均/峰值负载、仲裁延迟和超载风险；支持 CAN FD |
| P1 | CMSIS-SVD | SVD 导入、寄存器/字段/地址 | 寄存器实测值批量解码、数组/派生外设、厂家 Pack | 导入 SVD/Pack；粘贴寄存器转储；显示复位值、访问权限、保留位和字段差异 |
| P1 | ELF/AXF | 段节、符号、DWARF 地址定位 | 大项目筛选、两个版本比较、调用栈批量符号化 | 地址列表批量定位；符号/节区增长比较；明确 stripped、压缩节和 DWARF 边界 |
| P1 | Intel HEX | 校验、分段、BIN 导出 | 地址布局可视化、与 BIN/ELF 对照、重叠诊断 | 展示段/空洞/入口；重叠来源；导出时显式选择范围与填充值 |
| P1 | Motorola SREC | 记录校验、BIN 导出 | 与 HEX 相同的发布与比较闭环 | 复用统一固件段模型、布局、重叠、比较和发布清单 |
| P1 | BIN | CRC、空白比例、头尾字节 | 基地址、分区、熵/字符串、已知头识别和多版本对比 | 用户显式设置基地址；定位差异区、字符串和空白段；不猜测芯片或加载地址 |
| P2 | 定时器/PWM | 从 PSC/ARR/CCR 计算结果 | 工程师更常需要“目标频率反求参数” | 输入目标频率/占空比；枚举候选 PSC/ARR；按误差和分辨率排序；支持上下计数 |
| P2 | ADC 与分压 | 原始码、电压和分压换算 | 容差、采样阻抗、校准和温漂 | 给出最坏/典型范围；采样电容充电风险；两点校准；电阻功耗和输入保护提示 |
| P2 | UART 传输时间 | 单一帧格式吞吐 | 突发、FIFO、协议开销和接收超时 | 批量长度/周期；总线占用；软超时区间；给出无法保证实时性的条件 |
| P2 | IEEE 754 | Float32 位模式 | Float16/64、NaN 细节、四种字节/字序 | 支持 16/32/64 位；ABCD/BADC/CDAB/DCBA；批量日志转换；异常值分类 |
| P2 | 进制转换 | 大整数与常见进制 | 位域、掩码、地址偏移、批量列表 | 位字段编辑；置位/清位掩码；基址+偏移；一列地址批量转换和导出 |

## 3. 当前迭代已经落实的部分

- 通信终端：串口、WebSocket、TCP/UDP 使用一致的 `HH:mm:ss.SSS` 时间戳、RX/TX/SYS 方向、日志上限和导出格式。WebSocket 与 TCP/UDP 具备暂停显示但继续接收、字节统计、HEX 显示和周期发送。
- Modbus：支持 CSV/TSV/TXT、Excel 表格复制、PDF/Word 可选文字表格复制；识别逗号、制表符、分号、竖线和多空格分列。
- Modbus 列映射：先展示前五行预览、自动匹配数量和置信度；非标准厂家列名由用户映射名称、地址、区域、类型、倍率、单位及端序，确认数据结构后再解析。
- CRC：保留原有 Modbus CRC16、CRC32 和端序结果；新增命名参数模型、自定义 width/poly/init/refin/refout/xorout、字节校验范围、最多 500 帧批量隔离计算以及带参数注释的 C 参考实现。
- 自定义协议帧：保留单帧生成与字段解析；新增最多 1 MiB、1000 帧的连续 HEX 拆包，支持噪声跳过、坏帧隔离重同步、不完整尾帧保留、有/无长度字段协议及 CSV 导出。
- HardFault：可粘贴不超过 1 MiB 的 Keil/IAR/GDB/串口文本，识别普通、`stacked_*`、`fault_*` 和 `SCB->*` 寄存器格式；显示原始行证据、缺失项、冲突值与置信度，确认后再应用到分析表单并联动 ELF。
- MAP：当前与基线 MAP 分别在后台解析；展示 Flash/RAM/Code/RO/RW/ZI 增减、增长/减少模块及符号差异；模块可继续下钻到内存分类、节区和符号。工具链口径不同或证据不足时自动降级，结果可导出不含原文和绝对路径的 JSON/CSV 证据。
- 能力边界：浏览器不把 PDF/DOCX/XLSX 二进制文件伪装为文本解析；扫描件明确要求 OCR；协议内容不自动保存或上传。

## 4. 实施顺序

### 检查点 A：高频定位工具

1. CRC 参数模型、批量帧与 C 代码生成。
2. 自定义协议的连续字节流拆包和字段级错误定位。
3. HardFault 多格式日志提取、地址批量传递到 ELF/MAP。
4. MAP 对比下钻到对象、库与符号，并输出优化证据。

验收要求：四个工具各包含至少一个真实输入样例、一个损坏输入、一个批量输入和一个可下载结果。

### 检查点 B：固件与总线数据

1. HEX/SREC/BIN 统一为带基地址的固件段模型。
2. 固件合并、比较、空洞和冲突共用一套可视化与导出。
3. DBC 接受 candump/CSV 批量日志；CAN 负载接受报文周期表。
4. ELF/MAP/固件比较可关联同一个构建版本，但保持独立入口。

### 检查点 C：设计计算器

1. Timer 从目标反求候选，并按误差/分辨率排序。
2. ADC 加入容差、源阻抗、校准和保护检查。
3. UART 加入突发与软超时预算。
4. 进制/Float 工具升级为批量和位字段工作流。

## 6. 禁止的“伪实用”实现

- 只有一个硬编码示例或只接受已经整理好的理想输入。
- 自动猜测厂家文档列含义后直接产生设备写入值。
- 扫描 PDF 没有 OCR 证据却显示“解析成功”。
- 只显示计算结果，不显示单位、输入范围、字节序和依据。
- 日志、表格或固件无限增长；坏行导致整批数据丢失。
- 要求创建项目才能使用本应独立的通信或工具功能。
- 浏览器工具无必要地依赖 Local Agent，或将 Agent 的开发者启动命令作为普通用户主流程。
