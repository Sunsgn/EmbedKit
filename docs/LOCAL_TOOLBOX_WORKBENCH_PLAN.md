# EmbedKit 本地嵌入式工作台实施方案

## 1. 产品定位

EmbedKit 是面向通用嵌入式开发的本地工程资料、程序分析、通信调试和确定性工具工作台。

它不接管 Keil、IAR、ESP-IDF 等已有工具的编译、调试和烧录流程，也不要求用户为了使用 EmbedKit 改变原有开发习惯。工程、固件、设备和测试之间允许按需关联，但任何关联都不能成为独立工具的前置条件，也不能在缺少真实证据时自动宣称关联成立。

协议识别、本地 AI、开发环境检测和自动化测试均作为可选能力保留，不作为产品中心。

## 2. 高频用户工作流

### 2.1 管理和理解工程

- 输入：用户选择的源码目录，或者手工创建的工程说明。
- 操作：有界扫描目录，识别工程结构、框架、入口、IDE 配置和已有产物；用户补充当前程序的实际功能。
- 输出：可持久化的工程说明、相对路径证据、识别覆盖率、未知项和可导出的分析结果。
- 失败处理：Agent 离线时仍可查看历史档案；目录授权失效时允许重新定位；未知工程降级为通用源码和文件结构分析。

工程档案不保存源码内容和本机绝对路径，不负责证明某台设备当前运行了某个固件。

### 2.2 查询资料

- 输入：芯片完整型号、器件类别、接口协议或开发主题。
- 操作：查询本地索引，并导航到带来源、适用范围和验证日期的官方资料。
- 输出：可以打开、收藏、复制和重新查询的资料记录。
- 失败处理：离线或没有结果时保留查询条件，不以聚合转载或推测参数冒充官方资料。

### 2.3 通信调试和确定性工具

- 输入：真实串口或网络数据，以及用户主动选择的 HEX、BIN、ELF、MAP、DBC、SVD、日志或协议文档。
- 操作：直接进入独立工具完成采集、解析、校验、转换或计算；需要本机权限的操作仅通过 Local Agent。
- 输出：原始数据、错误位置、计算依据，以及可复制或导出的结果。
- 失败处理：区分损坏格式、资源超限、权限不足、Agent 离线和设备断开；不相关的纯浏览器能力继续可用。

### 2.4 与现有 IDE 和 AI 协作

- Keil、IAR、ESP-IDF 等继续负责它们擅长的编辑、编译、仿真、调试和烧录。
- EmbedKit 可以读取用户主动提供的工程配置、源码、日志和构建产物，但不要求构建或烧录必须从 EmbedKit 发起。
- 本地工具负责确定性解析、严格校验、资源边界和证据导出；用户可以将结果交给任意 AI、同事或现有流程。
- 本地 AI 页面作为可选入口保留，未安装模型不得影响其他模块。

## 3. 明确不做的事项

当前阶段不把以下事项作为核心产品能力：

1. 再实现一套 IDE、编译器、调试器或烧录器；
2. 为 Keil、IAR 等已经稳定配置的软件建立强制环境管理流程；
3. 仅为包裹现有命令而制作另一套构建和烧录按钮；
4. 在没有设备侧或用户确认的证据时，推断设备当前固件与某个工程产物一致；
5. 强制用户创建工程、配置设备或连接 AI 后才能使用通信和文件工具。

既有构建、环境检测和安装能力继续兼容，但降为高级按需入口；后续只有在真实用户工作流能证明收益时才扩展适配器。

## 4. 信息架构

第一层日常入口：

1. 工程中心与工程分析；
2. 资料中心与学习中心；
3. 通信调试与嵌入式工具箱；
4. 数据管理与可选 AI 协作。

第二层按需能力：开发环境检测、集成测试、本地助手以及既有高级构建能力。所有现有路由和旧数据继续兼容。

工程中心用于记录程序功能、目录结构、识别证据和用户已有材料。软件版本只作为可选备注，不作为打开工程、执行分析或使用工具的条件。

## 5. 实施顺序

### P0：入口与边界收敛

- 首页和导航突出工程分析、资料、通信和确定性工具；
- 开发环境检测降为按需能力；
- 页面明确不接管 IDE 编译和烧录；
- 保留所有既有路由、数据和可独立入口。

### P1：工程材料与陌生程序分析

- 完善程序功能说明、工程结构、入口和执行流程识别；
- 每项结论保留文件、行号、规则、覆盖率、可信度和未知项；
- 支持用户主动导入已有 MAP、ELF、日志等材料独立分析；
- 未知平台安全降级，不猜测芯片、RTOS 或工具链。

### P2：资料检索与导航

- 保留并完善芯片、元器件、官方文档和教程查询；
- 标注来源、版本、适用范围和验证日期；
- 支持从分析结论跳转到相关资料，但不要求先创建工程。

### P3：确定性结果交接

- 统一工具的复制、JSON、CSV 或 HTML 导出约定；
- 导出记录工具版本、输入摘要、时间、结论类型和能力边界；
- 提供适合交给 AI 或同事的最小证据包，但不自动上传本地数据。

## 6. 完成判定

- 新用户能直接进入工程分析、资料查询、通信调试和独立工具；
- 不通过 EmbedKit 编译或烧录，也能导入真实材料并得到可核验结果；
- Agent 离线时导航、工程档案、历史结果和纯浏览器工具正常工作；
- AI 未配置时不阻塞其他功能；
- 既有环境检测、构建和测试能力仍可从按需入口使用；
- 首页和导航回归测试、类型检查、代码检查及 GitHub Pages 隔离构建通过；
- 后续能力以减少查资料、理解陌生工程、处理数据和重复验证的时间为验收指标，不以页面或功能数量为完成标准。
