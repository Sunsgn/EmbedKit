# AI 嵌入式产品开发约束包

- 约束包版本：V3.0.0
- 使用人员：嵌入式开发工程师
- 使用目标：把约束包和一句需求交给AI，由AI按阶段推进、过门禁、交模板并更新交接包
- 适用：裸机、事件驱动、RTOS、嵌入式Linux及软硬件产品

## 1. 首次使用闭环

1. 将完整约束包放在项目可读取的稳定位置；推荐项目内`.ai/AI嵌入式产品开发约束包/`，也可使用只读公共路径，并记录版本。
2. 第一次只让AI读取README、00、00A、00B、00C、00D，不读取全部技术分册。
3. AI必须先输出：约束包版本、整体层文件检查结果、版本冲突和`[当前状态卡]`。
4. 出现`[约束包初始化确认]`且无版本冲突后，工程师再给一句需求；同一条消息已含需求时，AI从00的S0开始执行。
5. 后续会话按00D读取上一次交接包，只加载“下一步允许动作”对应章节。

```text
[约束包初始化确认]
版本：V3.0.0
整体层：00 / 00A / 00B / 00C / 00D 已读取
版本冲突：无 / <清单>
下一步：等待一句需求 / 执行S0
```

## 4. 读取规则

- 首次：整体层 → 项目输入分册 → 当前阶段分册章节 → 当前所需模板。
- 后续：整体层 → 上次交接包 → 唯一下一动作对应章节。
- 只报告触发规则ID、证据位置、未关闭项和下一步；不复制规则正文、门禁表或已完成全文。
- `S-*`是停止规则，`M-*`是强制规则，`C-*`是条件规则；只报告实际触发的ID。
- 版本和升级执行00D；规则冲突执行00的`M-CONFLICT-001`。
