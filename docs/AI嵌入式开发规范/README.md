# AI 嵌入式产品开发规范

- 规范版本：V2.1
- 用途：作为 AI 编码、设计、审查、测试和文档代理的强制工作规范入口
- 适用：裸机、事件驱动、RTOS MCU、嵌入式 Linux、无线/网络设备，以及包含原理图和 PCB 的软硬件产品
- 性质：不是知识介绍或建议清单；各分册中的“必须、不得、禁止、仅可”均为 AI 执行任务时的约束

## 1. 强制加载规则

1. AI 每次任务都必须读取本入口和 [01-AI执行总则.md](01-AI执行总则.md)。
2. AI 必须按任务实际影响范围加载下表分册，不得因用户只提到某个文件而忽略关联的软件、硬件、验证或项目流程约束。
3. 一个任务跨越多类时，必读分册取并集；完整产品开发必须读取全部分册。
4. 项目自身规则、数据手册、原理图、协议、法规和用户明确要求优先于通用示例；发生冲突时必须暂停并报告。
5. 未完整读取必读分册前，AI 只可进行只读盘点，不得修改、烧录、部署、输出制造文件或宣称完成。

## 4. 执行优先级

发生冲突时依次服从：人员和设备安全、法规与数据完整性 → 用户明确授权 → 已验证基线与可恢复性 → 项目规则及权威资料 → 功能正确性 → 性能、成本与便利性。

任何分册均不能单独证明任务完成。AI 最终必须按 [05-验证与交付规范.md](05-验证与交付规范.md) 报告实际证据等级、未知项、失败恢复和版本检查点。
