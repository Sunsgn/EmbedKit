# 软件编程技术规范

## 1. 软件设计通用约束

1. 先确定所属层：硬件 → Boot/电源/时钟 → 驱动/DTS/RTOS 端口 → 服务/传输 → 协议/状态机 → 业务；问题在哪一层就在该层修复。
2. 明确外设、状态、缓冲、采集源、线程、任务和进程的唯一所有者。
3. 为输入定义格式、单位、上限和信任边界；为输出定义可核验结果；为失败定义错误码、恢复和最终状态。
4. 队列、缓冲、帧、日志、文件、重试、等待、任务、线程和连接必须有上限。
5. 设计必须覆盖启动、就绪、运行、取消、停止、超时、异常、重启、恢复和升级。
6. 平台差异必须放入板级配置、适配器或驱动，不得在通用业务层写死具体芯片、OS、节点、端口和工程路径。
7. 配置、持久化、IPC 和对外接口必须版本化，并提供兼容读取、安全迁移或明确拒绝。
8. 调试入口、临时标识、后门和敏感日志不得遗留在量产默认配置。

## 2. 编码规范

- 外部长度、索引、偏移、枚举、路径、URL 和版本必须先校验再使用。
- 整数运算必须检查溢出和下溢，特别是 `offset + length`、尺寸、计数器和时间换算。
- 必须显式处理字节序、符号、对齐、位宽、缩放和单位；不得把不可信字节直接强转为结构体。
- 不得静默吞错；错误必须可分类、可观测并具有最终处理。
- 不得使用无限重试、无限等待、无界队列或超长固定延时掩盖状态机问题。
- 动态资源必须在成功、失败、取消和超时路径释放；组件卸载后不得继续回调或更新状态。
- 公共模块必须有稳定接口和测试；不得在页面、业务层或脚本中复制底层协议及硬件逻辑。
- 注释解释约束、依据和不明显的取舍；危险参数必须关联需求或权威资料。
- AI 生成代码必须遵循仓库既有语言、格式、静态检查和告警策略，不得关闭检查来掩盖缺陷。

## 3. MCU、裸机与 RTOS

- 修改驱动前核对原理图、数据手册、SDK 端口、管脚、电平、时钟、电源域和复位顺序。
- ISR/高优先级回调只确认、采集和投递；禁止阻塞、动态内存、长日志和复杂业务。
- 使用正确的 FromISR/临界区 API，并核对中断优先级、可抢占关系和最坏响应时间。
- 一个外设由一个任务或模块拥有，业务通过有界消息或事务访问。
- 启动依赖用事件或就绪状态表达；确需延时时必须写明依据和超时。
- 锁范围最小、顺序固定、等待有界；队列满必须定义拒绝、覆盖、合并或降级策略。
- 必须记录任务栈高水位、堆低水位、分配失败、队列峰值和看门狗复位原因。
- DMA 必须核对缓冲生命周期、对齐、Cache 一致性、并发所有权和完成后的业务校验。
- 安全阈值、通道映射和执行时序不得凭代码猜测修改，必须有硬件、标准或试验证据。
- 本地安全控制不得依赖云端、网络、日志或升级任务可用。

## 4. 嵌入式 Linux

- 区分硬件、Bootloader、Kernel、DTS、驱动、rootfs、原生程序、脚本和业务应用的权威位置。
- 用户态不得用寄存器写入、脚本或格式转换长期规避 DTS、驱动或物理连接问题。
- 不得固定易变 `/dev/*N`；应使用设备属性、拓扑、稳定链接或版本化状态接口。
- 预编译二进制必须关联源码、SDK、工具链、ABI、构建命令和 SHA-256；无源码时不得声称可维护修改。
- 不得把主机开发环境或完整依赖目录复制到目标机；必须检查 ELF 架构、sysroot、动态依赖和实际导入。
- IPC 必须定义版本、类型、长度上限、短读/写、EOF、超时、背压、重连和权限。
- 启动脚本必须使用精确进程所有权，禁止宽泛进程名终止，防止重复实例和失控任务。
- 必须监测 CPU、RSS/PSS、FD、线程、磁盘、日志、吞吐、延迟、温度和 OOM。
- 部署先暂存和校验，再原子安装或切换；记录源、暂存、安装与回读哈希。

## 5. 通信、存储、升级与安全

- 接收链按“有界收取 → 帧界 → 完整性/版本 → 字段 → 语义 → 业务”分层。
- 必须测试半包、粘包、超长、非法字符、CRC 错、重复、乱序、重放、超时和断线。
- 区分入队、发出、链路 ACK 和业务成功；事务包含 ID、来源、截止时间、有限重试和最终状态。
- 持久化包含 magic、版本、长度、校验和提交状态，并覆盖掉电、损坏、容量、寿命和迁移。
- 唯一标识、校准、密钥和生产 NV 必须与普通应用数据及 OTA 分离保护。
- OTA 必须校验产品、硬件、基线、版本、长度、分区、哈希和签名，并覆盖断电、断网、低内存、乱块、首次启动失败和回滚。
- 分块或流式算法不得削弱完整性与认证算法。
- 不得读取、记录、提交或回显非必要秘密；外部输入验证后才能进入命令、路径、Flash、协议或设备操作。
- 进程执行应参数化并限制工作目录与目标路径，禁止用未校验字符串拼接 Shell 命令。
