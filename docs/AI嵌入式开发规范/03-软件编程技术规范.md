# 软件编程技术规范

## 1. 通用设计与接口

| ID | 触发条件 | AI 必须执行 | 验证点 |
| --- | --- | --- | --- |
| M-SW-ARCH-001 | 新增模块或服务 | 定义职责、输入、输出、所有者、生命周期和禁止依赖 | 接口/调用图可回溯 |
| M-SW-ARCH-002 | 平台存在差异 | 差异放入板级配置、驱动或适配器 | 业务层无芯片/OS特例 |
| M-SW-ARCH-003 | 对外接口或公共模型变化 | 版本化并提供兼容读取、迁移或明确拒绝 | 旧版本回归 |
| M-SW-ARCH-004 | 状态跨任务/线程/进程 | 指定唯一写入者和一致性模型 | 并发测试或静态证明 |
| M-SW-ARCH-005 | 长任务或外设操作 | 定义开始、进度、取消、超时、完成和资源释放 | 取消/超时测试 |

接口定义必须包含单位、范围、字节序、所有权、可空性、错误和线程/中断上下文。只写类型名不算完成。

## 2. 输入、算术和内存

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-SW-IN-001 | 数据来自设备、网络、文件、用户或持久化 | 在进入业务前校验长度、类型、版本、枚举、范围和完整性 |
| M-SW-IN-002 | 处理 `offset + length`、乘法尺寸或时间换算 | 在运算前检查溢出/下溢，并使用明确宽度类型 |
| M-SW-IN-003 | 解析二进制 | 显式处理字节序、符号、对齐和位宽；不得直接强转不可信缓冲 |
| M-SW-MEM-001 | 使用动态内存 | 定义最大分配、失败行为和所有退出路径释放 |
| M-SW-MEM-002 | 使用缓冲、队列、日志或文件 | 定义单项上限、总上限、满载策略和可观测计数 |
| M-SW-MEM-003 | 处理大文件或连续数据 | 使用分块、流式或增量处理；定义取消和峰值内存 |
| M-SW-MEM-004 | 涉及敏感数据 | 最小读取、日志脱敏、受控保存，并在不再需要时清理 |

资源上限必须来自 [06-项目变量模板.md](06-项目变量模板.md) 或测量；未知时不得随意设置“足够大”的值。

## 3. 错误、时间和状态机

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-SW-ERR-001 | 调用可能失败 | 检查返回值并映射为配置、权限、设备、协议、资源、超时或系统错误 |
| M-SW-ERR-002 | 错误可重试 | 规定最大次数、退避、截止时间和重试耗尽后的最终状态 |
| M-SW-ERR-003 | 错误不可恢复 | 保存首个根因和必要上下文，进入明确安全/降级状态 |
| M-SW-TIME-001 | 使用延时或超时 | 说明时基、单位、范围、溢出行为和依据；禁止用长延时掩盖状态问题 |
| M-SW-TIME-002 | 使用计数器或 tick | 处理回绕并避免有符号/无符号混算 |
| M-SW-STATE-001 | 存在三种以上状态或异步事件 | 显式定义状态、事件、守卫、动作、超时和非法转换 |
| M-SW-STATE-002 | 系统重启或断线 | 定义恢复来源、幂等行为和旧事务处理 |

不得静默吞错、无限重试、无限等待或只打印日志后继续运行。

## 4. 并发、ISR 与 DMA

| ID | 触发条件 | AI 必须执行 | 禁止行为 |
| --- | --- | --- | --- |
| M-SW-CON-001 | 多上下文访问同一资源 | 指定唯一所有者；其他上下文通过有界消息、事务或受控同步访问 | 多任务直接操作同一外设 |
| M-SW-CON-002 | 使用锁 | 固定加锁顺序、最小范围、有限等待和超时诊断 | 持锁执行阻塞 I/O 或未知回调 |
| M-SW-CON-003 | 队列可能满 | 选择拒绝、覆盖、合并、背压或降级，并记录丢弃 | 默认无限增长 |
| M-SW-ISR-001 | 中断/高优先级回调 | 只采集、清标志和投递；核对专用 API 与优先级 | 阻塞、动态分配、长日志、复杂业务 |
| M-SW-DMA-001 | 使用 DMA | 核对缓冲生命周期、对齐、Cache、所有权、长度和完成校验 | DMA 未结束就复用缓冲 |
| M-SW-DMA-002 | DMA 数据异常 | 先保存原始数据并核对物理位、控制器位、长度和同步 | 先用格式转换掩盖缺位 |

## 5. MCU、裸机与 RTOS

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-SW-MCU-001 | 修改外设驱动 | 核对原理图、引脚、电平、时钟、电源域、复位和手册时序 |
| M-SW-MCU-002 | 创建任务、队列、锁或定时器 | 检查创建结果，定义失败处理和对象销毁/长期归属 |
| M-SW-MCU-003 | 调整任务优先级或栈 | 基于最坏响应和栈高水位；记录调整前后数据 |
| M-SW-MCU-004 | 启动依赖其他模块 | 使用事件/就绪状态和超时，不用固定延时表示就绪 |
| M-SW-MCU-005 | 启用看门狗 | 记录喂狗责任、复位原因和首个失败点；不得无条件喂狗 |
| M-SW-MCU-006 | 进入低功耗 | 检查事务、DMA、Flash、时钟和唤醒源；按阶段恢复并记录失败点 |
| M-SW-MCU-007 | 修改安全阈值/通道/时序 | 关联硬件版本、需求和试验记录；缺失时触发停止规则 |

发布构建应保留低成本的栈/堆低水位、队列峰值、分配失败和复位原因诊断。

## 6. 嵌入式 Linux

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-SW-LNX-001 | 修改设备访问 | 从 sysfs、拓扑、属性或稳定链接发现设备；禁止固定易变 `/dev/*N` |
| M-SW-LNX-002 | 修改 DTS/驱动相关功能 | 区分硬件、Bootloader、Kernel、DTS、驱动、rootfs 和用户态权威位置 |
| M-SW-LNX-003 | 使用预编译程序/库 | 记录源码、SDK、工具链、ABI、依赖、构建命令和 SHA-256；缺源码则标风险 |
| M-SW-LNX-004 | 部署依赖 | 使用目标 sysroot/配方和白名单；检查 ELF 架构及实际导入 |
| M-SW-LNX-005 | 启停进程 | 使用 PID/cgroup/服务身份，只停止本服务拥有的实例，且有超时 |
| M-SW-LNX-006 | 长期运行 | 监测 CPU、RSS/PSS、FD、线程、磁盘、日志、吞吐、延迟、温度和 OOM |
| M-SW-LNX-007 | 安装更新 | 暂存、校验、原子切换并记录源/安装/回读哈希；失败可回退 |

用户态脚本和寄存器写入只能用于有记录的临时诊断，不得长期绕过 DTS、驱动或物理连接问题。

## 7. 通信、IPC、存储与升级

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-SW-PROTO-001 | 接收字节流 | 按有界收取、帧界、完整性/版本、字段、语义、业务分层 |
| M-SW-PROTO-002 | 流式 IPC/Socket/FIFO | 处理短读写、粘包、EOF、超时、背压、取消、重连和最大帧 |
| M-SW-PROTO-003 | 请求具有业务结果 | 区分入队、发出、链路 ACK 和业务成功；使用事务 ID 和最终状态 |
| M-SW-PROTO-004 | 协议可被重复或乱序 | 定义幂等、序号、过期、重放和冲突处理 |
| M-SW-NV-001 | 保存持久化数据 | 包含 magic、版本、长度、校验和提交状态；处理半写和旧版本 |
| M-SW-NV-002 | 写入 Flash/EEPROM | 计算容量、写入频率和寿命；容量满必须有策略 |
| M-SW-OTA-001 | 固件升级 | 校验产品、硬件、基线、版本、长度、分区、哈希和签名 |
| M-SW-OTA-002 | 升级可中断 | 覆盖断电、断网、低内存、重复/漏/乱块、首次启动失败和回滚 |

唯一标识、校准、密钥和生产 NV 必须与普通应用数据及 OTA 分离保护。

## 8. 软件完成记录

软件任务交付时只填写实际项：接口变化、资源上限、失败路径、兼容/迁移、定向测试、实机待验证项和回退方法。缺少任一被触发项时不得标记为完成。
