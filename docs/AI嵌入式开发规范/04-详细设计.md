# 详细设计

## 快速摘要

- 解决：把已确认架构细化为软件结构、器件/接口设计、原理图约束和可执行验证点。
- 读取：F3详细设计、设计冻结前评审，或接口/器件/关键配置变化时。
- 产出：设计记录、选型依据、原理图评审、风险和影响检查。

## 任务路由

| 当前任务 | 只读章节 |
| --- | --- |
| 软件结构、模块接口或并发所有权 | 1 |
| 硬件开工边界或选型 | 2～3 |
| 电源、时钟、复位、模拟或外部接口 | 4～5 |
| 原理图评审 | 6 |
| 变更影响检查 | 7 |

## 不读本分册的情况

当前阶段未触发F3；交接包确认设计阶段未变且无新增未知项；普通代码修改不改变架构、器件、引脚、协议、存储格式或工具链。

## 1. 软件结构与接口

| ID | 触发条件 | AI 必须执行 | 验证点 |
| --- | --- | --- | --- |
| M-SW-ARCH-001 | 新增模块或服务 | 定义职责、输入、输出、所有者、生命周期和禁止依赖 | 接口/调用图可回溯 |
| M-SW-ARCH-002 | 平台存在差异 | 差异放入板级配置、驱动或适配器 | 业务层无芯片/OS特例 |
| M-SW-ARCH-003 | 对外接口或公共模型变化 | 版本化并提供兼容读取、迁移或明确拒绝 | 旧版本回归 |
| M-SW-ARCH-004 | 状态跨任务/线程/进程 | 指定唯一写入者和一致性模型 | 并发测试或静态证明 |
| M-SW-ARCH-005 | 长任务或外设操作 | 定义开始、进度、取消、超时、完成和资源释放 | 取消/超时测试 |

接口定义必须包含单位、范围、字节序、所有权、可空性、错误和线程/中断上下文。只写类型名不算完成。

## 2. 硬件开工与能力边界

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-HW-START-001 | 审查或修改硬件 | 确认 EDA/版本、板版、设计库、叠层、规则、网表同步、输出基线和回退 |
| M-HW-START-002 | 提出器件或参数 | 给出输入、计算、裕量、适用条件和待实测项；输入未知则只给参数化候选 |
| M-HW-START-003 | 高压、大电流、射频、安全或关键电源 | 标为需责任工程师复核，AI 不得自行放行 |
| M-HW-START-004 | 仅有截图/PDF而无源设计 | 只做可见范围评审，列出无法检查的网络、规则和一致性风险 |

ERC/DRC、仿真和视觉检查均不能替代样机验证。

## 3. 器件、符号与封装

| ID | 触发条件 | AI 必须执行 | 验证证据 |
| --- | --- | --- | --- |
| M-HW-PART-001 | 新增/替换器件 | 核对功能、工作/绝对额定、温度、精度、速度、功耗、生命周期和合规 | 选型对比表 |
| M-HW-PART-002 | 使用符号 | 逐项核对引脚号、名称、方向、隐藏电源脚、EP、NC/DNC和保留脚 | 引脚核对记录 |
| M-HW-PART-003 | 使用封装 | 核对焊盘号、尺寸基准、方向、Pin1、EP、庭院和装配高度 | 封装核对/3D检查 |
| M-HW-PART-004 | 使用替代料 | 比较电气、时序、引脚、封装、热、软件和认证兼容性 | 差异及验证计划 |
| M-HW-PART-005 | 自建库 | 记录资料版本、尺寸来源、创建者、复核状态和适用器件 | 库元数据 |

仅名称相同、封装外形相似或供应商标注“兼容”不能作为等价依据。

## 4. 电源、时钟、复位与启动

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-HW-PWR-001 | 任一电源轨 | 记录来源、范围、正常/峰值负载、时序、纹波、效率、温升、保护和测点 |
| M-HW-PWR-002 | 稳压/开关电源 | 按手册核对输入输出电容、补偿、反馈、限流、最小负载和布局敏感环路 |
| M-HW-PWR-003 | 电源域交互 | 检查上电/掉电回灌、失电钳位、域间容限和启动期间默认态 |
| M-HW-PWR-004 | 外部供电入口 | 检查反接、过压、欠压、过流、短路、浪涌、ESD 和保险/限流配合 |
| M-HW-CLK-001 | 时钟源 | 核对频率、精度、负载、驱动、电平、启动时间、布局和失效行为 |
| M-HW-RST-001 | 复位/启动配置 | 定义上电、掉电、看门狗、外部复位、调试和量产启动状态 |

去耦和储能不得只按“每个芯片放一个”处理；必须关联具体电源脚、瞬态电流和回路位置。

## 5. 数字、模拟与外部接口

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-HW-IO-001 | 任一外部/跨模块接口 | 标明方向、电平、默认态、上下拉、驱动、速率、端接、针序和热插拔条件 |
| M-HW-IO-002 | 跨电压域 | 核对 VIH/VIL/VOH/VOL、容限、方向、时序和失电状态 |
| M-HW-IO-003 | 开漏/三态/复用/启动脚 | 检查复位前、启动中、正常运行和掉电阶段，防止误动作 |
| M-HW-ANA-001 | ADC/DAC/传感/参考 | 建立量程、源阻抗、采样时间、偏置、噪声、滤波、精度和校准预算 |
| M-HW-PROT-001 | 接口暴露到板外 | 根据环境检查 ESD、浪涌、共模、反接和误插，并评估保护器件寄生影响 |
| M-HW-TEST-001 | 关键电源、总线或配置 | 预留可访问测点/分断点，并控制量产调试权限 |

## 6. 原理图审查

| ID | 检查项 | 通过条件 |
| --- | --- | --- |
| M-HW-SCH-001 | 层次与网络 | 功能页清晰、网络名有语义、跨页可追踪、方向一致 |
| M-HW-SCH-002 | 参数 | 关键阻容、精度、功率、耐压、封装和装配选项完整 |
| M-HW-SCH-003 | 配置 | 上下拉、跳线、DNP 和启动配置具有真值表或状态说明 |
| M-HW-SCH-004 | 未连接/豁免 | 每个 NC、未连接、ERC 豁免和规则例外有独立理由 |
| M-HW-SCH-005 | 软硬件一致性 | 引脚、极性、地址、位序、时钟和中断与软件配置一致 |

评审问题必须记录页码/位号/网络、风险、建议、责任状态和关闭证据，不能只写“注意检查”。

## 7. 改动影响速查（M-FLOW-005）

| 变更对象 | 必查文件/配置 | 必查测试 |
| --- | --- | --- |
| 需求/安全状态 | 需求、架构、原理图、软件配置、说明和生产配置 | 验收、安全状态和失败路径 |
| 器件/封装/BOM | 数据手册、库、原理图、PCB、BOM和驱动配置 | 电气、功耗、热、驱动和产测 |
| 引脚/时钟/电源 | 原理图/PCB、引脚与时钟配置、板级初始化、低功耗和产测配置 | 启动、复用、电平、时序、低功耗和产测 |
| 协议字段/接口 | 协议定义、生产者/消费者、编解码、版本、日志和兼容配置 | 正常帧、非法帧、版本兼容、分包粘包和恢复 |
| 存储格式/分区 | 格式/分区定义、读写代码、默认配置、迁移、回滚和恢复工具 | 新旧版本、损坏、容量、掉电、迁移和回滚 |
| 工具链/SDK/EDA | 锁定版本、工程配置、生成脚本、ABI、告警基线和发布清单 | 干净构建、生成物对比、ABI/兼容和回归 |

AI只需检查实际可能受影响的下游，但必须说明排除其他项的依据。
