## 4. 目录授权边界

1. `NEW`只按目录框架创建根文件、`.ai/`、`program/`、`开发文档/`、`硬件原理图PCB/`和`测试/`的最小基线；二级和其他一级分支仅在本阶段已有真实产物或近期用途时启用。
2. `ORGANIZE`必须走目录框架两轮闭环；本表的目标路径不能替代迁移映射、哈希、引用检查和破坏性操作确认。
3. `EXTEND`只创建当前交付物需要的分支，不补齐兄弟目录。
4. `AUDIT`保持只读；不得因模板或映射表存在而创建目录和文件。
5. `program/`内的完整源码工程保持原结构；不得按本表把工程内部`docs/tests/tools/build`拆到项目级目录。
6. 移动、覆盖、删除、清理、生产配置、`git add/commit/push`继续服从目录框架和01的授权边界。
