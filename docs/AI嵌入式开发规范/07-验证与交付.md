# 验证与交付

## 快速摘要

- 解决Bring-up、测试取证、故障诊断和交付检查点问题。
- 在F5～F7或任何需要验证、诊断、发布证据的任务中读取。
- 读完必须产出Bring-up记录、测试记录或发布记录，并标明实际证据等级。
- E0～E5定义与阶段门禁统一查[00B-门禁与证据总表.md](00B-门禁与证据总表.md)。

## 任务路由

| 当前任务 | 只读章节 |
| --- | --- |
| Bring-up | 1 |
| 选择最小验证范围 | 2～3 |
| 写测试记录或判定证据 | 4及00B |
| 故障诊断 | 5 |
| Git、EDA、部署或发布交付 | 6～7 |

## 不读本分册的情况

- 当前阶段未触发验证、诊断、Bring-up或交付。
- 交接包已说明阶段未变且没有新增验证未知项。
- 普通代码修改在尚未进入验证动作前不读本分册。

## 1. Bring-up顺序

| 步骤 | 进入条件与动作 |
| --- | --- |
| B1 无源检查 | 核对板号、装配、短路、阻值、极性和可见缺陷 |
| B2 限流上电 | 使用已确认电源、限流和停止条件，记录各电源轨原始值 |
| B3 基础启动 | 检查时钟、复位、启动脚和调试连接 |
| B4 最小固件 | 只启用建立基础可观测性所需的最小功能 |
| B5 外设总线 | 逐项验证电气层、时序、协议和失败恢复 |
| B6 系统业务 | 在下层证据关闭后验证完整业务、异常与资源边界 |

未通过当前步骤不得进入下一步骤；使用TPL-07记录进入条件、证据和恢复。

## 2. 按变更选择验证范围

AI 不得对所有任务机械执行全量测试，也不得只运行最容易通过的测试。先根据改动选择最小充分集合，再补受保护基线回归。

| 变更类型 | 最低验证 | 必须补充的失败路径 |
| --- | --- | --- |
| 文档/标签 | 链接、内容、构建或渲染检查 | 旧链接、空内容、编码 |
| 纯算法/解析器 | 单元测试、边界和损坏输入 | 超限、截断、未知格式、溢出 |
| 驱动/外设 | 构建、静态检查、回放/模拟、待实机步骤 | 超时、中断丢失、DMA、设备缺失、恢复 |
| 并发/状态机 | 状态转换、竞态、满队列、取消和反复启停 | 死锁、乱序、重复、资源耗尽 |
| 协议/IPC | 分包粘包、版本、最大帧、断线重连 | 非法帧、短读写、背压、重放 |
| 存储/配置 | 新旧版本、迁移、损坏、容量和掉电 | 半写、校验错、空间不足、回滚 |
| OTA/部署 | 安装、回读哈希、首次启动和回退 | 断电、断网、错误目标、旧基线 |
| 原理图/PCB | ERC/DRC、网络、库、制造和受影响电气检查 | 错件、极性、电源异常、返工和板版差异 |
| 安全功能 | 需求追踪、故障注入、独立保护和回退 | 传感器故障、通信失败、矛盾输入 |
| 发布/生产 | 锁定依赖、完整构建、回归、manifest 和批准 | 恢复演练、错误批次/板版、旧数据 |

### 最小验证命令表（M-VER-009）

命令使用项目已确认的工具链和脚本；未登记命令时只写操作类型和待确认入口，不臆造命令。

| 变更类型 | 最小命令/操作 | 预期输出 | 达不到时证据等级 |
| --- | --- | --- | --- |
| 纯算法 | 定向单元测试命令；补边界、损坏和超限输入 | 相关用例通过，失败用例能复现并关闭 | 无法执行时仅E0；主机测试通过为E2 |
| 驱动 | 目标构建/静态检查；回放或模拟；列出待实机步骤 | 构建无新增错误，超时/设备缺失/恢复路径有结果 | 仅构建为E1；回放为E2；无实机不得报E3 |
| 协议 | 定向协议测试或抓包回放；覆盖分包、粘包、非法帧和版本 | 编解码、错误分类、重连/恢复符合预期 | 仅静态为E0/E1；主机回放最高E2 |
| 存储 | 迁移/兼容测试；损坏、容量、半写或掉电模拟 | 新旧版本、失败恢复和回滚结果可复现 | 仅格式检查为E0/E1；主机模拟最高E2 |
| 硬件相关代码 | 目标构建；主机模拟；按板号/固件执行台架步骤 | 构建通过且原始实测值、日志和恢复结果可追溯 | 无台架证据最高E1/E2；只有实机结果可报E3 |

## 3. 原子验证规则

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-VER-001 | 修改解析、计算或状态逻辑 | 增加能在修改前失败、修改后通过的回归用例 |
| M-VER-002 | 修改失败处理 | 实际触发失败路径，检查错误分类、最终状态和资源释放 |
| M-VER-003 | 修改资源使用 | 记录正常、峰值、上限和超限行为；不能只看平均值 |
| M-VER-004 | 修改持久化或协议 | 覆盖旧版本、未知版本、损坏输入和兼容/迁移 |
| M-VER-005 | 修改硬件相关代码 | 区分主机证据和实机证据，提供精确待实机步骤 |
| M-VER-006 | 测试无法执行 | 记录阻塞原因、未验证风险、替代检查和恢复后执行命令 |
| M-VER-007 | 测试失败 | 不得把任务标为完成；先判断是实现缺陷、环境问题还是既有失败 |
| M-VER-008 | 全量测试成本过高 | 先执行定向测试，里程碑或发布时再执行全量回归 |

## 4. 单条测试记录

```text
测试 ID：
关联需求/规则/缺陷：
对象版本：源码、固件、板号、配置、工具
前置条件：
输入与操作：
预期：可测量结果
实际：原始值或日志位置
结论：通过 / 失败 / 阻塞 / 不适用
证据等级：E0-E5
资源数据：
失败定位与恢复：
失败动作/命令与退出状态：
失败证据或原始输出位置：
已尝试恢复及结果：
重试前置条件：
```

只写“测试通过”不是有效记录；结论为“失败”时，新增的四个失败交接字段必须填写，并带入00D交接包。

证据等级的唯一正文见[00B-门禁与证据总表.md](00B-门禁与证据总表.md)；AI只报告实际达到的等级，并写明对象版本和覆盖范围。

## 5. 故障诊断规则

| ID | AI 必须执行 |
| --- | --- |
| M-DIAG-001 | 冻结原始日志、波形、抓包、转储、板号、版本、配置和时间线 |
| M-DIAG-002 | 从最近变更和已验证基线差异开始，建立可证伪假设 |
| M-DIAG-003 | 每次实验只改变一个主要变量，记录预期、实际和结论 |
| M-DIAG-004 | 保存已排除路径；无新证据不得重复相同实验 |
| M-DIAG-005 | 证据指向物理连接或能力缺失时，停止上层延时、重试和格式补偿 |
| M-DIAG-006 | 区分根因、触发条件、放大因素和最终现象，不把最后一个错误当根因 |

## 6. Git、EDA 与交付检查点

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-DEL-001 | 修改前 | 记录状态，识别用户修改、生成物和受保护基线 |
| M-DEL-002 | 修改完成 | 审计差异，只保留当前任务文件，不提交日志、缓存、密钥和无关产物 |
| M-DEL-003 | 测试通过且项目要求检查点 | 创建单一目标提交，记录提交号和验证结果 |
| M-DEL-004 | 存在无关或无法拆分的重叠改动 | 不擅自提交，报告具体冲突 |
| M-DEL-005 | 原理图/PCB/制造输出 | 记录 EDA、库、板版、BOM、制造文件版本和哈希 |
| M-DEL-006 | 部署/烧录/发布 | 确认目标、当前版本、备份、回退、停止条件和授权 |

## 7. 完成判定

任务只有同时满足以下项目才能标记“完成”：

- 用户要求的实际工作流可执行，不只是存在入口或示例；
- 正常和被触发的失败路径已验证；
- 输入、资源和历史数据具有明确上限或兼容处理；
- 结果能复制、导出、定位或关联原始证据；
- 未验证项、能力边界和恢复方法已写明；
- 差异经过审计，相关测试通过，检查点符合项目规则。

若只完成部分，必须标记“部分完成”并列出剩余门禁，不得用模糊措辞弱化。

最终交接格式的唯一正文见[00D-交接包与状态模板.md](00D-交接包与状态模板.md)，具体交付物骨架见[09-交付物模板库.md](09-交付物模板库.md)。
