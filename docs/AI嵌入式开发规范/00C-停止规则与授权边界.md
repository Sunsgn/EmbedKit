# 停止规则与授权边界

本文件是停止、恢复、工程师决定权和高影响操作授权的唯一整体入口。触发任一停止规则时，AI停止受影响动作，但可继续不扩大风险的只读取证。

## 1. 停止与恢复

| ID | 停止条件 | 工程师恢复动作 | 确认后执行与记录 |
| --- | --- | --- | --- |
| S-AUTH-001 | 目标设备、板版、分区、文件或PCB版本无法唯一确认 | 提供稳定ID、版本、路径或现场标识 | 重新核对唯一目标，只对确认对象执行并记录标识 |
| S-AUTH-002 | 删除、覆盖、全量擦除、改板、破坏性迁移或不可恢复操作未获授权 | 确认精确目标、影响、备份和恢复方案并授权 | 仅执行获批范围，记录差异、备份和恢复结果 |
| S-AUTH-003 | 安全阈值、危险输出、额定值、安规距离、阻抗或生产参数来源不明 | 提供权威来源、适用对象和批准值 | 核对来源并记录版本，再恢复受阻步骤 |
| S-AUTH-004 | 协议、硬件、EDA、SDK或工具链版本冲突并会改变实现 | 指定权威版本或给出兼容决策 | 记录决策和影响，按选定版本重做受影响检查 |
| S-AUTH-005 | 目标位置有重叠的用户未提交修改且无法安全合并 | 说明改动归属及保留、隔离或合并方式 | 只处理确认范围，记录未触碰项 |
| S-AUTH-006 | 需要秘密、生产唯一值、采购、打样、认证、签名或正式发布权限 | 由责任人提供授权；秘密使用批准的安全通道 | 只执行授权动作，记录批准人和范围，不记录秘密值 |
| S-AUTH-007 | 没有受保护基线、备份、恢复通道或明确停止条件 | 建立并确认基线、备份、恢复步骤和停止条件 | 验证恢复可用后继续，记录基线和证据 |
| S-AUTH-008 | 继续操作可能扩大人员、设备、数据或法规风险 | 进入安全状态并由责任人决定处置 | 风险关闭或明确批准后恢复，记录决定和剩余风险 |

恢复后从停止发生的动作继续，不重新自由规划，不跳过未关闭门禁。

## 2. AI不得替工程师决定

| ID | AI可以做 | AI不得做 |
| --- | --- | --- |
| M-DEC-001 | 对器件型号、通信协议、RTOS、分区、超时和栈给出候选、依据与影响 | 自行选定并写入项目基线 |
| M-DEC-002 | 把建议值标为“待确认”，报告门禁证据和待批准状态 | 把建议值写成已确认，或把“AI建议通过”写成“门禁已通过” |

输入未知时执行02的输入规则；采购、打样、试产、量产、认证、签名、OTA发布和危险实机操作必须由责任人批准。

## 3. 文件、目录与Git授权边界

| 操作 | 默认权限 | 执行边界 |
| --- | --- | --- |
| 只读盘点、搜索、状态检查 | 允许 | 不改变文件、Git索引、设备或外部状态 |
| 创建当前任务所需的新文件/目录 | 条件允许 | 不覆盖，不伪造业务数据；目录位置服从10 |
| 移动或重命名 | 条件允许 | 先检查映射、引用和冲突；高影响或不确定时触发S-AUTH-002 |
| 删除、覆盖、擦除、清理 | 禁止自动执行 | 精确目标、影响、备份和恢复明确并取得单独确认 |
| 烧录、部署、生产配置 | 禁止自动执行 | 确认目标、当前版本、回退、停止条件和授权 |
| `git add` / `git commit` | 仅明确要求时允许 | 只包含本次范围，提交前审计差异 |
| `git push`、强推、改写历史 | 禁止自动执行 | 普通推送也需明确授权；强推或改写历史需单独确认 |

读取约束包、目录框架或用户提出“整理/修复”不等于获得上述高影响操作授权。

## 4. 工程师离线时的推进边界

| ID | 可以继续 | 必须停止并写入交接包 |
| --- | --- | --- |
| M-OFFLINE-001 | 已授权范围内的只读分析、证据整理、可回退检查，以及不写入项目基线的候选草案 | 需要工程师选择、确认默认值、扩大范围或关闭门禁 |
| M-OFFLINE-002 | 执行已明确授权且目标、停止条件和恢复方式未变化的非破坏性动作 | 删除、覆盖、烧录、部署、外部发布、实物危险操作、秘密处理或任何新增授权 |

工程师离线不改变当前F/G/B/E状态，也不把历史授权扩展到新目标；停止时记录已完成范围、失败或阻塞证据、唯一恢复动作和禁止动作。
