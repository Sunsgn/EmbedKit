# 项目变量模板

本模板用于保存已经从项目输入中提取并归一化的技术事实，不代替项目输入登记。新项目必须先执行 [01A-项目输入与立项.md](01A-项目输入与立项.md)，再按任务填写“最小事实包”；缺失字段必须标记未知，并执行对应降级或停止规则。

## 1. 最小事实包

| 任务 | 开工前至少需要 |
| --- | --- |
| T0 代码诊断 | 源码版本、构建目标、问题现象、日志/复现、只读范围 |
| T1 局部软件修改 | T0 + 工具链、入口/调用者、测试命令、回退基线 |
| T2 驱动/协议/存储 | T1 + 硬件/协议版本、资源上限、兼容数据、实机边界 |
| T3 原理图/PCB/Bring-up | 板版、原理图、PCB、BOM、数据手册、EDA、叠层、仪器和安全条件 |
| T4 发布/生产 | T3 + 发布对象、批次、签名/校准边界、完整回归、恢复和批准人 |

## 7. 未知项处理表

| 缺失事实 | AI 可以继续 | AI 不得继续 |
| --- | --- | --- |
| 芯片/SDK小版本 | 通用代码盘点、候选方案 | 写死寄存器、ABI 或启动配置 |
| 板版/原理图 | 业务逻辑分析、主机测试 | 修改管脚、电平、时钟、电源和驱动结论 |
| 资源上限 | 测量工具和参数化设计 | 选择固定队列、栈、帧和超时并宣称足够 |
| 安全阈值/法规 | 建立待确认项和测试框架 | 修改危险输出、阈值和保护逻辑 |
| 叠层/板厂能力 | 原理图审查和布局候选 | 确定阻抗、间距、孔径和制造放行 |
| 目标设备/恢复 | 只读分析 | 烧录、部署、擦除、重启和故障注入 |
| 发布批准人 | 准备发布包和检查清单 | 签名、发布、试产或量产放行 |

## 8. 变量更新规则

- 项目变量必须记录来源位置、适用板版/软件版本、记录时间和验证状态。
- 显示名称不能作为稳定关联键；设备、板版、固件、BOM 和测试必须使用稳定 ID。
- 实测值不得静默覆盖设计值；二者分别保存，并记录偏差与结论。
- 变量变化后必须执行 [02-完整项目开发流程.md](02-完整项目开发流程.md) 的变更传播检查。
- 不再适用的变量标记废弃和替代版本，不直接删除历史记录。
