# 项目变量模板

本模板必须由具体项目的权威资料补齐。AI 不得沿用示例值或用推测填充未知项。

## 1. 产品与责任边界

- 产品/项目稳定 ID：
- 使用场景与环境：
- 硬件版本与装配版本：
- 危险动作和安全状态：
- 安全等级、法规和认证范围：
- 需求、硬件、软件、测试、生产和发布批准人：

## 2. 软件事实

- MCU/SoC：
- OS/RTOS/事件框架及版本：
- SDK、工具链、IDE 和构建目标：
- 启动链、分区、升级与回退方式：
- 协议、配置、持久化和数据格式版本：
- Flash/RAM/栈/CPU/带宽/磁盘上限：
- 实时、吞吐、延迟和长稳指标：

## 3. 硬件事实

- 原理图、PCB、BOM 和设计规则版本：
- EDA 类型与版本、设计库和输出基线：
- 叠层、铜厚、阻抗、线宽/间距和板厂能力：
- 电源、时钟、复位、接口和启动配置：
- 外设、管脚、封装、替代料和板型差异：
- 功耗、热、EMC、射频、安规和结构约束：

## 4. 生产与敏感数据

- 密钥、证书、校准、唯一标识和生产 NV 边界：
- 调试、产测、校准和量产固件差异：
- 治具、烧录、校准和生产测试版本：
- 制造文件、固件、配置和发布清单的哈希策略：

## 5. 验证与恢复

- 测试设备、仪器、探头和治具：
- 台架、样机、整机、环境和长稳条件：
- 受保护的软件、硬件和制造基线：
- 备份、恢复、返工、回滚和停止条件：
- 当前证据等级及目标证据等级：
- 未知项、责任人和关闭条件：

## 6. 缺失变量处理

变量缺失时，AI 必须标记“未知”，说明它影响的决策、所需来源和验证方法。AI 仅可进行只读盘点、通用方案、候选计算、主机侧准备和评审清单，不得把高风险软件、硬件、安全、生产或发布任务宣称为完成。
