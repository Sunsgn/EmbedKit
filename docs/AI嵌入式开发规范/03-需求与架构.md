# 需求与架构

## 快速摘要

- 解决：把已确认输入转成可验收需求、系统职责、跨域接口和资源预算。
- 读取：F1需求、F2架构，或需求/跨域接口发生变化时。
- 产出：需求与追溯、系统框图、接口表、预算及相关ADR。

## 任务路由

| 当前任务 | 只读章节 |
| --- | --- |
| 需求拆解或验收定义 | 1 |
| 系统职责、数据流或资源预算 | 2 |
| 软硬件接口或协议边界 | 3 |

## 不读本分册的情况

当前阶段未触发F1/F2；交接包确认阶段与接口未变且无新增未知项；普通实现修改且不改变需求、公共接口或资源预算。

## 1. 需求拆解规则

每项需求至少包含：

```text
需求 ID：稳定且不可复用
触发输入：谁、何时、什么格式和范围
正常输出：可观测且可测量
失败输出：错误分类、最终状态和恢复
资源上限：时间、内存、队列、功耗或空间
兼容范围：旧硬件、旧数据、旧协议和迁移
验证方法：主机、台架、样机、整机或生产
```

| ID | 触发条件 | AI 必须执行 |
| --- | --- | --- |
| M-REQ-001 | 需求包含“快速、低功耗、稳定”等词 | 转成可测指标，无法确定时标记未知并请求范围 |
| M-REQ-002 | 需求涉及外部输入 | 定义格式、单位、边界、无效输入和信任等级 |
| M-REQ-003 | 需求涉及状态变化 | 定义启动、运行、停止、超时、取消、异常、重启和恢复 |
| M-REQ-004 | 需求涉及安全动作 | 定义安全状态、单点故障反应和人工批准边界 |

## 2. 系统架构输出

F2只使用已确认需求，划分软硬件职责、数据流、控制流、所有者、降级和恢复；输出系统框图、接口表和资源预算。跨域接口没有电气与逻辑定义时不得关闭G2，门禁判定引用00B。

## 3. 软硬件接口

每个接口必须在同一记录中包含：信号/协议名称、电气属性、逻辑语义、方向、时序、默认态、所有者、异常状态、版本和验证点。软件不得只依据变量名猜测硬件语义，硬件不得只依据功能名猜测固件时序。

接口和预算使用09中的TPL-03；架构决策使用TPL-04。
