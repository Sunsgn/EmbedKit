# 交接包与状态模板

本文件规定阶段状态、跨会话交接和约束包版本，是交接包的唯一正文来源。

## 1. 交接规则

| ID | 触发条件 | AI必须执行 |
| --- | --- | --- |
| M-HANDOFF-001 | 本轮结束、暂停、阻塞或切换会话 | 更新交接包，只写变化、未关闭项和下一步 |
| M-HANDOFF-002 | 生成交接包 | 引用真实文件、版本、哈希和证据，不复制规则正文或虚构结果 |
| M-HANDOFF-003 | 新会话继续项目 | 先读整体层，再读上次交接包，只读“下一步允许动作”对应分册章节 |

## 2. 交接包模板

```text
[项目交接包]
约束包版本：
项目/产品稳定ID：
当前F/G阶段：
门禁状态：通过 / 失败 / 阻塞
本轮变化：<无或清单>
输入/需求/接口/决策版本：
软件/硬件/BOM/配置/工具版本：
目录状态及工作主文件：
交付物、证据位置和E等级：
未关闭阻塞、风险和未知项：
下一步允许动作：<一个>
下一步禁止动作：<一个>
恢复、回退或返工方法：
需要的授权/批准：
关键文件SHA-256：
Git/EDA状态及检查点：
```

最少必填：当前阶段、门禁状态、未关闭阻塞、下一步允许动作、下一步禁止动作、关键文件SHA-256。其他字段无内容写“无”，未变化写“未变”。

## 3. 最小交接包示例

```text
[项目交接包]
约束包版本：V4.0.0
当前F/G阶段：F1 / G1
门禁状态：阻塞
未关闭阻塞、风险和未知项：B1，验收指标待工程师确认
下一步允许动作：补全输入登记表中的验收指标
下一步禁止动作：进入F2正式架构
关键文件SHA-256：开发文档/需求规格/项目输入登记表.md = <实际哈希>
其他字段：未变
```

## 4. 新会话读取顺序

1. README、00、00A、00B、00C、00D；
2. 上一次交接包；
3. 交接包“下一步允许动作”对应的一个技术分册章节；
4. 只有发现新增未知、接口变化或阶段变化时，才追加相关分册。

不得因新会话重读全部技术分册或复述已完成内容。

## 5. 约束包版本与升级

| ID | 规则 |
| --- | --- |
| M-PACK-001 | 整体版本写在README和交接包；结构或职责变化升主版本，规则行为变化升次版本，文字/链接修正升修订版本 |
| M-PACK-002 | 升级时同步检查README导航、00～00D路由、受影响分册引用、模板引用和资料中心注册 |
| M-PACK-003 | 新旧版本可共存，但每个项目/交接包只能声明一个生效版本；历史记录保留原版本 |
| M-PACK-004 | 发现文件版本、清单或引用不一致时停止加载技术分册，报告冲突并由工程师指定生效版本 |

约束包升级不得静默改变既有项目基线；采用新版本后在交接包记录升级前后版本、影响和未迁移项。
